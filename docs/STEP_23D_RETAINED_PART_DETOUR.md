# 23D: 이미 조립한 기둥을 유지하며 다음 기둥을 우회 조립하기

작성: 2026-11-01. [18B의 첫 기둥 우회·삽입](STEP_18B_TRANSPORT_INSERTION.md)을 기존 프레임 실행기에 연결했다. 이번 물리 검증은 **바닥판 1개 + 로봇이 설치하는 기둥 2개**다. 최종 목표는 10부품 프레임을 유지한다.

## 무엇을 추가했나

첫 기둥을 설치하면 그 기둥은 다음 동작의 장애물이자 보존해야 할 조립물이 된다. 두 번째 기둥만 성공했다고 끝낼 수 없다. 이전 기둥의 위치·방향·지지·정지 상태도 유지해야 한다.

이번 실행은 하나의 MuJoCo 장면에서 `첫 기둥 집기·우회·삽입 → 빈 그리퍼로 다음 부품 위에 접근 → 두 번째 기둥 집기·우회·삽입`으로 이어진다. 두 기둥은 시작부터 자유 물체로 존재하며 중간에 생성하거나 강제로 부착하지 않는다. 같은 모델과 물리 상태를 계속 사용한다.

## 개발 중 실제로 막힌 두 지점

1. 부품을 든 운반만 우회하도록 연결했을 때는 첫 기둥 설치 후 두 번째 기둥을 가지러 가는 **빈 그리퍼 접근**이 막혔다. `approach_hover`의 사전 충돌 검사에서 멈췄다. 실행: `runs/step23_frame/20261101T075139_673383Z_a218aa41`.
2. 빈 그리퍼 접근도 우회하도록 연결한 뒤에는 두 번째 기둥의 **삽입 하강 공간**을 시험 장애물이 막았다. 운반을 마쳤지만 `insert_lower` 사전 검사에서 멈췄다. 실행: `runs/step23_frame/20261101T075300_804993Z_f27eb7b1`.

두 실행 모두 첫 기둥 1개만 설치한 실패로 남겼다. 두 번째 실패는 운반 길을 바꿔 해결할 수 없는 시험 배치였다. 충돌 기준이나 삽입 검사를 완화하지 않고, 장애물이 삽입 공간 밖에 있는 별도 장면으로 변경했다. 이 실패 기록을 최종 성공 결과로 덮어쓰지 않았다.

최종 프레임 시험 장애물의 중심은 작업대 좌표 `[0.040, -0.150, 0.115]`m, 반지름은 25mm, 충돌 여유는 6mm다. 두 초기 실패 장면은 `[-0.010, -0.125, 0.115]`m였다. 각 장면의 장애물은 초기화 때 배치하고 실행 중에는 고정한다. 기존 18B 단일 기둥 장면의 기본 위치는 그대로다. 공중의 고정 구는 통제된 충돌 시험용 형상이며 실제 지지대나 임의 작업대 환경의 재현은 아니다.

## 파일과 역할

| 파일 | 역할 |
|---|---|
| `scripts/empty_approach.py` | 열린 빈 그리퍼가 부품 위로 접근할 때 현재 관측 확인, 직접 경로 거부 후 기존 IK·RRT 대안 계획 |
| `scripts/frame_assembly_skills.py` | 기존 기둥 운반과 빈 그리퍼 접근에 선택형 우회 연결. 물리 판정은 기존 FrameVerifier 사용 |
| `scripts/frame_assembly_scene.py` | 프레임 시험용 장애물 배치와 명시적인 장면 조건 기록 |
| `scripts/insertion_scene.py` | 단일 기둥·프레임이 공유하는 고정 장애물 구성 함수 추출 |
| `scripts/run_frame_assembly.py` | 부품별 시도·우회 이유·기존 조립물의 측정 오차를 기록하며 같은 장면에서 순차 실행 |
| `tests/test_frame_detour.py` | 실제 두 기둥 설치, 기존 조립물 후보 충돌, 물리 상태 보존, 계획 거부·부분 성공 집계 검사 |

`FrameVerifier`는 원래 모든 조립물의 접촉·지지와 상태를 검사하고 있었다. 이번에는 그 검사를 그대로 둔 채 우회 계획과 실행을 연결했다. 새 IK나 탐색 알고리즘을 직접 작성하지 않았으며 기존 Mink·MIT 라이선스 RRT-Connect를 사용한다. 출처는 [12B](STEP_12B_RRT_CONNECT.md)를 따른다.

## 허용되는 구간

- `approach_hover`: 그리퍼가 비어 있고 충분히 열려 있으며, 집을 부품이 지지된 채 안정된 상태일 때만 빈 그리퍼 우회 계획을 요청한다.
- `insert_transfer`: 부품을 실제로 들고 있는 상태를 재확인한 뒤 운반 우회 계획을 요청한다.
- `approach_lower`, `insert_lower` 등 하강·접촉 구간: 기존 지역 경로 검사와 실행을 유지한다. 이 구간에서 막히면 우회하지 않는다.

각 계획 도구는 후보를 계산할 뿐 실제 로봇 상태나 물리 시각을 바꾸지 않는다. 사전 검사 이후 위치·속도·제어 입력 등이 달라지면 멈춘다. 경로를 찾지 못하거나 예산을 소진해도 실행하지 않는다. 실행은 기존 제어기 한 곳에서 직렬로 수행한다.

프레임 실행기의 `--transport-strategy direct_then_rrt`는 이번부터 빈 그리퍼 접근과 들고 있는 기둥 운반에 적용한다. 기본값 `direct`는 기존 동작을 유지한다. 새 우회 옵션은 현재 바닥판과 기둥만 있는 `--parts 2`부터 `5`까지 받을 수 있고, 슬리브·덮개를 포함한 요청은 실행 전에 거부한다. 그중 이번에 실제 우회를 연속 검증한 크기는 `--parts 3`이다.

## 실행과 결과

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/run_frame_assembly.py --parts 3 --mode single --transfer-obstacle --transport-strategy direct_then_rrt --snapshots
```

`success`와 결과 폴더가 출력된다. 창 없이 계산하며 `after_post_1.png`, `after_post_2.png`를 저장한다. 실행: `runs/step23_frame/20261101T075500_510987Z_3709bbf8`.

- 로봇 설치 **2/2**, 두 결합 모두 해제·후퇴 후 독립적인 물리 판정 통과.
- 전체 시뮬레이션 시간 **209.510초**, 측정 기록 **104,798행**. 해당 PC의 실제 실행 시간 약 **88.1초**였고 다른 검사와 동시 실행했다.
- 첫 기둥의 최종 검사 구간 최대 위치 오차 약 **0.112mm**, 두 번째 기둥 약 **0.174mm**.
- 두 번째 작업 전체에서 첫 기둥의 **목표 위치 대비 최대 오차** 약 **0.112mm**. 이는 첫 기둥이 그만큼 추가로 움직였다는 뜻이 아니다.
- 운반 중 최대 상대 미끄러짐: 첫 기둥 약 **1.102mm**, 두 번째 기둥 약 **1.407mm**. 기존 5mm 이내 조건을 통과했다.
- 운반 중 최대 기울기: 첫 기둥 약 **24.8도**, 두 번째 기둥 약 **17.3도**. 끝에서 기존 정렬 조건을 다시 확인한 뒤 삽입했다.
- 규칙 정책 호출 **6회**, 실제 API 호출 **0회**. `single`은 이번 실행에서 단일 규칙 정책이며 실제 LLM 판단 결과가 아니다.

최종 이미지를 확인했고 두 기둥이 바닥판에 설치된 상태였다. 전체 10부품 조립으로 세지 않으며 `ten_part_assembly_complete=false`로 기록한다. 고정 장면·seed 3의 개발 검증으로, 임의 장애물이나 새 제품에 대한 성공률 실험은 아니다.

## 로그에서 확인할 내용

`transport_attempts`는 들고 있는 부품의 운반, `empty_approach_attempts`는 빈 그리퍼 접근 시도를 구분한다. `motion_preflight_failures`와 `motion_preflight_*.json`은 실행하지 않은 직접 경로의 충돌 예측을 보존한다. 성공 결과 폴더에도 사전 실패 보고서가 있을 수 있으므로 전체 상태는 `result.json`을 읽는다.

`part_metrics.post_2.previous_parts.post_1`에는 두 번째 작업 중 첫 기둥의 최대 위치·방향 오차가 있다. 그 행을 기록하기 전에 기존 검증기가 실제 접촉·지지·속도도 검사한다. 실패하면 별도 FailureReport에 해당 관측과 위반 조건을 남기고 중단한다.

## 검사 결과

신규 검사 4개:

1. 빈 그리퍼 도구를 하강·운반 단계나 점유 상태에서 호출하면 거부하고, 사전 검사 후 상태 변경·탐색 예산 소진 때 실행하지 않는다.
2. 아직 검증 범위를 정하지 않은 슬리브·덮개 우회 요청을 실행 전에 거부한다.
3. 실제 두 기둥을 연속 설치하면서 같은 모델·물리 상태를 유지한다. 모든 실제 `mj_step`·`mj_forward` 전후를 감시해 강제 상태 변경·추가 부착·외력·중력 해제가 없음을 확인한다. 첫 기둥과 겹치는 두 번째 기둥의 목표를 **계산용 후보로만** 요청하면 두 부품의 충돌 형상을 검출하고 거부하며 실제 상태는 바뀌지 않는다. 이후 정상 목표로 실제 조립을 완료한다.
4. 첫 설치 후 시험용 중단을 넣으면 설치 수 1개와 전체 실패로 기록한다. 부분 진행을 전체 성공으로 집계하지 않는다.

신규 4개와 관련 회귀 6개 통과 여부·실행 시간은 아래 최종 검증 기록에 남긴다. 기존 프레임 장면 4개, 프레임 판정 1개, 첫 기둥 RRT 물리 조립 1개를 회귀 검사했다. 장면·판정 검사에는 독립적인 형상 시험편이 포함되며 이를 로봇 조립 성공 횟수로 세지 않는다. 전체 저장소 검사와 10부품 연속 동작을 이번 코드로 다시 수행한 것은 아니다.

## 남은 범위

두 기둥에서 확인한 뒤 기둥 수와 장애물 조건을 늘리고, 슬리브·덮개는 각각의 형상·파지·지지 관계로 별도 검증해야 한다. RRT는 운반 내내 수직 방향을 유지하거나 산업용 가속도·jerk 제한을 보장하지 않는다. 이산 샘플 충돌 검사도 연속 경로 안전성의 증명은 아니다. 실제 LLM 판단과 실물 실행은 이번 작업에 포함하지 않았다.
