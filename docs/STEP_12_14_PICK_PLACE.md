# 12~14단계: 현재 자세에서 이동하고, 실제 접촉으로 집어 옮겨 놓기

이번 단계의 목표는 **작업대 위의 상자 하나를 잡아서 들어 올리고, 목표 위치로 옮겨 놓은 뒤 성공을 측정하는 것**이다. 사용자가 14단계까지 함께 진행하도록 요청해 이동·집기·놓기를 별도 모듈로 구현했다. LangGraph는 다음 15단계다.

현재 검증 대상은 알려진 40 × 30 × 40 mm, 50 g 상자 하나다. 임의의 물체 인식이나 삽입 조립, 약 10부품 제품 조립의 완료를 뜻하지 않는다. 최종 제품 부품 수 목표는 유지한다.

## 실행해 보기

프로젝트 위치에서 실행한다. 새 패키지 설치는 필요 없다. 기존 MuJoCo, Mink와 lockfile에 포함된 SciPy를 사용한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/run_pick_place.py --config config/local.workcell.toml
```

순서대로 작업대 안정화 → 부품 위로 접근 → 하강 → 그리퍼 닫힘 → 집기 확인 → 100 mm 상승 → 목표 위로 이동 → 하강 → 놓기 → 손 후퇴 → 결과 확인이 진행된다. 정상 완료 시 `Step 14: SUCCESS`가 출력된다. 이후 정지 화면에서 결과를 살펴보고 창을 닫으면 된다.

`config/local.workcell.toml`이 없는 새 설치에서는 `--config`를 생략하면 저장소의 예시 설정을 사용한다. 개인 설정을 만들 때는 존재하는 파일을 덮어쓰지 말고 `config/workcell.example.toml`을 복사한다. 현재 개인 설정도 실측값이 아닌 예시다.

단계별로 멈춰서 확인할 수 있다. 각각은 새 시뮬레이션을 초기화해 시작한다.

```powershell
# 12: 부품 위 접근과 하강까지만. 손가락은 열린 상태다.
uv run --locked python scripts/run_pick_place.py --through 12 --config config/local.workcell.toml

# 13: 집고 들어 올리기까지.
uv run --locked python scripts/run_pick_place.py --through 13 --config config/local.workcell.toml

# 14: 창 없이 전체 물리 계산·검증. 주요 순간의 실제 렌더 이미지도 저장한다.
uv run --locked python scripts/run_pick_place.py --check --snapshots --config config/local.workcell.toml
```

`--check`도 실제 `mj_step()`을 실행한다. 숫자를 가정하는 모의 성공 결과가 아니다. 화면을 표시하는 속도와 물리 시뮬레이션 시간은 별개이며, 컴퓨터 성능과 IK 계산 시간에 따라 실제 소요 시간은 달라진다. 개발 중에는 headless 실행과 offscreen 렌더를 확인했다. 이번 단계의 대화형 viewer를 직접 조작해 검사하지는 않았다.

## 12단계: 현재 상태에서 다음 목표로 이동

**TCP**는 그리퍼에 정한 집기 기준점이다. “손을 이 위치와 방향으로 옮겨라”는 목표를 **IK(역기구학)**가 팔 관절 각도로 바꾼다. 이번에도 기존 Mink 솔버를 사용하며 IK 수치 알고리즘을 새로 만들지 않았다.

이전 9단계는 초기 자세에서 위로 30 mm 이동하는 고정 예제였다. 새 이동 모듈은 현재 `qpos`와 시간을 읽어 출발점을 잡는다. 첫 이동이 끝난 상태에서 다음 이동을 이어서 계산한다.

1. 현재 TCP와 목표 사이에 위치 10 mm 이하, 방향 3도 이하 간격으로 중간 목표를 만든다.
2. 각 목표의 IK를 계산한다. 팔 6개 관절만 바꾸고 손가락과 자유 부품의 좌표는 고정한다.
3. 실행할 관절 보간 경로를 관절당 0.25도 이하 간격으로 검사한다.
4. 모두 통과한 구간에 대해서만 모터 명령을 실행한다.
5. 물리 시간 2 ms마다 접촉, 관절 범위, 속도, 추종 오차와 상태를 검사한다.
6. 마지막 0.5초 동안 TCP 위치 오차 1 mm 이하, 방향 오차 0.5도 이하, 로봇 관절 속도 0.5도/초 이하인지 확인한다.

계획 당시의 자세·시간과 실행 직전 상태가 달라지면 오래된 계획으로 판단해 거부한다. 계획 계산용 복사본에는 현재 이동 장애물의 위치도 복사한다. IK 계산과 사전검사는 실제 장면의 위치·속도·제어 입력·시간을 바꾸지 않는다.

속도는 기준 궤적 기준 최대 5도/초를 목표로 정하고 실제 팔 속도 15도/초, 관절 추종 오차 2도를 실행 제한으로 검사한다. 모터는 기존 힘 제한을 사용한다. 중력 보상도 기존 위치 구동기를 통해 적용한다.

이는 **정해진 접근·상승 경로를 검사하는 로컬 이동 기능**이다. 막힌 경로를 우회해 찾는 RRT/OMPL 같은 범용 탐색기는 아직 없고, 샘플 간 연속 충돌 무발생을 수학적으로 보장하지 않는다. 막히면 실패로 반환한다.

## 13단계: 실제 접촉으로 잡고 들어 올리기

상자는 위를 향해 똑바로 서 있어야 한다. 현재 관측한 상자의 중심과 방향으로 접근 자세를 계산한다. TCP는 상자 중심보다 6 mm 위에 둔다. 이 값은 고정 TCP와 실제 손가락 패드의 위치 차이를 고려한 현재 모델의 파지 설정이다.

상자 위 80 mm 지점에 접근한 후 상자가 움직이지 않았는지 다시 읽고 내려간다. 손가락은 그리퍼 원본 모델의 모터로 닫는다.

닫힘 명령을 무조건 255까지 주지 않는다. 양쪽 패드가 각각 부품에 0.01 N보다 큰 법선 접촉력을 가하는 상태가 20 ms 이어지면 접촉을 확인한다. 이후 **현재 실제 tendon 위치를 명령 단위로 환산한 값 + 3**을 유지 목표로 사용한다. 원본 모델의 `0..0.8 rad ↔ 0..255` 구동 관계를 사용한 작은 추가 닫힘이며, 실물 그리퍼의 힘 단위나 캘리브레이션은 아니다.

개발 초기에는 최대 닫힘 명령을 계속 줬을 때 링크 제약 잔차가 0.2 mm를 넘어 중단됐다. 검사 기준이나 물체 질량·마찰을 바꾸지 않고 접촉 기반 닫힘 제어로 수정했다. 기존 모델과 라이선스 파일은 변경하지 않았다.

집기 판정은 다음을 모두 요구한다.

- 닫힘 후 안정 구간에 양쪽 패드 접촉과 실제 손가락 간격이 유지된다.
- 로봇이 100 mm 상승한 뒤 부품 바닥이 작업대에서 최소 50 mm 떨어져 있다.
- 그때 부품과 작업대의 지지 접촉이 없다.
- 운반 중 양쪽 접촉이 유지되고, TCP에 대한 부품 위치 변화가 5 mm, 방향 변화가 5도를 넘지 않는다.

부품은 계속 자유 물체다. 부품과 손 사이에 weld/equality 제약을 추가하거나, 실제 부품 `qpos`를 TCP 위치로 덮어쓰지 않는다. 모터가 손가락을 움직이고 접촉·마찰이 부품을 들어 올린다.

파지 시 측정한 TCP-부품 상대 변환은 **계획 복사본에서 운반 부품의 충돌 위치를 예측하고, 실제 미끄러짐을 검사하는 데만** 사용한다. 이 예측은 실제 물리적 부착과 다르다. 이동 중 실제 관측으로 계속 검사한다.

## 14단계: 목표로 운반하고 놓은 뒤 판정

`target` 설정은 TCP 목표가 아니라 **부품의 최종 중심 위치와 방향**이다. 파지할 때 측정한 손-부품 상대 변환으로 필요한 TCP 목표를 계산한다. 따라서 목표 방향을 바꾸면 부품이 그 방향으로 놓이도록 손의 방향도 바뀐다.

목표 위로 운반한 뒤, 부품 바닥이 작업대보다 명목상 2 mm 높은 위치까지 내린다. 그리퍼를 열면 부품이 중력으로 내려와 작업대에 놓인다. 손이 완전히 열린 후 80 mm 후퇴하고 결과를 확인한다. 이 동작은 작은 높이에서의 놓기이며 힘 제어에 의한 정밀 삽입은 아니다.

마지막 0.5초 전체에서 다음을 만족해야 `place/v1`이 성공한다.

| 확인 항목 | 기준 |
|---|---|
| 실제 부품 중심과 목표의 3차원 거리 | 3 mm 이하 |
| 실제 부품 방향과 목표 방향의 차이 | 3도 이하 |
| 부품 선속도 | 1 mm/초 미만 |
| 부품 각속도 | 0.01 rad/초 미만 |
| 지지 접촉 | 부품이 작업대에 실제 접촉력을 가함 |
| 손 해제 | 양쪽 패드 접촉 없음, 열린 간격 80 mm 초과 |
| 최종 접촉 겹침 | 1 mm 미만 |

MuJoCo의 부드러운 접촉 모델에서는 작은 겹침이 생긴다. 실행 중 최대 3 mm, 최종 안정 구간 1 mm 기준을 사용한다. 실행 중 기준은 11단계의 초기 낙하 접촉 기준을 유지한 것이다.

허용 접촉은 단계별로 부품-작업대, 부품-손가락 패드 쌍만 명시한다. 운반 구간에서는 부품-작업대 접촉도 허용하지 않는다. 로봇-작업대, 손가락 이외의 부위-부품, 부품-장애물 등의 접촉은 실패다. 현재 제품 부품은 하나이며, 앞으로 다른 조립 부품을 추가할 때 그 부품의 충돌 형상과 허용 결합 접촉을 정의해야 한다.

## 실행 기록과 실패

각 실행은 Git에서 제외된 `runs/step12_14/<run_id>/`에 별도 저장한다.

- `resolved_config.json`: 사용한 설정 사본, 파일 해시, MuJoCo 버전과 시간 간격.
- `skill_trace.csv`: 물리 실행 중 단계, TCP/부품 위치, 접촉, 속도, 오차.
- `result.json`: 전체 성공/실패, 완료된 스킬, 계획별 목표와 검사 수, 마지막 관측.
- `failure_report.json`: 실패·중단일 때만 생성. 실패 시점/단계, 목표/실제, 접촉, 마지막 정상 관측, 사전검사 후보를 분리한다.
- `*.png`: `--snapshots`로 요청한 실제 물리 상태의 렌더 이미지.

상자는 자유 관절이므로 상태 배열에 미터와 quaternion도 들어간다. 새 관측 기록은 전체 `qpos`를 라디안으로 잘못 표시하지 않고 관절 종류·주소·단위를 함께 저장한다. 기존 14-hinge 예제의 `qpos_rad` 형식은 유지한다.

이번에 실제 사용되는 실패 코드에는 `GRASP_NOT_CONFIRMED`(집기 확인 실패), `PART_LOST`(운반 중 파지 손실), `PLACEMENT_NOT_CONFIRMED`(배치 판정 실패)가 추가됐다. 자동 재시도나 복구 동작은 구현하지 않았다. 실패하면 더 이상 물리 시간을 진행하지 않고 `stop_without_retry`로 기록한다. 새 CLI 실행에서 초기 상태를 만드는 것은 새 시험의 시작이며 이전 실패의 복구 성공이 아니다.

검사 항목은 기본 물리 집기·놓기, 실행 중 실제 `qpos/qvel`을 덮어쓰지 않는지, 작업대 평행이동/높이/회전 및 목표 방향 변경, 계획의 상태 불변성·오래된 계획 거부, 손에 든 부품의 경로 충돌, 실제 운반 중 손 열림 고장, 닫히지 않는 그리퍼의 실패 기록, 실제 이동 중 장애물 접촉의 정확한 시점 기록, 지지 없는 정지 부품의 배치 성공 거부다. 기존 단계의 회귀검사도 함께 유지한다. 2026-10-28에 전체 33개 검사가 통과했다(약 94.9초). 의도적으로 고장을 넣은 시험에서는 `FAILED` 출력이 나오는 것이 예상 결과이며, unittest의 최종 `OK`가 검사 전체의 통과를 뜻한다.

## 다음 단계와 변경 지점

작업대 치수·위치·로봇 설치·부품 배치·목표 위치는 계속 11단계 TOML에서 바꾼다. 설정이 유효해도 로봇이 도달하거나 집을 수 있다는 보장은 없으므로 해당 설정으로 다시 물리 실행·검증한다. 현재 스킬은 X/Y 크기 20~60 mm, 높이 30~80 mm, 수직 상자만 입력으로 받지만 이 범위의 모든 치수·질량을 검증한 것은 아니다.

15단계에서는 먼저 `관측 → 스킬 선택 → 실행 → 결과 판정 → 종료/실패 분기`를 LangGraph 단일 흐름으로 연결할 수 있다. LLM이 선택하는 단위는 `pick(part_id)`와 `place(part_id, target_id)`이며 관절 각도를 매 순간 생성하지 않는다. 이후 정렬·삽입, 3→6→약 10부품, 경험 검색·실패 대응을 확장한다.
