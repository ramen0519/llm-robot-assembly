# 22G — 현재 부품·실패 상황에 맞는 경험 검색

작성: 2026-11-10. 범위: **기둥 경험 검색 한 단위**. Luna 연결·교훈 생성·새 스킬 생성은 후속이다.

## 1. 이번 기능의 의미

22F는 과거 실행을 사건별 JSON으로 저장했다. 22G는 그 자료에서 **현재 기둥과 실패 상황을 이해하는 데 도움이 될 경험을 최대3개 골라 주는 기능**이다.

입력 예: “UR3e와 2F-85로 20×20×60mm 기둥을 조립하려는데, 삽입 사전검사에서 PLANNED_CONTACT가 발생했다.” 출력 예: “이전 회차에서는 중앙 파지가 벽과 간섭했고, 높이를 바꾼 뒤 삽입 검증을 통과했다.”

결과의 숫자는 과거 파지값이다. 현재 로봇에 바로 명령하거나 추천 파지로 확정하지 않는다. 모든 카드에 `execution_authorized: false`, `requires_current_scene_validation: true`를 붙였다.

## 2. 사용하는 파일과 함수

- `scripts/retrieve_grasp_experience.py`: 새 검색 모듈. Python 표준 기능과 22F의 기록 검증 함수를 사용한다.
- `tests/test_retrieve_grasp_experience.py`: 합성 로그를 실제 exporter로 변환한 뒤 검색 계약을 검사한다.
- 입력: `runtime/memory/simulation/grasp_v2/*.json`의 과거 경험.
- 실제 검색 확인 보고: `runtime/validation/step22g_saved_search_check.json`.

`query_from_run()`은 지정한 run의 **resolved_config.json만** 읽어 검색 질문을 만든다. 결과 파일이나 그 회차의 정답을 읽어 질문을 만들지 않는다. `retrieve_experiences()`가 기록 검증·호환성 검사·정렬·카드 생성을 수행한다. 검색 함수는 파일을 쓰지 않는다.

이번 CLI의 “현재 조건”은 지정한 장면 설정이다. 실시간 관측이나 Luna의 실패 메시지를 자동으로 연결한 상태는 아니다. 호출부가 사용할 공개 함수와 확인 가능한 실행 명령까지 준비한 단계다.

## 3. 검색 순서

1. **자료 확인:** 파일 내용 hash와 사건 연결을 확인한다. 망가진 파일은 제외하고 이유를 남긴다.
2. **같은 회차 제외:** 질문에 사용한 회차의 모든 부품과 모든 저장 버전을 제외한다.
3. **기본 조건 확인:** 시뮬레이션/관측 출처, UR3e·2F-85, 부품 기준 좌표·mm/deg, top-down 접근·TCP 명칭이 지원 범위에 맞아야 한다.
4. **실패 연결:** 요청한 실패 코드가 직접 연결된 사전검사 기록을 찾는다. 부모 기록을 따라 실패와 수정 시도를 함께 묶는다.
5. **정렬:** 같은 부품 설정 → 같은 실패 발생 단계 → 가까운 치수 → 가까운 삽입 깊이·여유 → 수치 검증이 남은 수정 사례 → 같은 제품 설정 순이다. 동률은 고정 ID로 정렬한다.
6. **출력 제한:** 회차당 한 카드, 전체 최대3카드다. 같은 실행의 기둥 여러 개를 독립적인 여러 제품의 성공 근거처럼 늘리지 않는다.

치수 관련성은 대응 축마다 `작은 치수/큰 치수`를 구한 뒤 가장 작은 값을 사용한다. 결합 관련성도 깊이·측면 여유에 같은 방식을 쓴다. 이는 검색 정렬용 숫자이며 성공 확률이 아니다. 부동소수점의 아주 작은 차이는 정렬값 반올림으로 흡수한다.

`same_active_part_config`는 부품 설정·결합 설정·MuJoCo 버전이 같은 경우다. 주변 설치물·현재 물리 상태·TCP 보정까지 같다는 인증이 아니다. 같은 명칭의 TCP만으로 실제 실행 호환성을 보장하지 않는다.

## 4. 결과 카드가 담는 내용

카드 하나는 parent로 연결된 파지 시도 묶음이다. 같은 실패 뒤 성공한 수정뿐 아니라 계속 거절된 수정도 남긴다.

- 원본 회차·부품·목표, 조건이 같은지/유사한지와 정렬 이유.
- 부품 치수·삽입 깊이·여유·배치·남아 있는 설치물 정보.
- 각 시도의 파지 XYZ/각도·변경량, 이전 실패 ID.
- 검사 수락/거절, 접촉 쌍·거리, 패드 여유, 실행 노드의 반환 결과.
- 그래프 검증 완료와 실제 수치 결과의 보존 여부.
- 원본 export/snapshot/record ID와 파일·행·측정 위치 참조.

접촉 상세는 사건당 최대4개만 넣고 원래 개수와 생략 여부를 표시한다. 긴 원시 trace나 LLM 대화 전문은 넣지 않는다. 카드당 파지 시도 최대8개, 시도당 사건 최대32개이며 넘는 묶음은 제외 이유를 남긴다. 이 크기 상한은 모델 토큰 수를 정확히 계산하는 기능은 아니다.

## 5. 같은 경험이 여러 번 저장된 경우

같은 attempt ID의 여러 버전은 성공 여부로 고르지 않는다. 먼저 겹치는 제안·검사·실행 사실이 같은지 비교한다.

- 초기 파일에 수치 결과가 없고 나중 파일에만 생겼다면, 기존 사건과 모순 없이 더 많은 근거를 포함하는 버전을 하나 사용한다.
- 같은 시도의 파지·수락·사건·측정이 모순되면 해당 시도를 제외한다.
- 제외된 실패를 부모로 가진 수정 성공도 혼자 떼어 반환하지 않는다.
- 서로 다른 실제 시도는 같은 파지 숫자를 사용했어도 하나로 합치지 않는다.

불완전한 기록을 성공한 기록으로 임의 병합하거나, 저장 파일 개수를 물리 시도 수로 계산하지 않는다.

## 6. 실제 저장 자료에서 확인한 검색

질문 조건은 21N 전체 실행의 설정을 사용했다. **21N 자신은 검색 대상에서 제외**하고 앞선 개발 회차들을 찾았다. 새 모델 호출·시뮬레이션은 수행하지 않았다.

### 첫 기둥 + PLANNED_CONTACT + insert_lower/preflight

| 순위 | 과거 경험 | 조건 구분 | 기록된 변화와 결과 |
|---:|---|---|---|
| 1 | 21K post1 | 같은 부품 설정 | Z=0 거절 → Z=20mm, 수치 삽입 검증 기록 |
| 2 | 21M post1 | 같은 부품 설정 | Z=0 거절 → Z=4mm, 수치 삽입 검증 기록 |
| 3 | 21F 트레이 변경 post1 | 관련 기둥 조건 | Z=0 거절 → Z=12mm, 수치 삽입 검증 기록 |

20mm·4mm·12mm 중 하나를 검색기가 정답으로 선택한 것은 아니다. 각각의 과거 조건과 결과를 반환한다. Luna에 연결하는 후속 단계에서도 현재 상태에 맞게 판단하고 물리 검사를 거쳐야 한다.

21K·21M은 전체 회차가 중단/실패했지만 첫 기둥의 검증 근거는 남아 있다. 전체 회차 실패를 이유로 완료된 부품 경험까지 지우지 않는다.

### 미확인·계속 거절된 사례

- post2 질문: 같은 조건의 21M post2가 먼저 나왔다. 그래프 검증은 있으나 수치 자료가 빠져 있어 `graph_verified_without_saved_measurements`를 유지하고 측정 성공으로 표시하지 않았다.
- post4 질문: 21K post4의 세 후보 거절이 먼저 나왔다. 실제 집기 실패3회로 바꾸거나 수정 성공을 만들어내지 않았다.
- `PART_LOST` 질문: 해당 실패가 직접 기록된 사례가 없어 **0건**을 반환했다. 관련 없는 성공 사례로 빈칸을 채우지 않았다.

현재 실제 자료는 같은 치수의 기둥뿐이다. 서로 다른 치수의 순위 검사는 합성 자료로 확인하며, 새로운 형상의 물리 일반화 성공으로 해석하지 않는다.

## 7. 실행 명령

```powershell
cd C:\dev\llm-robot-assembly
.\runtime\luna-venv\Scripts\python.exe scripts/retrieve_grasp_experience.py --run-dir runs/step23_frame/20261105T052814_462220Z_48e7b620 --part post_1 --failure-code PLANNED_CONTACT --failure-phase insert_lower/preflight
```

예상 결과: `returned_cards: 3`, `current_episode_excluded: 1`. 위 표의 실패→수정 경험과 원본 참조가 출력된다. `--part post_2` 또는 `post_4`로 다른 기둥을 검색할 수 있다. 실패 코드 없이 호출하면 부품 조건을 중심으로 찾는다.

```powershell
.\runtime\luna-venv\Scripts\python.exe -B -m unittest discover -s tests -p test_retrieve_grasp_experience.py -v
.\runtime\luna-venv\Scripts\python.exe -B -m unittest discover -s tests -p test_export_grasp_experience.py -v
```

새 패키지·DB·검색 API·API 키는 필요 없다. 기존 run과 경험 JSON은 Git에 없으므로 실제 예제 검색에는 로컬 자료가 필요하다. 합성 검사에는 과거 실행 폴더가 필요 없다.

## 8. 검증 결과와 남은 범위

- 검색 모듈의 합성 로그 계약 검사 **22개 통과** (저장소 위치에서 1.084초).
- 기존 경험 변환기의 검사 **29개 통과** (0.802초). 이번에는 변환기 코드를 수정하지 않았다.
- 실제 저장 export6개에서 질문4종 확인: 첫 기둥 관련 경험3개, 둘째 기둥 미확인 결과 보존, 넷째 기둥 후보 거절3회 보존, 해당 실패 없음0건.
- 같은 질문을 반복했을 때 같은 결과를 확인했다. 현재 회차의 다른 기둥도 제외하고 회차별 한 카드만 반환했다.
- 원본 로그·v1/v2 경험·기존 스킬·동결 지식·관련 코드 **65개 파일의 내용 hash가 동일**했다.
- 안내한 CLI 명령을 실행해 `files_scanned: 6`, `returned_cards: 3`, `current_episode_excluded: 1`을 확인했다.
- 새 API 호출 **0회**, 새 MuJoCo 실행 **0회**. 검색의 정확성을 검사했으며 로봇 동작이나 학습 성능을 새로 검증한 결과는 아니다.

이번 검색의 실패 코드 필터는 **시도에 직접 연결된 복사 장면 사전검사 보고**를 사용한다. 회차 전체의 통신 오류나 부품 단위 FailureReport를 임의의 파지 시도에 귀속하지 않는다. 실행 중 실패 보고를 정확히 연결하는 별도 어댑터는 후속이다.

모든 출력은 개발 참고용이고 `training_eligibility=unassigned_requires_dataset_manifest`를 유지한다. 독립 평가 데이터 분리와 사용 지식 동결은 아직 연결하지 않았다. 파일당16MiB, 폴더 최대128파일·64MiB로 범위를 제한한다.

Luna의 실제 입력 연결, 경험이 판단에 미친 효과 측정, 자연어 교훈과 제한 Python 스킬 생성은 이번 변경에 포함하지 않는다. 기존 v1 메모리·스킬·동결 검사는 그대로 유지한다.
