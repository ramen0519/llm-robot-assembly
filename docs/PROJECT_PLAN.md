# 현재 개발 계획 · 일반 메시 v2

최신 기준은 `docs/design_v2/`의 세 문서다. v1.2의 사각 전용 범위를 일반 메시 실행으로 대체하되 기존 프레임은 회귀 사례로 보존한다. 이번 작업은 사용자 요청에 따라 입력·실행·경험·UI·평가를 통합하며 모듈마다 재승인을 요청하지 않는다.

## 구현 경로

1. 원본 단위·완성 배치·검증된 native 체인과 실제 기하 대응 검사.
2. 원본 메시·검증된 convex decomposition·원본 체적/관성·고정 베이스·동적 부품·초기 배치 생성.
3. 별도 완성 기준 장면의 연속 물리 유지 검사. 실패는 `reference_invalid`.
4. 실제 메시 표면/법선 파지 후보와 Astra의 선택·수정·직접 전체 pose 제안.
5. 복사 장면의 파지 가능성과 해당 파지의 설치 가능성을 분리 검증.
6. 주 장면의 접근·닫기·들기·운반·설치·해제·후퇴. 계획용 현재 파지 변환과 최초 슬립 기준을 분리.
7. 동일 완료 프로파일로 모든 설치 부품의 동일한 연속 창 검사.
8. 객관적 실패 사건 → 실제 설치 해결/종료 보존 → 근거가 연결된 지침 → 다음 실행의 고정 snapshot 검색.
9. 공통 실행기를 호출하는 로컬 UI, 실제 상태 영상, 기록 audit, 원 run 이동 후에도 확인 가능한 bundle.
10. 실제 Astra memory-off 시범 수집 → 등록 확인 → 본 수집 → 동결 → 독립 평가의 S0/S1/R0/R1.

## 완료 확인 원칙

코드 존재, 계약 검사, 실제 MuJoCo, 실제 Astra, 다음 실행의 경험 재사용, 새 CAD 전체 조립을 서로 다른 증거로 기록한다. `not_run`을 성공으로 바꾸지 않는다. 모든 CAD에서 성공한다는 주장은 하지 않는다. 후보/경로/시간 소진은 현재 예산 내 미발견이다.

일반 구현 범위는 [STEP 29](STEP_29_GENERAL_MESH_V2.md), 최신 실제 API 실행과 F01–F16/V01–V08의 추가 검증은 [STEP 30](STEP_30_LIVE_ASTRA_V2.md)에 있다. 실제 Astra 2부품 조립·5회 시범 수집과 개발용 실패의 지침 생성/등록/다음 검색·재검증은 확인했다. 다음 우선순위는 응답 가능한 native 분해 환경, 배터리의 엄격한 충돌 자산 준비, 일반 형상 포함 10부품 이상의 연속 조립, 추가 수집 입력과 별도의 독립 평가다. 같은 2부품 5회 반복이나 개발 교란을 일반화 성능으로 해석하지 않는다.

실물 연결·나사 조임·유연체·재파지 전략·fine-tuning은 이번 구현 성공 범위에 포함하지 않는다. 코드·제품 원본·로봇 자산·완료 프로파일·모델/예산·메모리를 동결한 후 연구 비교를 진행한다.

## 2026-11-25 실행 안정화 이후

배터리의 기존 검증 분기에서 6/12개를 원래 완료 프로파일로 확인했다. 중단 시 복원 가능한 상태·실제 실패·물리 불가능을 구별한다. timestep은 0.002초 그대로 두고 같은 프레임의 중복 계산을 줄였다.

파지값에 더해 제한된 동작 계획을 모델·복사 검사·주 실행·기록에 연결했다. 같은 실제 파지 상태에서 Astra high 고정 계획/null 대 65mm 수정의 들기 시험은 각각 성공했다. 생성 2회, 조건별 1표본으로 전체 조립 성능을 주장하지 않는다.

다음 물리 범위는 남은 배터리 부품의 경로·해제 가능성 및 전체 연속 실행이다. 그 후 실제로 설치까지 해결된 사례만 지침 등록 대상으로 삼고 다음 실행 재검증을 수행한다. 본 수집/독립 평가는 이 연결을 먼저 확인한 뒤 동결된 모드·코드·예산으로 진행한다. 상세 근거는 [STEP 43](STEP_43_EXECUTION_STABILITY.md), [STEP 44](STEP_44_BOUNDED_MOTION_PLAN.md), [STEP 45](STEP_45_ASTRA_MOTION_COMPARISON.md) 참조.


## 2026-11-26 배터리 전 공통 프로토타입

현재 요청은 배터리 재실행 전에 실행·실패·경험·결과 연결을 끝내는 것이다. 자세한 변경과 실제 결과는 [STEP 47](STEP_47_PROTOTYPE_FLOW.md), [STEP 48](STEP_48_PROTOTYPE_VALIDATION.md)에 있다. 작은 새 CAD 묶음과 기존 native 입력으로 검증하며, 실패한 물리 시험도 보존한다. 원본 목표·완료 프로파일·0.002초 timestep은 유지한다.

이번에 제한된 현재 상태 이어가기, 해제 상태의 별도 처리, 항상 수행하는 종료 기록, 실패 행동 기준 검색, 격리한 개발 지침 작성·등록·재검색, 설치 손 방향 정보와 지지 여유 기반 공급 자세, 쉬운 UI 상태를 구현했다. 실제 Astra 경로와 제한된 동작 계획 인터페이스는 유지한다. 개발 경험은 연구 수집/평가에 사용할 수 없다.

후속 작업은 원본 CAD용 WSL 응답 문제 해결, 새 코드에서 작은 실제 Astra 시범, 그 결과를 근거로 한 배터리 재시험이다. API 없이 기능 검사를 마친 것을 새 Astra 판단 또는 배터리 완주로 대신하지 않는다. 실패로 확인된 지원 한계·미실행 항목은 STEP 48을 따른다.


## 2026-11-26 원본 CAD 연결 후속

[STEP 49](STEP_49_NATIVE_INPUT_BRIDGE.md)에서 다른 Linux 작업을 중단하지 않고 입력 연결을 복구했다. 보통 WSL 접속 실패 시 명시적 대체 접속을 검사하고 동일 실행 파일 해시와 RedMax import를 확인한다. 순서가 없는 개발용 3부품 CAD 목록으로 실제 분해 2단계·최종 베이스 잔여·역순 후보·공통 장면 준비를 확인했다. 다음은 같은 raw 입력의 실제 MuJoCo 연속 실행 및 키가 연결된 상태의 최신 Astra 시범이다. 기존 STEP 48의 WSL 차단 기록은 당시 결과로 보존한다.


[STEP 50](STEP_50_RAW_CAD_ASSEMBLY.md)에서 CAD 목록→실제 native 체인→같은 주 장면의 2/2 설치→이전 해제 사례 검색/재검증→결과/영상까지 539.063초에 확인했다. 정책은 scripted 개발 정책이며 API 0회다. [STEP 51](STEP_51_STEP_INPUT_READY.md)에서는 누락된 STEP 변환 라이브러리를 원본 보존 후 F:로 복사하고, 별도 소형 STEP 단일 파일의 부품·단위·완성 배치 추출부터 실제 분해 검증/장면 준비까지 확인했다. 이 STEP 예제의 로봇 조립을 확인한 것은 아니다. 다음은 키를 가진 사용자 UI 서버를 유지한 상태의 실제 Astra 검증이다.


## 2026-11-26 실제 Astra UI 시범 후속

[STEP 52](STEP_52_ASTRA_INPUT_SIZE.md)에서 후보 입력 중복을 줄여 실제 첫 요청을 12,047→7,267토큰으로 줄였다. [STEP 53](STEP_53_ASTRA_UI_TRIAL.md)의 새 실제 Astra high R0 실행은 생성 3회·추정 $0.258317, 첫 부품 본 장면 설치 통과 후 두 번째 복사 관찰 중 시간 한도로 종료했다. 본 장면 1/2, 별도 복사 상태 관찰 501회 통과를 구분한다. 복구 역할 호출·새 해결지침·등록은 0이다.

시간 초과를 물리 실패로 감싸던 오류를 수정했고 136개 회귀 검사 및 별도 실제 MuJoCo 관찰/중단 시험을 통과했다. 수정 후 전체 Astra 재실행, 자연 실패 복구·경험 재사용, 배터리 전체 시험은 남아 있다. 이번 결과만으로 본 수집/독립 평가를 시작하지 않는다.

## 2026-11-26 물리 계산 간격 후속

[STEP 54](STEP_54_TIMESTEP_VARIANTS.md)에서 0.004초/0.01초를 별도 개발 옵션으로 연결했다. 기존 0.002초 완료 프로파일은 유지한다. 12개 실제 파지 유지 진단 후 0.01초 새 장면은 첫 그리퍼 관절 검사에서 실패했고, 0.004초는 같은 주 장면에서 두 부품 설치·해제·1초 관찰을 251회 통과했다. 소요 197.843초, API 0회 scripted 실행이며 147개 코드 검사도 통과했다.

실험 프로파일은 연구 수집/평가를 차단하고 다른 계산 간격 경험과 검색을 구분한다. 다음 검증은 선택한 0.004초의 새 Astra 전체 흐름, 더 복잡한 접촉/배터리 및 동일 조건 반복 비교다. 새로운 Astra 호출과 배터리 전체 조립 검증은 이번에 수행하지 않았다.

Astra는 첫 파지와 1mm 보정을 제안했으나 복사 해제 접촉/계획 끝 자세 충돌로 주 장면 0/12, 경험 등록 0이다. 생성 합계 3회·추정 $1.1528055, 156개 코드 검사 통과. 다음은 API 없는 실제 접촉 위치 기반 파지·해제 경로 개선이며, 두 후보의 실패를 제품 전체의 조립 불가능으로 해석하지 않는다.

## 검증된 설치 상태 이어가기

[STEP 57](STEP_57_RELEASED_CONTINUATION.md): 기존 설치 증거와 전체 저장 상태를 검증하고 1초/501회 재관찰한 뒤 API 없이 남은 조립을 수행하는 경로를 추가했다. 전체 개발 시간 제한은 선택 사항이며 개별 동작 한도·물리 기준은 유지한다. 기하 수정 후보 선택 누락과 2π 관절 각도 분기에서 IK가 해를 놓친 문제를 보완했다. 최신 배터리 실행과 실제 검증 범위는 STEP 57 및 F:의 별도 결과를 따른다. 전체 조립 성공이나 새 Astra/연구 경험 수집 성공으로 미리 판정하지 않는다.
