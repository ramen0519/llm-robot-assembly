# 현재 개발 계획 · v1.2부터 새 경험 수집

2026-11-24 사용자 요청으로 구버전 코드와 모든 과거 조립 경험·생성 스킬·실험 기록을 정리했다. 이번 계획과 [MASTER v1.2](design_v12/ASSEMBLY_MASTER_DESIGN_v1.2.md)를 현재 기준으로 사용한다. 원문 설계의 과거 코드 보존 지침은 이번 명시적인 삭제 요청으로 갱신되었다.

## 현재 구조

제품 입력/실제 분해 export → 지원 형상 자동 준비 → 관측 → 공유 이력 정책 → 복사 검사/주 실행/설치 검증 → 다음 부품 또는 지원 복구 → 원래 부품의 해결 사건과 근거 있는 자연어 지침 → 다음 run의 조건·이미지 검색.

같은 실행기에서 S0(single/off), S1(single/on), R0(순차 역할 분리/off), R1(순차 역할 분리/on)을 비교한다. 현재 스킬은 검증된 실행 함수이며 LLM이 임의 Python 실행 코드를 생성하는 경로는 없다.

## 남은 순서

1. 비어 있는 메모리와 정리된 코드로 입력부터 scripted MuJoCo 설치까지 회귀 확인. 결과는 [STEP 28](STEP_28_CLEAN_START.md)에 남긴다.
2. 승인된 키·모델·금액·시간 설정으로 작은 실제 Astra+MuJoCo 실행 확인. 지난 키 부재 및 실제 모델 미검증을 성공으로 바꾸어 기록하지 않는다.
3. 로컬 DINO 선택 의존성 준비와 실제 특징 계산 검증. 동일 카메라 v2에서 새로 모은 실패 이미지로 검색 확인.
4. 독립적인 collection 조건에서 객관 사건과 종료 후 지침 수집. 새 기본 메모리는 `runtime/memory/assembly_v12`; 개발 fixture를 수집 완료 사례로 세지 않는다.
5. collection 메모리·입력·코드·모델·도구·예산을 고정한 뒤 보류한 evaluation 조건에서 S0/S1/R0/R1 비교. 유료/장시간 batch는 별도 승인 범위에서만 실행.
6. 전체 10부품 프레임의 실제 연속 통합 검증. 지난 시도는 분해 180초 상한에서 2/9 제거 후 중단되었고 전체 성공은 아직 미완료다.

이번 정리는 실물 로봇 연결, 일반 CAD 지원 확대, 모델 파인튜닝, 추가 유료 호출을 포함하지 않는다. 로봇/그리퍼 크기, 접촉·파지·설치 안정성 기준과 지원 복구의 누적 예산을 유지한다.
