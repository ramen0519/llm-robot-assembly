# 현재 개발 계획 · 일반 메시 v2

최신 기준은 `docs/design_v2/`의 세 문서다. v1.2의 사각 전용 범위를 일반 메시 실행으로 대체하되 기존 프레임은 회귀 사례로 보존한다. 이번 작업은 사용자 요청에 따라 입력·실행·경험·UI·평가를 통합하며 모듈마다 재승인을 요청하지 않는다.

## 구현 경로

1. 원본 단위·완성 배치·검증된 native 체인과 실제 기하 대응 검사.
2. 원본 메시·검증된 convex decomposition·원본 체적/관성·고정 베이스·동적 부품·초기 배치 생성.
3. 별도 완성 기준 장면의 연속 물리 유지 검사. 실패는 `reference_invalid`.
4. 실제 메시 표면/법선 파지 후보와 Astra의 선택·수정·직접 전체 pose 제안.
5. 복사 장면의 파지 가능성과 해당 파지의 설치 가능성을 분리 검증.
6. 주 장면의 접근·닫기·들기·운반·설치·해제·후퇴. 계획용 현재 파지 변환과 최초 슬립 기준을 분리.
7. 동일 완료 프로파일로 모든 설치 부품의 동일한 연속 창 검사.
8. 객관적 실패 사건 → 실제 설치 해결/종료 보존 → 근거가 연결된 지침 → 다음 실행의 고정 snapshot 검색.
9. 공통 실행기를 호출하는 로컬 UI, 실제 상태 영상, 기록 audit, 원 run 이동 후에도 확인 가능한 bundle.
10. 실제 Astra memory-off 시범 수집 → 등록 확인 → 본 수집 → 동결 → 독립 평가의 S0/S1/R0/R1.

## 완료 확인 원칙

코드 존재, 계약 검사, 실제 MuJoCo, 실제 Astra, 다음 실행의 경험 재사용, 새 CAD 전체 조립을 서로 다른 증거로 기록한다. `not_run`을 성공으로 바꾸지 않는다. 모든 CAD에서 성공한다는 주장은 하지 않는다. 후보/경로/시간 소진은 현재 예산 내 미발견이다.

실제 결과와 F01–F16/V01–V08 상태는 [STEP 29](STEP_29_GENERAL_MESH_V2.md)가 기준이다. 남은 우선순위는 응답 가능한 native 분해 환경, 실제 Astra 키/승인된 집계 예산, 배터리의 엄격한 충돌 자산 준비, 10부품 및 일반 제품의 실시간 모델 연속 조립, 실제 모델로 생성한 지침의 다음 실행 재사용 검증이다.

실물 연결·나사 조임·유연체·재파지 전략·fine-tuning은 이번 구현 성공 범위에 포함하지 않는다. 코드·제품 원본·로봇 자산·완료 프로파일·모델/예산·메모리를 동결한 후 연구 비교를 진행한다.
