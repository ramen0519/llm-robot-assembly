# 22U · 기존 개발 장면에서 메모리·코드 스킬의 비교 조건 점검

**2026-11-12. 첫 미사용 제품 실험에는 22T에서 정한 축소안 A/B를 사용한다.** A는 현재 관측과 회차 안의 실패 이력, B는 거기에 동결한 슬리브 경험 1건을 더한다. 같은 기둥 실패에서 기존 B와 C가 읽는 과거 자료가 달랐고, 등록 함수의 적용 범위도 기존 제품의 특정 기둥에 묶여 있었다. 이번 검사는 시험군의 정보 차이를 측정했다. 평가 제품의 조립 성공률과 재시도 횟수 측정은 아직 시작하지 않았다.

## 슬리브 첫 파지

22R의 슬리브2·4와 22S의 슬리브3·2의 **집기 전** 체크포인트를 각각 세 번 복원했다. 원래 LangGraph가 안정화·관측을 거쳐 첫 파지 요청을 만들면 모델에 보내기 직전에 중단했다. B·C의 검색어는 검사자가 고정했다. 기존 모델 응답이나 미래의 파지 결과를 새 요청 입력에 넣지 않았다. 같은 개발 상태를 비교한 A/B/C 세 요청에서 물리 상태 지문이 일치했다.

| 4개 개발 상태에서 관찰한 항목 | A | B | C의 슬리브 경로 |
|---|---|---|---|
| 과거 슬리브 카드 | 0건 | 상태당 1건 | B와 같은 1건 |
| 현재 형상, 관측, 남은 시도, 제안 도구 | 공통 | 공통 | 공통 |
| 첫 집기 전 경험 검색 요청 | 없음 | 있음 | B와 동일 |
| 파지 판단 지시문 | 기본 지시 | 경험을 어떻게 참고했는지 설명하는 문구 추가 | B와 동일 |

네 상태 모두 B·C의 검색 요청과 첫 파지 요청 내용이 각각 같았고 기존 실시간 요청 기록과도 일치했다. 이번 12개 요청 캡처의 새 모델 호출은 0회다. 따라서 A/B의 처치는 **경험 검색·카드 제공 및 활용 근거를 설명하는 지시를 함께 켠 것**으로 보고한다. 카드만의 효과를 분리하려면 지시문까지 공통화한 새 설계가 필요하다.

## 같은 기둥 실패에서 B와 C가 읽은 정보

네 기둥 제품의 빈 장면과 당시 개발용 첫 제안(+1 mm)을 복원했다. 실제 무조코 복사본에서 오른쪽 패드와 바닥판 벽의 같은 삽입 간섭과 **−2.37 mm**의 예상 여유가 재현됐다. 원래 장면은 사전검사 전후 상태가 일치했다.

- 코드 저장소를 끈 현 B의 복구 요청에는 현재 실패 1건과 과거 기둥 카드 **0건**이 들어갔다. 이 단계에서는 슬리브 검색이 작동하지 않는다.
- 같은 상태의 기존 22R 실시간 선택기 기록에는 검색·문서 읽기·스킬 선택 과정이 있다. 당시 복구 에이전트에 과거 실패 카드 1건과 스킬 설명 카드 1건이 전달됐음을 실제 요청·응답과 대조했다. 이 3회는 과거 호출이다.

이 상태에서 C를 켜면 에이전트가 읽는 자료와 실행 가능한 함수가 함께 달라진다. **C−B를 코드 실행의 추가 효과로 해석하기 위한 22T의 사전 조건을 충족하지 못했다.**

## 동결한 코드 스킬은 어디까지 적용됐나?

| 개발 사례 | 이번 검사 | 기존 원래 장면에서 확인된 동작 |
|---|---|---|
| 네 기둥 제품, 기둥1 | 동결 코드와 당시 관측·거절 기록으로 **+4.37 mm**가 다시 계산됐다. 제안 전체와 선택한 코드 해시가 원본과 일치했다. | 같은 값으로 집기·인계·설치. 설치 위치 오차 0.121 mm. |
| 삼각 배치 제품, 기둥3 | 원래 상태를 복원하고 당시 −4 mm를 복사본에서 다시 검사했다. 집기는 성공했고 삽입 경로에서 패드–벽 간섭과 **−7.30 mm**의 예상 여유가 다시 측정됐다. 이 근거로 기존 함수를 조회했지만 등록 조건이 달라 실행이 거절됐다. | 기존 회차는 복구 에이전트가 직접 제안한 **+8 mm**로 집기·인계·설치. 설치 위치 오차 0.122 mm. |

새로 수행한 무조코 사전검사는 기둥 사례별 1회씩이다. 이번 회차에서는 원래 장면에 부품을 새로 설치하지 않았다. 위 설치 수치는 과거 개발 회차의 물리 판정, 손끝 동작, 실제로 실행한 파지와 대조한 값이다.

```powershell
.\runtime\luna-venv\Scripts\python.exe -B -u -X utf8 scripts/check_development_knowledge.py
```

실행 기록은 `runs/step22u_development_knowledge/20261111T181118_233390Z_d005ff52a8a3`에 있다. 각 슬리브 JSON에는 요청과 초기 상태 지문, `post_requests.json`에는 B·C의 문서 ID와 모델 요청 출처, `post_scope.json`에는 계산·거절·기존 원래 장면의 설치 근거, `result.json`에는 사전 조건별 결과가 있다. 관련 회귀 검사 20개가 통과했다.
