# STEP 44 · 짧은 동작 계획과 실행·검증 연결

2026-11-25. 긴 Python 프로그램을 매번 생성하는 방식 대신, 공통 실행기가 지원하는 짧은 계획을 제안·수정하도록 확장했다. 임의 코드 생성, 새 도구 학습, 재파지·나사 작업은 포함하지 않는다.

## 모델이 바꿀 수 있는 것

`motion_plan`은 접근 거리(40~120mm), 들기 높이(65~120mm), 최대 2개 운반 중간 위치, 설치 접근 방향, 기하로 계산한 접근 여유에 더할 거리(0~40mm), 기존 해제 방식 중 선택을 담는다.

파지 방향은 기존 전체 TCP 자세로 제안한다. 중간 위치는 CAD 부품 목표 원점을 기준으로 한 **월드 축 방향 mm 오프셋**이고, 목표 부품 방향은 유지한다. 삽입축이 정의된 작업의 축은 바꿀 수 없다. 기하 검사에서 필요한 최소 접근 여유를 줄일 수 없다.

`null` 계획은 현재/공통 기본 계획을 유지한다. 새 pick은 공통 기본값에서 시작한다. 기존 기본 들기는 100/80/65mm 후보 중 물리 명령 전에 계획이 가능한 것을 검사한다. 모델이 높이를 명시하면 그 높이를 시험하고 결과를 돌려주므로, 호스트가 다른 높이를 몰래 실행한 것을 모델 제안의 성공으로 세지 않는다.

## 연결과 통과 기준

- `motion_plan.py`: 유한 값·범위·단위·허용 필드 검사. 힘·완료 기준·물성·예산 변경은 계약에 없다.
- `policy.py`: 동일한 모델·공유 이력·도구 계약에서 `fixed` 또는 `bounded` 선택. 새로운 관측에는 계획 또는 null이 필수다. 예전 기록을 읽는 호출과는 명시적 호환 경로를 유지한다.
- `skills.py`: 같은 계획을 복사 시험과 주 실행에 적용. 실제 들기·이동·해제·후퇴 후 원래 완료 검사를 수행한다.
- `execution.py`: 계획을 사건에 기록하고, 실제 들기 전 계획 실패에서는 `lift`를 제안할 수 있게 연결. 잡은 상태의 설치 계획을 바꾸면 새 복사 검사 후 실행하며, 거절되면 이전 계획으로 복원한다.
- `memory.py`, `packets.py`: 해결 지침에 계획을 넣으려면 실제 성공한 행동의 정확한 적용 계획과 사건 ID가 필요하다. 원래 실패와 실제 주 장면 설치 근거도 요구한다. 코드 테스트용 사례는 경험으로 등록하지 않았다.
- `entry.py`: `--motion-plan-mode fixed|bounded` 연결. 기본은 bounded, UI도 같은 실행기로 연결된다.
- 바뀌지 않은 계약 설명은 다음 모델 메시지에서 이전 공유 이력을 참조한다. 현재 계획과 허용 동작은 계속 전달한다. 과거 이력은 잘라내지 않는다.

## 검사

최종 계약·회귀 검사 107개 통과(9.508초). 기존 테스트에서 옛 호출의 필드와 가짜 실행 객체 초기화가 새 계약과 맞지 않던 부분을 수정했다. 범위를 벗어난 값, NaN, 임의 필드, 정의된 삽입축 변경, 오래된 관측, 실제로 실행하지 않은 계획을 해결 지침으로 저장하는 경우를 거절한다.

코드 검사 통과를 전체 물리 검증으로 해석하지 않는다. 각 계획 선택지의 실제 검증 범위는 후속 비교 보고서에 구분한다. 모든 일반 형상·모든 방향·모든 해제 선택이 검증된 것은 아니다.

## 실행

```powershell
cd C:/dev/llm-robot-assembly
$assemblyPython = './runtime/luna-venv/Scripts/python.exe'
& $assemblyPython -B scripts/run_assembly.py run `
  --input 'C:/path/to/prepared.json' --policy astra --condition R0 `
  --motion-plan-mode bounded --split development --seconds 600
```

고정 행동 비교는 `--motion-plan-mode fixed`로 같은 코드·물리·예산을 사용한다. 이 모드에서는 모델의 `motion_plan`은 null이어야 한다. 입력 경로는 실제 제품 자료로 바꿔야 하며 새 유료 실행은 현재 승인 범위 안에서만 한다.

`scripts/probe_motion_plans.py`는 동일한 실제 파지 체크포인트에서 들기 한 번만 비교하는 작은 개발 검증 도구다. 전체 조립 성공률, 경험 수집, 새 제품 일반화 시험을 대신하지 않는다. 실제 API 모드에는 조건별 1회 생성, 명시적인 최대 비용·시간이 필요하고 오류 시 자동 모델 재호출은 없다.

실제 Astra high의 65mm 들기 제안과 실제 MuJoCo 검증, 고정 실행기와의 토큰·시간 비교는 [STEP 45](STEP_45_ASTRA_MOTION_COMPARISON.md)에 기록했다.

셀 7의 별도 설치 계획 복사 검사는 `unknown`, 주 장면 상태 보존은 통과했다. 판정과 제한은 STEP 45의 마지막 추가 검사에 기록했다.
