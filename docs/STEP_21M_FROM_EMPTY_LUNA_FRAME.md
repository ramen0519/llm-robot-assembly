**검증 중단 (2026-11-05).** runs/step23_frame/20261105T045731_324207Z_a5a5914d는 코드 69aec1b로 빈 바닥판에서 시작했다. 첫 기둥 설치를 기록하고 둘째 기둥의 pick/insert를 마친 후, 완료 응답에 앞선 입력 토큰 계산 요청이 APIConnectionError로 실패했다. 전체 성공이 아니다. 생성 요청 7회, 입력 계산 시도 8회, 알려진 추정 비용 $0.002269875다. 실패한 입력 계산 뒤에는 모델 생성이나 물리 동작을 재시도하지 않았다. 21L과 결과·비용은 별도다.

## 이번 단위의 목표

고정 바닥판 1개와 자유 부품 9개에서 시작해, 기둥 4개·슬리브 4개·덮개 1개를 한 MuJoCo 장면에서 설치한다. 모든 부품의 파지 위치 X·Y·Z와 손가락 닫힘 각도는 실제 Luna가 제안한다. 후보를 MuJoCo 복사본에서 검사하고, 거절한 측정 정보를 받아 수정하며, 승인된 숫자를 원래 장면의 실제 동작에 그대로 사용한다.

이번 단계는 새 동작 코드를 추가하는 일이 아니라 **수정을 끝낸 동일 코드의 처음부터 끝까지 검증**이다. 21K의 중단과 21L의 상태 재개는 각각 별도 기록이며, 이 실행의 설치 개수에 합산하지 않는다. 최종 결과가 success, 설치 수가 9이고 독립 검사까지 통과해야 완료로 기록한다.

## 실행과 검사 방법

실제 API 환경 준비는 [21E](STEP_21E_FIRST_LIVE_LUNA.md), 현재 좌표 설명·저장 및 재개 기능·관련 검사 9개는 [21L](STEP_21L_RESUME_FULL_LUNA_FRAME.md)를 따른다. 로컬 설정 파일은 키를 포함하지 않으며 다른 컴퓨터에서는 config/llm.example.toml을 기준으로 활성화한 모델·단가·예산 설정을 준비한다.

모델은 gpt-6-luna다. 생성 요청 50회, 전체 토큰 300,000, 설정 단가 기준 추정 비용 $0.15가 한 실행의 상한이다. 부품마다 예산을 새로 받지 않는다. 기록 사진을 보는 것은 추가 호출이 없고, --viewer로 새로 실행하면 모델을 다시 호출한다.

최종 검사는 다음 내용을 대조한다.

- 시작 시 설치물 0개와 자유 부품 9개. 이전 실행을 재개하거나 미리 조립한 장면이 아님.

- 손을 뗀 뒤 네 슬리브의 기둥 관통, 덮개 네 구멍의 관통, 슬리브별 덮개 지지력, 모든 부품의 위치·방향을 현재 장면에서 확인함.

## 결과의 범위

현재는 위에서 접근하는 파지와 정해진 CAD·결합 치수·트레이 배치·시뮬레이터 정답 관측을 사용한다. 순서는 요청한 기둥 1~4 → 슬리브 1~4 → 덮개이며, 외부 분해 플래너를 이번 실행에서 호출하지 않는다. 이동에는 Mink IK와 기존 모션 도구를 쓰고, direct_then_rrt의 우회는 모션 계층 동작으로 기록한다.

Luna는 각 부품의 네 파지 매개변수와 허용된 다음 동작을 선택한다. 새로운 Python 동작 코드를 생성하지 않는다. 같은 부품의 실패 후보는 다음 제안에 전달하지만, 다른 부품의 성공 파지를 자동 학습하는 메모리나 동결 지식 묶음은 이번 실행에 사용하지 않았다.

이것은 개발용 10부품 프레임의 시뮬레이션 프로토타입 검증이다. 처음 보는 임의 조립품, 카메라 인식, 다중 LLM 비교, 별도 시험셋 반복 성공률과 실물 동작은 다음 검증 범위다. 21K에서 좌표 설명을 보완하고 21L을 재개한 것은 개발 중 수행한 변경이며, 실행 중 에이전트가 자신의 코드나 프롬프트를 자동 수정한 기능은 아니다.
