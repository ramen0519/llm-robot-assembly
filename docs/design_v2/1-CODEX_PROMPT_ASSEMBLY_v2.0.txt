[가장 중요한 목표와 이전 지시 대체]

사용자 목표는 사각 기둥·슬리브·덮개 전용 조립기가 아니야.
완성 CAD/목표 배치를 입력하면 고정 Python이 실제 형상과 초기 배치를 준비하고, Astra가 잡을 부위·방향을 선택/수정하며, Python과 MuJoCo가 실제 접근·닫기·들기·운반·설치·해제·안정성을 시험하는 시스템이야. 실패하면 실제 근거를 돌려줘 재시도하고, 해결된 경험과 지침을 저장·재사용해야 해.

이번 v2.0은 이전 문서의 '사각 형상만 허용, top-down 파지만, 수직 사각 삽입만, max_parts=10 유지, 사각 프레임 성공이면 최종 완료' 지시를 명시적으로 대체해. 오래된 설계·프롬프트·README에 충돌 지시가 남지 않게 갱신해.

[필수 구현]

1. STEP/OBJ의 부품 인스턴스·단위·원본 메시·현재/목표 SE(3)를 보존해. 제품별 수동 좌표나 관계 registry 작성 없이 입력 하나로 자동 준비되게 해. raw CAD와 검증 분해 export 경로 모두 연결하고 자동 베이스 선택/고정 가정을 명시해.

2. 특정 형상 분류를 공통 실행의 필수 조건에서 제거해. 원통·곡면·오목한 케이스·비대칭 부품도 실제 메시로 충돌 자산·질량/관성·장면을 생성해. bbox나 단일 convex hull로 구멍을 막지 말고 충돌 근사 품질을 검사해. scene.py의 boxes/kind/구멍 치수/identity 목표 회전 가정까지 바꿔. 거절문만 지우고 끝내지 마.

3. Python이 메시 표면·법선·접촉면 간격·실제 그리퍼 형상에서 파지 후보를 생성하고, Astra가 후보 ID를 선택하거나 전체 위치·방향 pose를 수정/직접 제안하게 해. 위·옆·경사 접근을 처리하고 기존 bbox 내부 TCP 제한을 일반 파지에 적용하지 마. 후보의 좌표계·단위·quaternion·revision·출처를 검증해. 기하 후보 점수를 실제 파지 성공으로 취급하지 마.

4. 접근·닫기·들기·슬립 검사를 통한 파지 가능성과, 그 파지로 운반·설치·해제 가능한지를 분리해. 현재 copy의 pick+사각 insert 결합을 풀고 두 결과의 원인을 각각 반환해. copy 시험과 주 장면 실행을 구분하고 실제 실패 상태를 순간이동이나 숨은 고정으로 지우지 마.

5. 검증 분해 부품 궤적의 좌표/단위/hash를 prepared까지 보존해 역경로를 설치 접근 후보로 활용해. 부품 경로는 로봇 궤적이 아니므로 로봇·그리퍼·잡힌 부품의 IK/연속 충돌/접촉을 다시 검사해. 유효한 역경로가 없거나 따를 수 없으면 검증된 순서와 CAD 목표 pose로 허용된 경로 계획기를 사용해. 입력의 필수 검증 증거 누락은 우회하지 마.

6. 실제 파지 상대변환으로 목표 TCP와 경로를 계산하고, 임의 목표 회전·접근·해제 후 후퇴를 검사해. 목표를 identity 회전이나 world-Z 수직 삽입으로 강제하지 마. 목표 CAD와 관측에서 접촉 관계를 자동 생성하고, 수동 기둥–슬리브 규칙을 일반 경로에 요구하지 마.

7. 초기 자세·정착·배치를 자동 생성하고 전체 완성품 영역과 로봇 도달을 고려해. 정착 후 미설치 보존 기준을 한 번 확정해. 부품 수에 따라 동적으로 생성하고 고정10개 제한을 제거하되 실제 시간·메모리·기하·호출 예산은 유지해. 배치 탐색 실패와 물리적 불가능을 구분해.

[완료 판정: 수치는 확정]

- 원 CAD 목표를 보존하고 별도 완성 기준 상태 검사와 실제 주 조립을 분리.
- 고정 베이스 좌표계 XYZ 각 축 오차 절댓값 ≤5mm, 상대 SO(3) 회전각 ≤3°.
- 최종 경질 제품 관통 ≤0.5mm, 실행 중 경질 관통 >1mm이면 실패.
- 선속도 ≤1mm/s, 각속도 ≤0.01rad/s.
- 최종 로봇–제품 비접촉, 실제 그리퍼 충돌 형상–제품 최소거리 ≥5mm.
- 해제·후퇴 후 정착1초+이어지는 연속 관찰1초. 매2ms 스텝에서 같은 창의 모든 대상 부품 검사.
- 최종/기설치 목표 pose 보존은 같은 정책으로 통일.
- 삽입 깊이 오차<1mm와 사전 정렬<1mm/<1°는 실제 축·깊이를 정의한 해당 삽입 동작에만 적용. 일반 놓기에는 가짜 깊이를 만들지 말고 적용 불가의 근거를 기록. 필요한데 계산하지 못한 검사는 성공 처리하지 마.

자세한 의미는 완료 프로파일 v1.2를 따라. 실행기·memory·audit·평가 동결·UI가 같은 프로파일과 실제 증거를 사용하고 과거 결과는 당시 버전으로 보존해.

[기존 보완점·경험·UI]

전체 작업서 §10의 F01–F16도 모두 처리해. 정상 접촉 비대칭, 복구 변환, 실행 여부 보고, deadline, 전역/제어 예산, 수집·평가 분리와 누수, 자산 동결, audit, 검색 적용 조건, 지침 근거, 단위, 배치, 후보 출처, 지표, 재현 자산 보존을 새 일반 경로에 반영해.

원래 설치의 해결이 실제 검증된 사건에서만 지침을 등록해. 문제 조건 필터 후 DINO 이미지 임베딩으로 순위를 매기고 Astra에는 짧은 지침을 제공해. 파지 copy 통과를 설치 해결로 세지 마. 단일/순차 역할 비교에는 같은 후보·실행기·검증기·예산을 사용해.

기존 UI가 있으면 연결하고 없으면 기존 실행기를 호출하는 최소 로컬 UI를 구현해. 입력 선택→자동 준비/실행 상태→실제 결과·실패 근거·영상·비용·경험 등록/검색까지 확인되게 해. 제품마다 좌표·관계를 손으로 작성하거나 파지를 클릭해야 하는 흐름으로 바꾸지 마.

[실제 검증과 완료]

작업서 V01–V08을 확인해. 사각 프레임은 회귀 사례이고, 일반 비사각 부품의 실제 집기/설치와 위에서 내려오는 방향 외 파지도 확인해야 해. 일반 형상을 포함한10부품 이상 조립체의 실제 Astra 전체 run, 11개 이상 준비, 실패→후보 수정→설치 해결→지침 등록→다음 실행 검색/재검증, UI 연결을 증거로 제출해.

사용자의 실제 배터리팩/학습 CAD가 프로젝트에 있으면 우선 사용해. 해당 파일이 없으면 이름만 같은 예제로 대체하지 말고, 일반 fixture 검증과 사용자 제품 미검증을 분리해. 목표 직접 배치·작은 기둥 성공·mock·scripted를 일반 형상의 실제 Astra 완주로 세지 마.

기존 승인·설정 예산 안에서 Astra5회 시범 수집을 하고 판정·기록·저장 오류가 없으면 기존 manifest와 예산으로 본 수집을 이어가. 모두 성공할 필요는 없으며 실패와 실제 해결을 정확히 기록해야 해. 예산을 임의 증액하거나 실패를 숨기려고 공차를 더 완화하지 마.

내부적으로 모듈별 구현/검증을 하되 중간 단계마다 진행 허가를 다시 묻지 말고 이미 승인된 범위에서 끝까지 작업해. 실제 키·자산·예산이 없어 못 한 검사는 not_run과 이유로 남기고 가능한 구현/오프라인 검증은 완료해. 실제 통합 검증을 못 했으면 전체 검증 완료라고 보고하지 마.
