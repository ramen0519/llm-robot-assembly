# 5단계: UR3e 손목에 Robotiq 2F-85 장착

목표는 두 모델을 하나의 로봇으로 결합하고, 열린 그리퍼를 장착한 초기 자세가 중력 아래에서 유지되는지 확인하는 것이다. 손가락 개폐 동작과 물체 집기는 다음 단계다.

## 실행

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/view_ur3e_gripper.py
```

5초간 물리 계산을 진행한 뒤 창이 닫히며 `Gripper mount and hold: PASS`가 출력된다. 자세를 더 오래 살펴보려면 `--seconds 20`을 붙인다. 검사 완료 전에 창을 닫으면 실패로 종료한다.

```powershell
uv run --locked python scripts/view_ur3e_gripper.py --check
```

`--check`는 창 없이 같은 자세 유지 검사를 수행한다. 새로운 패키지 설치는 필요 없다.

## 파일과 데이터 흐름

- `models/robotiq_2f85/`: Menagerie 원본 모델·8개 메시·라이선스·출처 기록.
- `scripts/ur3e_with_gripper.py`: 두 모델을 읽고, 손목 기준점에 그리퍼를 붙이고, 초기 상태를 만든다.
- `scripts/view_ur3e_gripper.py`: 결합된 모델을 표시하고 5초간 상태를 검사한다.

기존 로봇만 표시하는 예제와 한 관절 이동 예제는 그대로 유지한다. 그리퍼가 달린 모델에서의 이동은 별도의 후속 검증이다.

## 실제로 무엇을 붙였나?

로봇 손목에는 `attachment_site`라는 가상의 위치·방향 기준점이 있다. 이 점에 그리퍼의 장착 구조를 연결한다.

```python
arm = mujoco.MjSpec.from_file(str(SCENE_PATH))
gripper = mujoco.MjSpec.from_file(str(GRIPPER_PATH))
arm.attach(gripper, site="attachment_site", prefix="gripper_")
model = arm.compile()
```

`MjSpec`은 실행 가능한 물리 모델로 변환하기 전의 모델 설명이다. `attach()`로 두 설명을 결합하고 `compile()`로 MuJoCo가 계산할 수 있는 모델을 만든다. 두 모델에 같은 이름이 있어도 충돌하지 않도록 그리퍼 쪽 이름 앞에 `gripper_`를 붙인다. [MuJoCo 공식 attachment 문서](https://mujoco.readthedocs.io/en/stable/python.html#attachment)

그리퍼 본체에는 손목과 따로 움직이는 관절을 추가하지 않았다. 따라서 볼트로 고정한 것처럼 손목을 따라 움직인다. 이것은 실제 장비의 고정 장착을 표현한 것이며, 잡을 물체를 손가락에 인위적으로 붙이는 기능은 아니다.

원본 그리퍼 장착부의 중심은 기준점에서 로컬 Z방향으로 7mm 떨어져 있다. 이 원래 오프셋을 유지하고 위치·방향 관계를 수치 검사한다. 위쪽에 붙거나 거꾸로 붙는 실수를 감지하기 위한 검사다. 실제 어댑터 치수와 장착 회전각은 실물 단계에서 확인해야 한다.

## 관절 14개인데 입력은 왜 7개인가?

| 부분 | 물리 관절 수 | 제어 입력 수 |
|---|---:|---:|
| UR3e 팔 | 6 | 6 |
| 2F-85 그리퍼 | 8 | 1 |
| 합계 | 14 | 7 |

그리퍼 손가락은 여러 막대와 관절로 연결되어 움직인다. 원본 모델의 tendon은 모터 힘을 양쪽에 분배하고, equality constraint는 연결부와 좌우 관절 관계를 유지한다. 각각을 별개의 모터처럼 조작하는 구조가 아니다.

팔의 제어 입력은 관절 목표 각도(rad)다. 이 그리퍼 모델의 제어 입력은 0~255이며, 이번에는 열린 상태에 해당하는 0을 유지한다. 255 방향의 개폐 성능은 이번 단계에서 검증하지 않았다.

원본 모델의 질량과 관성을 유지했으므로 그리퍼 무게도 팔에 영향을 준다. 형상만 화면 위에 겹쳐 그린 것이 아니다. 접촉 계산은 그리퍼 원본의 elliptic cone과 impratio=10을 결합 모델에 적용하고, 적분 방법 implicitfast와 시간 간격 0.002초는 팔 장면의 설정을 유지한다.

## 검사와 실제 결과

2026-10-26, Python 3.11.15 / MuJoCo 3.17.0에서 창 없는 실행과 뷰어 실행을 확인했다.

| 검사 | 기준 / 결과 |
|---|---|
| 구조 | 팔 6관절 + 그리퍼 8관절, 제어 입력 7개, equality 3개, tendon 1개 |
| 그리퍼 모델 질량 | 약 1.052608kg |
| 중력 아래 유지 | 5초 |
| 팔의 최대 자세 변화 | 1.070551도, 기준 2도 이하 |
| 마지막 0.5초 전체 관절의 최대 속도 | 약 0.000000298도/초, 기준 0.5도/초 미만 |
| 장착 기준점 관계 오차 | 수치 정밀도 수준, 기준 위치·회전 행렬 성분 오차 각각 1e-8 이내 |
| 관절 한계의 최대 초과량 | 약 0.000158rad, 허용 기준 0.001rad 이하 |
| 손가락 연결 위치 제약의 최대 성분 잔차 | 약 0.007513mm, 기준 0.1mm 이하 |
| 예상치 못한 접촉 / 엔진 경고 | 없음 |

MuJoCo의 관절 한계는 부드러운 제약이라 매우 작은 초과가 생길 수 있다. 이번에는 0.001rad까지 허용하고 실제 초과량도 출력한다. 연결 제약 잔차는 연결된 막대가 수치적으로 얼마나 어긋나는지 나타낸다. 이러한 허용값은 이 장면의 검사 기준이다.

장착 위치를 일부러 10mm 틀리게 만든 임시 대조 실험에서는 장착 검사가 실패했다. 정상 모델은 실제 렌더러로 확인했고, 뷰어도 정상 종료했다. 원본 모델 파일은 대조 실험으로 수정하지 않았다.
