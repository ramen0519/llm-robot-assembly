# 21H · 슬리브를 든 채로 정렬 실패에서 복구한다

## 실험 조건

21G에서 썼던 바닥판, 설치된 자유 기둥, 작업대의 슬리브를 사용한다. 이번에는 처음 삽입할 때만 운반 목표를 월드 X 방향으로 6mm 이동시킨다. 이 값은 개발자가 설정한 시험 조건이다. 그리퍼가 모터로 그 목표까지 이동한 뒤 실제 슬리브 위치와 목표의 차이를 측정한다. 기둥과 슬리브의 시뮬레이션 좌표를 덮어쓰지 않는다.

파지 제안은 기존처럼 독립 복사본에서 정상 삽입까지 검사한다. 본 실행에서는 승인한 자세로 슬리브를 집는다. 오정렬 시험은 본 실행에만 적용한다. 수평 오차가 1mm 이상이면 그리퍼가 슬리브를 잡고 있는 상태에서 하강 전에 멈춘다.

## 모델과 실행기가 맡은 일

1. 단일 Luna가 슬리브 파지를 제안한다. 그리퍼가 실제 슬리브를 집은 뒤 첫 삽입을 선택하면 실행기가 한 번만 어긋난 운반 목표를 적용한다.
2. 정렬 검사가 실패하면 LangGraph가 같은 장면을 재관측한다. Luna는 실패 코드·단계와 함께 현재 가로·세로 오차, 기둥 끝과 슬리브 밑면의 수직 간격, 양쪽 패드 접촉, 물체 속도·지지 상태를 받는다. 허용된 행동은 한 번의 재정렬 또는 중단이다.
3. 재정렬을 선택하면 기존 복구 스킬이 현재 파지를 다시 검사하고, 10mm 위로 물러난 뒤 잡힌 슬리브와 그리퍼 사이의 실제 위치·방향으로 새 목표를 계산한다. 허용 가로오차 20mm, 최소 수직 여유 20mm 등 복구 조건을 만족할 때만 수행한다. 복구 중 기둥의 지지와 움직임도 검사한다.
4. 정렬 복구만으로는 설치 완료가 아니다. 다음 관측에서 모델이 다시 삽입을 선택해야 하며, 손을 놓고 후퇴한 뒤 바닥판 지지와 기둥이 양쪽 구멍을 통과하는지를 포함한 아홉 조건을 다시 검사한다.

## 실제 실행

실행 폴더는 `runs/component_probes/20261103T104005_919166Z_da66981f`이다. Luna의 선택 순서는 `pick → pick → insert → recover_alignment → insert → finish`였다. 파지 단계에서는 첫 제안이 복사본에서 거절되어 마지막에 슬리브 중심보다 8mm 위를 잡았다. 아래 오정렬은 그 뒤 원래 장면에서 발생한 별개의 실패다.

| 시점 | 원래 장면의 측정·행동 |
|---|---|
| 첫 삽입 전 검사 | 수평 오차 6.090mm (허용 1mm 미만). 기둥 끝 위 55.07mm에서 정지. 양쪽 패드 접촉 유지 |
| 복구 선택 | Luna가 재정렬을 선택. 10mm 상승 후 현재 파지 변환으로 다시 정렬. 수평 오차 0.138mm, 복구에 걸린 시뮬레이션 시간 9.250초 |
| 삽입·해제·후퇴 | 슬리브 최종 위치 오차 최대 0.035mm. 구멍의 최소 측면 여유 1.979mm. 기존 기둥의 최대 목표 위치 오차 0.175mm. 최종 검사 9/9 |

복구 전후 시간은 81.222초와 90.472초다. 본 실행의 물리 추적에서 파지 닫기는 한 번, 삽입 하강과 해제는 재정렬 이후에 각각 한 번이었다. 실제 Luna 생성 요청 6회, 추정 비용 0.001466375달러, 프로젝트 누적 추정 비용은 0.007714875달러다. 인보이스 금액과는 구분한다.

재정렬 좌표와 관절 궤적은 기존 스킬이 계산했다. 이 한 건은 정상적으로 잡힌 슬리브의 오정렬에 대한 모델의 행동 선택과 복구 실행 근거다. 실패 종류 전반의 성공률은 측정하지 않았다.

관련 회귀 검사 28개를 통과했다. 슬리브 중단 경로 및 기존 물리 복구 검사 5개, 조립 그래프와 API 계약 검사 23개다. 별도의 키 없는 중단 시험에서는 실제 오정렬 이후 정책이 중단을 선택하면 슬리브를 잡은 채 시뮬레이션 시간이 더 진행되지 않고 하강·해제가 실행되지 않음을 확인했다. 기존 고정 파지 복구 절차도 현재 코드로 재검증해 동결했다.

## 재현과 기록

`C:\dev\llm-robot-assembly`에서 프로젝트 키가 등록된 PowerShell로 실행한다. `runs/step21h-budget.toml`은 21G에 쓴 로컬 설정의 생성 요청 한도를 7회로 설정한 파일이다. 이번 실행의 추정 비용 상한은 0.02달러다. 새 복제본에서는 활성화된 프로젝트 설정 경로를 지정한다. `--scenario`를 생략하면 기존 정상 장면이 실행된다.

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/run_component_probe.py --component sleeve_1 --sleeve-llm-config runs/step21h-budget.toml --scenario alignment_offset --snapshots
.\runtime\luna-venv\Scripts\python.exe -m unittest discover -s tests -p test_sleeve_alignment_recovery.py -v
```

- `graph_events.jsonl`에는 관측 번호, Luna의 행동과 순서가 있다. `llm_events.jsonl`의 복구 요청에 담긴 `alignment_observation`은 실패 후 원래 장면에서 다시 읽은 값이다.
- `failure_report.json`과 `alignment_failure.png`는 첫 삽입 실패 시점이다. `result.json`의 `skill_results`에 있는 `recover_alignment/v1` 기록에서 복구 전후 오차, 시뮬레이션 시간, 리셋 사용 여부를 볼 수 있다. `final.png`는 조립 종료 시점이다.
- 이 실험은 파지가 유지되고 슬리브가 기둥과 접촉하기 전 발생한 위치 오차를 다룬다. 끼임·낙하·부품 손상에서의 복구는 별도 시험 범위다.
