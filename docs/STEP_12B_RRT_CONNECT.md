# 모션 확장: 기존 RRT-Connect로 우회 경로를 찾고 실제로 움직이기

작성: 2026-11-01. 기본 12단계의 지역 중간점 이동에 더하는 별도 검증 모듈이다.

## IK·경로·궤적이 여기서는 어떻게 나뉘나

IK로 목표 TCP를 만드는 마지막 관절 자세를 구해도, 거기까지 가는 길은 막혀 있을 수 있다. 이번 시험은 목표 자세를 먼저 확보하고, 중간의 정적 장애물 때문에 기존 직선형 TCP 경로가 거부되는 장면을 만든다.

`joint_path_planner.py`는 여섯 관절 각도를 공간의 한 점으로 보고 다른 경로를 찾는다. 탐색 알고리즘은 직접 작성하지 않고 [Caelan Garrett의 motion-planners](https://github.com/caelan/motion-planners)의 RRT-Connect를 재사용했다. 커밋 `dba9aac6c5204b303c8d36b6a8291d1bbb6ba678`의 Python 파일, MIT LICENSE, 출처·파일 해시를 `third_party/motion_planners`에 보존했다. 원본의 Windows에서 허용되지 않는 이미지 이름은 패키지에 포함하지 않았다.

우리가 연결한 것은 로봇 관절 범위, 현재 상태, 후보 충돌 검사와 실제 실행기다. 후보마다 MuJoCo로 로봇·그리퍼·주변 물체의 형상을 검사한다. 기존 운반 부품 예상 자세 검사도 같은 함수에 남아 있다. 후보 계산용 복사본의 자세는 바꾸지만 실제 로봇 상태와 물리 시간은 진행하지 않는다.

찾은 경로에는 시간을 붙여 기존 위치 제어기로 실행한다. 시간 변화는 smoothstep이며 관절 기준 속도는 최대 5도/초에 맞춘다. 실제 이동 중에는 기존 500Hz 검사와 목표 TCP 도착·정지 검사를 계속 수행한다.

## 오래된 계획을 거부하기

이전에는 위치와 시뮬레이션 시간이 달라졌는지 확인했다. 이제 속도, 모터 입력, 이동 가능한 장애물의 위치·방향도 계획 당시와 비교한다. 같은 시각에 장애물만 옮겨도 기존 계획을 실행하기 전에 거부한다. 새로운 관측에서 다시 계획해야 한다.

탐색 시간이나 반복 한도를 넘기면 `MOTION_PATH_NOT_FOUND`로 종료한다. 이는 주어진 예산에서 검증한 경로를 찾지 못했다는 뜻이며, 가능한 경로가 아예 없다는 증명이 아니다.

## 실제 시험

```powershell
uv run --locked python scripts/run_motion_detour.py --snapshots
uv run --locked python -m unittest discover -s tests -p test_joint_path_planner.py -v
```

실제 실행: `runs/motion_detour/20261101T054611_820322Z_c6e1575b`.

- 시작·목표 자세는 가능하지만 중간의 빨간 정적 시험 장애물에 기존 TCP 경로가 걸리도록 구성했다.
- 장애물 변경 전 계획은 실행 전에 거부됐다. 새 직선 TCP 경로도 충돌 검사에서 거부됐다.
- 실제 선택된 탐색 방법: RRT-Connect. 검증 질의 488회, 최종 경로 229개 관절 자세.
- 경로 재검사 간격: 관절당 최대 0.25도. 시험 장애물에는 1mm 충돌 여유를 적용했다.
- 시험 탐색 범위는 시작/목표 관절 범위 주변 ±0.5rad다. 전체 관절 범위나 모든 장애물에 대한 성공 보장이 아니다.
- 예정 이동 시간 약 17.093초, 안정화 등을 포함한 전체 물리 시간 약 21.594초.
- 실제 도착 후 최대 TCP 위치 오차 약 0.0021mm. 이상화된 시뮬레이션의 측정값이며 실물 정확도로 해석하지 않는다.
- 실행 중 금지된 접촉이 없었고 목표 방향과 정지 검사도 통과했다.

경로를 화면에만 그린 결과가 아니다. 위치 제어기와 MuJoCo 물리 시간을 진행했다. 이 시험은 물체 조립을 수행하지 않으므로 `robot_installed_parts=0`, `assembly_success=false`로 기록한다.

검사 4개 PASS: 실제 우회 이동, 예산 소진 때 로봇 무동작, 속도/입력/장애물 변경 시 오래된 계획 거부, 잘못된 목표 각도 거부. 기존 운반 부품 경로 충돌 검사 1개도 다시 통과했다.

## 현재 연결 범위

기본 10부품 실행은 여전히 기존 지역 TCP 경로를 사용한다. RRT를 삽입 하강 중 자동 호출하지 않는다. RRT의 중간 자세는 TCP 방향을 계속 수직으로 유지한다고 보장하지 않으므로, 앞으로 자유 공간의 접근·운반 단계에 적절한 조건을 붙여 연결해야 한다.

실제 물리 검증은 **빈 그리퍼·정적 장애물 1개** 범위다. 부품을 잡은 RRT 이동, 움직이는 장애물, 정밀 접촉 중 우회, 실물 로봇은 별도 검증 대상이다. 현재 궤적은 조각별 관절 보간이며 산업용 가속도·jerk 제한 궤적까지 구현한 것은 아니다.
