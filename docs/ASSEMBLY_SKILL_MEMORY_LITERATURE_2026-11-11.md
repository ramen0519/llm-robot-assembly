# 조립 에이전트 선행연구 비교와 설계 결정

2026-11-11 · 졸업프로젝트 시뮬레이션 범위 · 비교 대상 28편/프로젝트. 회의에서 먼저 볼 곳은 1절과 5절이다. 실제 개발 순서와 통과 기준은 [프로토타입 설계서](SIMULATION_PROTOTYPE_PLAN_2026-11-11.md)에 반영했다.

## 1. 우리 프로젝트가 검증할 질문

**“같은 물리 피드백과 시도 예산에서, 과거 실패와 검증된 파지 스킬을 검색한 에이전트가 새 조립 구성의 삽입 실패를 더 잘 복구하는가?”** 조립·복구 역할 분리와 모델 교체는 이 질문을 시험할 실행 환경이 갖춰진 뒤 진행할 비교다.

- **가장 가까운 사례는 ReTrace의 플러그 삽입이다.** 실제 Franka가 플러그를 집고 들어 올리고 회전하는 데 성공했는데도, 앞서 선택한 파지 자세 때문에 뒤의 삽입에서 여유가 부족했다. 연구진은 관측을 되짚어 원인 후보를 이전 결정에 연결하고, 다음 시도에서 유효성을 점검했다. 우리도 실패가 검출된 ‘삽입 단계’와 수정할 수 있는 ‘앞선 파지 결정’을 따로 기록할 이유가 있다. [ReTrace 원문 그림 1·표 1](https://arxiv.org/html/2610.15814v1)
- **가장 가까운 조립 아키텍처는 AIDF의 Skill Graph와 CAD2Real이다.** 전자는 LEGO 조립의 스킬마다 실행 조건·완료 조건·판정기를 연결한다. 후자는 VLM이 현재 기하 상태를 보고 CAD와 시연으로 학습된 스킬의 순서와 매개변수를 고른다. 우리에게 설득력 있는 시연은 LLM이 고른 파지가 후속 결합까지 가능한지 로봇 실행기로 입증하는 것이다. [AIDF 저자 프로젝트](https://intelligent-control-lab.github.io/AIDF/) · [CAD2Real, IEEE RA-L](https://doi.org/10.1109/LRA.2026.3730294)
- **메모리의 이득은 과제에 따라 달랐다.** IEEE CASE의 Ahmad 등은 실물 핀 삽입을 포함해 실행 전 검사와 실행 중 복구를 평가했다. 해당 구성요소 제거 실험에서는 현재 회차의 실행 이력을 빼도 비슷한 성공률이었다고 보고했다. ReTrace에서는 이전 시도에서 습득한 스킬의 효과가 과제·모델별로 달랐다. 둘은 서로 다른 종류의 메모리를 시험했다. 우리 실험에서는 ‘현재 실패를 모두에게 제공하는 것’과 ‘다른 회차의 사례를 추가하는 것’을 서로 다른 변수로 다룬다. [Ahmad 등, V절](https://arxiv.org/html/2503.15202v1) · [ReTrace, IV절](https://arxiv.org/html/2610.15814v1)
- **부분 성공과 제품 완성은 매우 다르다.** Fabrica가 미학습 조립품을 대상으로 실물에서 측정한 일반 정책은 무개입 단계 성공률 80%, 무개입 전체 조립 성공률 10%였다. 단계마다 최대 세 번의 자체 시도가 허용됐고, 외부 개입 허용 횟수를 바꿨을 때 전체 결과도 따로 보고했다. 우리 9/9는 한 개발 회차의 설치 부품 수다. 전체 회차 수, 개입, 시도 한도를 함께 남긴다. [Fabrica 원문 표 4·5](https://arxiv.org/html/2506.05168v1)

### 조사 범위와 읽는 법

2026-11-11까지 공개된 연구를 대상으로, 물리 조립·접촉 삽입과 LLM/VLM, 코드 스킬·장기 메모리·실패 복구, 새 조립품 평가의 세 축에서 찾았다. IEEE·RSS·CoRL·ICLR·CIRP·제조 저널, arXiv 저자 원문과 저자 연구실 프로젝트를 사용했다. 같은 논문·코드·프로젝트 페이지는 한 편으로 셌다. 표 2~4는 직접 조립·지원 연구 14편, 스킬·메모리 방법 연구 8편, 비교용 계획·검색·평가 연구 6편이다. 28편 모두가 LLM·장기 메모리·자동 조립을 동시에 구현한 것은 아니다. 원문에 따라 실물, 시뮬레이션, 계획·파지 단위 평가를 적었다. 지표 정의가 서로 달라 연구 간 성공률 순위는 산출하지 않았다. 공개 자료를 선별한 기술 검토이며 저자 결과를 재현한 실험은 아니다.

## 5. 우리 설계에서 실제로 바꿀 것

**프로토타입 개발에서는 실패 근거로 스킬을 수정하고 재사용하는 경로를 먼저 완성한다.** 아래의 규칙·모델·검색 방식은 통합 시연 이후 비교군을 정할 때 쓸 후보안이다.

| 기존 설계 및 현재 상태 | 문헌을 반영한 변경 | 개발 확인 항목 또는 완성 후 실험안 |
|---|---|---|
| 22K는 +1mm 제안과 예상 여유를 기록한다. 기존 후보 함수에는 현재 예상 여유·접촉 쌍 입력 필드가 없다. | 22L에서 실패를 검출한 시점, 수정 대상인 과거 결정, 관측 근거, 원인 **가설**을 연결한다. 새 입력 버전에만 시점·좌표계·단위·출처가 있는 여유와 접촉 쌍을 허용한다. 값이 없으면 ‘미측정’으로 전달한다. | 같은 장면·부품·시도에 연결된 거절만 사용. 기존 v1 후보는 기존 계약으로 재생. ‘여유 개선’, ‘사전검사 통과’, ‘원래 장면 삽입 성공’ 세 결과를 별도 열에 기록. A01·A02·B01 근거. |
| 규칙 기준선·메모리 유무 비교를 계획했다. | **수치 기반 규칙**을 명시한다. 기둥에서 실패 단계·접촉 형상이 일치할 때만 예상 부족분과 사전에 정한 여유로 파지 높이를 계산한다. 여기에 현재 실패만 보는 LLM, 과거 경험까지 보는 LLM, 같은 경험과 검증 코드까지 쓰는 LLM을 대응시킨다. | 규칙과 LLM은 같은 현재 측정값, 허용 행동, 시작 장면, 제안 횟수와 물리 판정기를 받는다. 조립 성공이 같은 경우 검색·호출 비용도 보고한다. A06·B04·B06·C03 근거. |
| 한 조건에서 성공한 후보를 등록하고 다음 회차에서 재사용할 계획이다. | 등록할 때 ‘개발 조건에서 검증’과 ‘변경 조건으로 전이 검증’을 표시한다. 성공·계속 거절·보류·미확인 사례를 저장하고, 아직 시험하지 않은 형상은 적용 범위에 추가하지 않는다. | 스킬 버전, 원래 실패, 검증한 부품/결합, 사용할 수 없는 조건, 마지막 확인 결과가 검색 카드에 남는다. 목표 또는 그 시험 결과가 개발 자료에 섞이지 않게 동결한다. A01·B01·B03·C02 근거. |

**프로토타입 완성 후 비교군을 검토할 때 쓸 수치 규칙 예시.** 22K에서 같은 파지축의 Z를 0→+1mm로 올렸을 때, 명목 삽입 깊이에서 예측한 패드 여유는 −3.37→−2.37mm였다. 예를 들어 개발용 목표 여유를 +0.5mm로 미리 정하면, 선형으로 보정하는 규칙은 부품 중심 기준 Z = 1 + (0.5 − (−2.37)) = **+3.87mm**를 제안한다. +0.5mm는 설명용 설계값이며 +3.87mm의 성공은 미검증이다. 이 규칙은 같은 축·같은 종류의 간섭에서만 비교한다. 두 시험점으로 비선형 접촉, 파지 안정성, 다른 부품 여유를 예측할 수 없으므로 호환성·물리 사전검사·원래 장면 검증은 그대로 적용한다. 조건 밖이면 보류한다. [22K 원래 결과](STEP_22K_CANDIDATE_PREFLIGHT.md)

**진행 순서.** 개발 중에는 ① 기둥 실패 기록으로 Luna가 수정값이나 보류를 내도록 연결하고, ② 수정 후보의 사전검사와 원래 장면 설치를 확인하며, ③ 다음 개발 회차의 스킬 재사용과 전체 조립·복구를 통합 시연한다. 프로토타입 완성 후에는 버전을 고정하고 비교군·평가 과제·반복 수·예산을 정한 뒤 성능을 측정한다. 동일 실패에서 시작하는 복구 시험과 처음부터 수행하는 전체 조립 시험은 각각 집계한다.

**판단 기준.** 기하 규칙이 기둥 사례를 동등하게 해결하면 그 조건에서는 단순 규칙이 충분하다고 보고한다. 제품·실패 유형이 달라질 때 관련 스킬을 골라 쓰거나 보류하는 능력, 재제안·검사 횟수, 전체 조립 성공에서 차이가 나타나는지를 시험한다. 과제별 결과가 엇갈리면 어느 조건에서 어느 방법이 유리했는지 제시한다. 이번 반영 범위는 설계와 평가 기준이며 위 수정 규칙·새 후보·역할 분리의 성능값은 향후 실험 대상이다.
