## 입력과 판단

입력은 `F:/dev/llm-robot-assembly-data/research/20261126_prototype/socket_fixture/cad/assembly.json`이다. OBJ 대응·mm 단위·완성 배치가 있는 원본 목록이며 순서 hint와 제품 전용 Python은 넣지 않았다.

Python이 형상으로 우선순위를 준비하고 기존 native ASAP/RedMax가 분해 경로·지지를 검사했다. native 실행 `disassembly-7500e0b6865d4abc`의 연결된 parent/child와 before/after를 다시 확인했다. 경로 검사 12회·안정성 검사 2회, 제거 2/2, 추가 지지 0이다. 이 부분의 API는 0회이며 Astra가 분해 순서를 판단한 회차는 아니다. 부품 분해 경로를 로봇 관절 경로로 사용하지 않았다.

조립 조건은 `R0`: 조립·복구 역할 분리 인터페이스, 같은 Astra high·공유 이력·전역 예산, 과거 경험 검색 OFF다. 이번에 실제 발생한 모델 판단은 모두 조립 역할이다.

1. Astra는 Python 표면 후보 `1:r1:g65`를 선택했다. 복사 장면에서 파지와 설치를 모두 확인한 뒤 본 장면에서 실제 접촉·마찰로 집었다.
2. 실제 들기 관측을 받은 Astra가 `insert`를 제안했다. 본 장면에서 원래 CAD 목표에 설치·해제·후퇴한 뒤 1초 관찰을 통과했다.
3. Astra는 두 번째 후보 `2:r3:g114`와 `limited_open_then_retreat`를 제안했다. 이미 설치된 이웃과의 해제 간섭을 줄이려는 이유를 응답에 명시했다. 호스트가 임의로 그 계획을 모델 판단처럼 붙이지 않았다.
4. 두 번째는 복사 장면에서 집기·운반·설치·제한 개방·후퇴까지 진행했으나 마지막 관찰 중 총 시간 한도가 끝났다. 본 장면의 두 번째 부품은 공급 위치에 남았다.

두 파지 좌표는 Python의 실제 메시 후보이며 Astra가 선택했다. 직접 pose 생성이나 새 제어 코드 생성이 있었던 것으로 주장하지 않는다. IK·경로·서보 제어·성공 판정은 기존 Python/MuJoCo 실행기가 맡았다.

## 발견한 문제와 수정

### 1. 첫 요청이 입력 토큰 한도에 걸림

첫 시도 `8cc38de28de24974ab76285ab2a4ce8c-53d2de07`은 입력 계수 12,047토큰으로 기존 요청당 8,000 한도에 걸려 모델 생성 0회·설치 0/2·비용 $0으로 종료됐다. 후보 공통 정보 중복을 줄이고 빠져 있던 대체 자세 정보를 전달하도록 수정했다. 요청당 상한은 24,000, 회차 총 토큰/생성/비용 상한은 유지했다. 상세 원인·복원 검사는 [STEP 52](STEP_52_ASTRA_INPUT_SIZE.md)에 있다.

재실행의 실제 첫 입력은 **7,267토큰**, 약 **39.7% 감소**했다. 18개 후보와 검사 상태·실패 근거를 보존했으며 실제 형상·물리 수치를 바꾸지 않았다.

### 2. 안정성 관찰 시간 초과를 물리 실패로 감쌈

원 실행의 두 번째 부품 관찰은 시뮬레이션 183.556–183.612초, **0.056초·29회**였다. 기록된 기준 위반은 없고 원인은 `TimeoutError: deadline:physics_step`이었다. 그러나 `finish_release`가 모든 미통과 관찰을 `PLACEMENT_NOT_CONFIRMED`로 감싸 진단에 `measured_violation`이 붙었다. 최종 회차 상태는 다음 루프의 deadline으로 멈췄지만 사건의 원인 분류는 부정확했다.

수정 사항:

- `verification.py`: 중단 원인의 예외 종류·메시지를 완료 관찰 자료에 구조화해 보존.
- `failure_diagnosis.py`: 시간 초과·취소·미관측과 실제 측정된 위반을 구별. 과거 감싸진 로그도 원본을 바꾸지 않고 별도 진단 가능.
- `skills.py`: 시간 초과는 `TimeoutError`로 전달하고 사전검사 설치 가능성을 `unknown`으로 유지. 실제 접촉/완료 기준 위반은 실패로 유지.
- `execution.py`: 복사 검사에서 반환된 시간 초과·취소도 회차를 종료하며 추가 모델 판단을 요청하지 않음.
- `tests/test_v2_completion_stop.py`: 시간 초과, 취소, 과거 로그, 누락 측정, 중단 전 실제 위반, 완료된 실패, 정착 중 접촉을 검사.

**기존 회차 로그를 새 분류로 덮어쓰지 않았다.** 해당 run의 bundle에는 당시 코드와 원래 실패가 그대로 있다. 후속 코드는 별도 검사했고 최신 전체 Astra 회차를 다시 실행한 것은 아니다.
