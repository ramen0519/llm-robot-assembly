## 1. 목표와 기존 프로젝트의 역할

졸프의 목표는 **제품 수준의 계획을 실제 로봇 조립 동작으로 구체화하고, 관측된 실패에서 복구하며, 검증된 작업 경험을 재사용하는 것**이다.

- 기존 분해 플래너는 외부 계획 제공 모듈로 활용한다. 부품 순서·방향·조립체 자세·지지 조건과 검증 근거를 받는다.
- 졸프는 파지·접근·정렬·삽입·해제·후퇴, 실행 결과 판정, 실패 복구에 집중한다.
- 최종 목표는 약 10개 제품 부품의 조립과 실물 시연이다. 3·6부품은 중간 개발 단계다.
- UR3e + 2F-85 시뮬레이션과 단일 팔을 사용하며, 기존 제품 계획 에이전트에 조립 실행·실패 복구 에이전트를 연결한다. 실제 UR3/UR3e 기종과 센서·제어 기능은 실물 연동 전에 확인한다.
- 멀티에이전트를 기본 제품 구조로 구현하고 단일 조립 제어 정책은 비교군으로 유지한다. 파인튜닝과 런타임 임의 Python 생성은 이번 핵심 범위에 넣지 않는다.
- 기존 플래너 내부 모델 호출은 별도 서브시스템으로 기록한다. 외부 3역할과 내부 모델 수를 구분하고, 에이전트 수는 평가 범위를 명시한다.

기존 플래너가 20~30%라는 이전 설명은 권장 기능 배분이며 코드량·공수·독창성을 측정한 수치가 아니다. 발표에서는 재사용한 기능과 새로 구현·평가한 기능으로 구분한다.

## 2. 현재 출발점

현재 실제로 확인한 내용은 다음과 같다.

- 작업대·UR3e·2F-85, Mink IK, 물리 집기·운반·삽입·해제와 결과 검사.
- 저장된 분해 결과를 검증해 조립 후보로 가져오는 어댑터. 로봇 실행 보장은 별도.
- 10부품 사각 프레임 CAD와 기둥·슬리브·덮개의 연속 물리 조립. 고정 바닥판 제외 로봇 설치 9개.
- 측정한 정렬 실패를 현재 상태에서 재관측·재정렬해 복구. 최대 1회, 지원 범위 밖은 중단.
- 정책 계약과 LangGraph의 조립/복구 인계·단일 비교 기반. 기본은 규칙 정책이며 단일 API 연결부·사용량 기록을 추가했다. 첫 기둥에서 단일 Luna API 정책을 검증했다. [고정 파지](STEP_21E_FIRST_LIVE_LUNA.md)와 [모델 제안 파지](STEP_21F_PROPOSED_POST_GRASP.md)의 기록을 나눠 보관한다.
- 시뮬레이션 경험 저장·조건 일치 검색·정책 문맥 전달. 기록된 복구 순서의 JSON 후보를 새 물리 실행으로 재검증하고 해당 조건에서만 등록.
- 기존 RRT-Connect를 재사용한 빈 그리퍼·상자 운반 시험, 첫 기둥의 선택형 우회→삽입 및 정렬 복구, 두 기둥 연속 조립의 기존 부품 보존·빈 그리퍼 접근 우회 연결, 6회 규칙 정책 평가 기준선.

21N에서 실제 Luna의 수치 파지와 전체 연속 설치를 확인했다. 외부 전체 순서의 물리 실행, 새로운 복구 전략 생성과 비교 평가, 실물은 별도다. 23G에서 10부품 전체의 허용된 접근·운반 구간에 자동 우회를 연결했다. 정책이 선택하는 운반 재계획은 21C의 첫 결합에서 23H의 두 기둥·전체 한도로 확장했으며, 등록 절차는 기존 첫 기둥의 한 오정렬 사례에 한정된다. STEP별 보고서와 실행 근거는 [현재 진행 보고서](CURRENT_STATUS.md)를 따른다.

기존 분해 플래너에는 실제 계획·ASAP/RedMax 검증 성공 사례와 실패 사례가 함께 있다. 최근 복구 개선판의 실제 효과는 미검증이다. 처음에는 성공 기록이 있는 버전·설정·입력을 고정하고 현재 환경에서 재현한다. 최신 파일이라는 이유만으로 검증 완료 버전으로 취급하지 않는다.

## 3. 입력과 모듈 경계

입력은 OBJ 하나가 아니라 다음 정보를 가진 작업 묶음이다.

| 입력 | 용도 |
|---|---|
| 부품별 CAD, 부품 ID, 단위, 완성 조립체에서의 각 부품 자세 | 형상과 최종 목표 정의 |
| 초기 트레이 배치, 로봇·작업대·지그 설정 | 현재 실행 조건 |
| 결합 목표와 성공 허용치 | 삽입 깊이·상대 자세·지지·안정 상태 판정 |
| 부품 형상·자세, 그리퍼 치수와 허용 접근 조건 | 실행 에이전트가 부품 좌표계에서 파지를 제안할 근거 |
| 기존 플래너의 결과·버전·검증 근거 | 제품 수준 계획 후보 제공 |

첫 기둥에서는 모델이 부품 중심 기준 TCP 위치 세 값(mm)과 수직축 둘레의 그리퍼 닫힘 각도(도)를 직접 제안한다. 모델에 전달하는 정보는 부품·손가락·소켓 치수와 현재 자세다. 장면의 독립 복사본에서 집기부터 삽입·해제까지 검사한다. 거절하면 발생 단계, 접촉 또는 측정 오차를 모델에 돌려주고 재관측 후 새 수치를 받는다. 최대 세 번 안에 통과하면 원래 장면에서 같은 제안으로 집고 삽입한 뒤 별도로 검증한다. 첫 기둥은 위에서 접근한다. 고정 파지 비교군과 기존 10부품 규칙 실행은 별도 조건으로 기록한다.

기둥 배치 변경에 이어 [첫 슬리브](STEP_21G_PROPOSED_SLEEVE_GRASP.md)의 수치 파지와 관통을 별도 장면에서 검증했다. [21I](STEP_21I_POST_SLEEVE_EPISODE.md)에서는 빈 바닥판에서 두 동작을 연속 실행한다. [21J](STEP_21J_COVER_GRASP.md)에서는 넓은 덮개의 파지와 네 구멍 동시 결합을 개별 시험한다. 부품별로 정답 파지점을 추가하지 않고 형상과 주변 공간을 입력하는 방식을 확장한다. 처음 보는 조립품에 대한 주장은 개발에 사용하지 않은 조립품에서 고정 파지 방식과 같은 조건으로 비교한 뒤 판단한다.

| 모듈 | 책임 |
|---|---|
| TaskSpec / Workcell 설정 | 부품·목표·장비·허용 동작 정의 |
| DisassemblyPlannerAdapter | 기존 CLI/결과 파일을 호출·읽고 버전·상태·근거 보존 |
| AssemblyCandidateBuilder | 분해 순서·변환을 조립 후보로 변환하고 전제조건 명시 |
| 조립 실행 에이전트 | 현재 상태·조립 후보·경험을 보고 스킬을 선택하고 파지 위치·방향을 제안하거나 수정 |
| 실패 복구 에이전트 | 최신 관측·FailureReport에 따른 복구·재관측·종료 제안 |
| LangGraph runner | 일반 코드로 상태·인계·예산 관리; 물리 실행 직렬화 |
| SkillExecutor | observe, approach, pick, align, insert, release, retreat 실행 |
| MotionBackend | IK, 경로 후보, 충돌·관절 제한, 궤적 제어 |
| EnvironmentAdapter | MuJoCo / 실물 관측·실행·취소·상태 조회 |
| Verifier / FailureReport | 측정에 따른 성공·실패·미확인 판정 |
| ExperienceStore / Logger | 실행 근거, 적용 조건, 스킬 버전, 비용·시간 기록 |

기존 플래너의 소스·연구 기록을 졸프 저장소에 통째로 복사하지 않는다. 별도 프로세스와 설정 경로로 연결하고 입력·출력 계약을 고정한다. 공개 예제나 배포 가능한 최소 결과만 출처·라이선스 확인 후 포함한다. 연구실 비공개 자료·실험 로그·키는 Git에 넣지 않는다.

## 3.1 확정된 멀티에이전트 구성

2026-10-31 후속 사용자 결정으로 멀티에이전트를 기본 구조로 채택했다. 아래 구성은 목표 설계다. 현재 조립/복구의 규칙 정책 인계만 구현했으며 실제 LLM 에이전트는 미연결이다. 먼저 단일 LLM 정책을 검증하고 같은 계약의 역할 분리로 확장한다.

| 역할 | 목표·입력 | 출력·호출 시점 |
|---|---|---|
| 제품 계획 에이전트 (기존 분해 시스템) | CAD·목표·지원 가능한 제약을 받아 부품 수준 계획 탐색 | 분해 계획·가정·검증 근거. 최초 계획 또는 순서 재검토가 필요한 경우 호출 |
| 조립 실행 에이전트 | 조립 후보·현재 관측·형상·관련 경험으로 다음 작업과 파지 수치 결정 | 실행 가능한 스킬 제안 또는 재관측/중단 요청 |
| 실패 복구 에이전트 | FailureReport·최신 관측·실패 이력·허용 복구 절차를 받아 대응 판단 | 관측 추가, 대체 파지·접근·정렬·복구 제안, 제품 계획 재검토 요청 또는 종료 |

분해 결과를 조립 후보로 바꾸는 기능은 일반 코드다. LangGraph runner도 분기·상태·예산·인계 관리를 맡는 일반 코드이며 별도 LLM 관리자 에이전트를 추가하지 않는다. 에이전트별 모델은 설정으로 분리하지만 최초 구조 비교에는 동일 모델을 사용한다.

조립 실행과 실패 복구는 역할별 지시문·문맥을 갖되 공통 관측과 검증 이력에 접근한다. 각 제안은 task/part ID, observation revision, 허용된 skill ID와 파라미터, 관측 근거 참조를 포함한다. 원인 가설을 측정 사실로 바꾸지 않는다.

정상 단계는 조립 실행 에이전트가 담당한다. 계획 거부·실행 실패 시 runner가 먼저 정지/상태를 확인하고 필요한 관측을 갱신한 뒤 복구 에이전트로 인계한다. 복구 제안은 공통 검증기·실행기를 통과하고 후조건을 만족하면 조립 실행으로 돌아온다. 복구 한도 초과·불확실한 상태는 명시적으로 종료한다.

로봇에 명령을 제출하는 곳은 SkillExecutor 하나다. 두 에이전트가 같은 MuJoCo 장면이나 실물 팔에 동시에 명령하지 않는다. 오래된 관측을 근거로 한 제안은 거부하고, 명령 수행 여부가 불명확하면 재전송하지 않는다.

에이전트 수는 평가 범위를 명시한다. 기존 분해 에이전트를 실시간 호출하면 외부 기능 역할 기준으로 제품 계획·조립 실행·실패 복구의 3역할이다. 저장된 분해 결과만 읽는 시험에서는 조립·복구의 2개 에이전트가 동작한다. 기존 분해 시스템 내부의 Luna/Sol 모델 수를 그대로 에이전트 수로 세지 않는다.

단일 에이전트 비교군은 하나의 정책이 조립과 복구를 모두 판단하도록 두고 같은 도구·관측·실행기·검증기를 사용한다. 기존 분해 모듈 또는 그 출력은 양쪽에서 고정한다. 이에 따라 비교 명칭은 “공통 제품 계획 모듈 아래 조립 제어의 단일/다중 에이전트 비교”로 적는다.

## 4. 분해 계획을 조립에 활용하는 정확한 범위

분해 순서의 역순은 조립 후보이지 실행 보증이 아니다.

1. 완성 CAD의 목표 부품 자세와 기준 좌표계를 확보한다.
2. 분해 계획의 순서·방향·자세·지지 조건과 실제 검증 여부를 읽는다.
3. 역순을 조립 순서 후보로 만들고 각 단계의 필요 지지·접근 조건을 명시한다.
4. 로봇 파지·접근·삽입·해제·후퇴 동작을 새로 구성한다.
5. 각 중간 조립 상태의 안정성과 로봇 전체의 실행 가능성을 MuJoCo에서 검증한다.

힘 방향을 TCP 이동 벡터로 그대로 사용하지 않는다. 좌표 변환·공차·파지 변환을 확인한다. 분해에서 가정한 부품 고정과 조립체 회전은 실제 지그·재파지·자세 전환으로 구현 가능한지 확인한다. 접착·소성변형·체결처럼 단순 역재생이 성립하지 않는 작업은 별도 모델·스킬 없이는 지원하지 않는다.

초기에는 저장된 성공 계획으로 입출력 연결을 확인한다. 이는 새 계획 생성 성공이 아니다. 이후 기존 플래너를 실제 호출해 같은 계약으로 결과를 읽는다. 실패·부분 결과는 전체 성공 계획으로 포장하지 않는다.

## 5. 실행 흐름과 두 루프

시뮬레이션 모드:

작업 읽기 → 조립 후보 준비 → 현재 상태 관측 → 경험 검색 → 다음 스킬 선택 → 전제조건·경로 검사 → 물리 실행 → 결과 판정 → 다음 단계 또는 복구 → 전체 목표 판정·기록.

처음에는 LLM 없이 고정 정책으로 그래프 연결을 확인한다. 이후 조립 실행 정책과 실패 복구 정책을 각각 연결하고 인계를 검증한다. 단일 정책 비교군도 같은 입출력 계약을 사용한다. 정상 단계마다 모든 에이전트를 호출하거나 매 물리 시간 단계마다 LLM을 호출하지 않는다.

- 빠른 루프: 스킬·제어기가 관절·접촉·파지 상태를 검사하고 동작을 중단한다.
- 작업 루프: 조립 실행 에이전트가 정상 작업을 선택하고, 실패 시 복구 에이전트가 FailureReport와 새 관측으로 대안을 제안한다. 공통 검증·실행 후 성공하면 조립 실행으로 복귀한다.
- 순서 자체의 문제는 기존 플래너가 지원하는 입력으로 변환할 수 있을 때만 재계획을 요청한다. 지원되지 않는 제약 전달을 구현된 것처럼 취급하지 않는다.
- 복구 한도·시간·API 예산을 소진하거나 관측이 부족하면 명시적으로 종료한다.

sim_only에서는 실제 MuJoCo 실행과 결과 판정을 한 번의 검증으로 센다. 같은 실행을 사전 검증과 본 실행이라는 이름으로 중복 집계하지 않는다.

sim_then_real에서는 현재 실물 상태를 반영한 시뮬레이션 검증 → 실행 직전 실물 상태 재확인 → 한 단계 실물 실행 → 실물 결과 판정으로 진행한다. 실물 실패 후에는 재관측하고 변경된 상태에서 복구 계획을 다시 검증한다. 시뮬레이션 통과는 실물 성공 보장이 아니다.

## 6. 실패 복구와 스킬·메모리

다음 표는 전체 개발 대상이다. 현재는 하강 전 정렬 실패의 재관측·수직 후퇴·재정렬 1종만 검증했다. 기존 FailureReport 분류를 재사용·확장한다.

| 실패 | 관측 근거 | 복구 후보 |
|---|---|---|
| 파지 미확인 | 검증 리프트 후 부품 미상승·상대 자세 불안정 | 부품과 빈 그리퍼 상태 재확인 후 다른 파지 후보 |
| 계획 중 간섭 / IK 수렴 실패 | 충돌 쌍, 목표·잔차·관절 상태 | 접근 자세·waypoint·IK 초기 후보 변경 후 재검증 |
| 정렬 오차 / 삽입 미완료 | 상대 자세·삽입 깊이·진행량 미달 | 파지·접촉 상태와 후퇴 경로 확인 후 후퇴·재정렬 |
| 운반 중 부품 이탈 | 그리퍼-부품 상대 자세 변화·낙하 | 멈춤·재관측; 안정된 위치에서 가능한 경우만 재파지 |
| 관측 부족 / 실행 여부 불명 | 센서 품질·명령 완료 확인 부족 | 재관측·상태 조회 또는 개입 필요로 종료 |

실행 중 예상 밖 접촉은 계획 단계의 간섭과 구분한다. 확인 없이 자동 후퇴하거나 같은 명령을 재전송하지 않는다. LLM은 속도·힘·작업영역 제한을 해제하지 못한다. 힘 센서가 없는 장비에서 힘 관측을 가정하지 않는다.

성공 여부는 수치 검사기가 판정한다. 실패 원인 설명은 관측 사실과 가설로 나눠 저장한다. 장면 reset으로 복구 성공을 만들지 않는다. 이미 조립된 부품을 보존한 상태에서 후조건을 만족해야 복구 성공이다.

- 기본 스킬: 개발자가 검증한 동작 코드.
- 경험: 성공·실패 시 조건과 관측, 선택한 대안, 실제 결과.
- 축적 절차: 검증된 기본 스킬의 조합·파라미터·적용 조건. 첫 버전은 온라인 임의 코드 생성을 하지 않는다.
- 기존 플래너의 분해 경험과 졸프의 로봇 파지·삽입 경험을 별도 출처·이름 공간으로 관리한다.
- 후보 / sim 검증 / real 검증 상태와 적용 범위를 분리한다. 한 번 성공한 절차를 범용 스킬로 승격하지 않는다.
- 현재 초기 검색은 OneDrive 밖의 닫힌 JSON 기록과 명시적 조건 지문 필터를 사용한다. 필요 시 SQLite로 전환한다. 로봇·그리퍼·부품군·지그·좌표 보정·스킬 버전으로 호환성을 확인한다.
- live DB는 OneDrive 밖 로컬 경로에 두고 Git에서 제외한다. 실패 기록도 보존한다.

## 7. 작은 단위 개발 순서

각 행은 독립적인 구현·설명·검증 단위다. 다음 단계로 넘어가기 전에 사용자에게 코드와 결과를 설명한다.

| 단계 | 구현 단위 | 통과 기준 |
|---|---|---|
| 15 (완료) | 기존 observe/pick/place를 LangGraph에 연결, LLM 없음 | 기존 물리 성공 유지, 단계 상태·실패 종료가 그래프에 전달 |
| 16 (저장 결과 완료) | 분해 결과 어댑터와 조립 후보 계약 | 저장된 실제 결과에서 ID·단위·좌표·순서·근거를 읽고 불완전 입력 거부; 역순은 후보로 표시 |
| 17 (개발 후보 완료) | 최종 제품 후보 선정, CAD·지그·첫 결합 시험 장면 | 약 10부품 BOM, 파지 공간·지지·제작 조건 확인; 첫 단일 결합은 2~3부품으로 재현 |
| 18 (첫 기둥 완료) | 한 부품의 align/insert/release/retreat | 순간이동·강제 부착 없이 결합, 해제·후퇴 후 깊이·상대 자세·안정성 통과 |
| 19 (첫 결합 범위 완료) | 파지·정렬·삽입 실패 검출 | 사전 선정한 원인/초기 조건으로 실제 실패 발생, 측정 근거와 코드 일치; 복구는 아직 불필요 |
| 20 (오정렬 1종 완료) | 결정론적 복구 기본 동작 | reset 없이 현재 실패 상태에서 다른 파지 또는 후퇴·재정렬로 성공하거나 명시적 종료 |
| 21 (단일 API 연결부 완료, 라이브 검증 대기) | 멀티에이전트 정책을 21a 조립 실행 → 21b 실패 복구 → 21c 인계·단일 비교군으로 분할 | 역할별 구조화 출력·공통 검증, 실패 때 복구 호출, 관측 revision 확인, 동시 로봇 명령 방지·전체 예산 제한 |
| 22 (저장/검색·제한된 절차 등록 완료) | 로봇 실행 경험 저장·검색과 기록된 절차의 재검증 | 적용 조건과 성공/실패 보존, 호환 경험만 검색; 효과 입증과 검색 성공 구분 |
| 23 (10부품 물리 성공, 외부 계획 후속) | 3→6→약 10부품 전체 sim + 외부 플래너 실제 연동 | 중간 상태·전체 목표 판정, 이전 조립 보존, 등록된 실패·복구 시험, 출처·비용 로그 |
| 24 (이번 범위 제외) | 실물 환경 adapter·보정·단일 결합, 이후 전체 조립 | 실제 기종 확인, TCP·카메라/지그 보정, sim 검증 후 실물 관측으로 판정 |
| 25 (규칙 기준선 완료) | 반복 평가·시연·보고서 | 공통 제품 계획 아래 규칙/단일/다중 조립 제어 및 경험·스킬·모델 비교, 성공·복구·개입·시간·비용 공개 |

15단계부터 LangGraph를 사용하며 실제 단일 Luna 판단은 21N까지 전체 조립으로 검증했다. 이번 연속 작업은 API 제공자·모델·예산 답변 전까지 과금 없이 가능한 물리 검증·정책 계약·기록을 우선 진행했다. 단일 LLM 검증에 이어 역할 분리와 비교한다. 16~17에서 기존 성공 예제 CAD가 실물 목표에 적합한지 확인하고, 적합하지 않으면 새 제품 CAD를 기존 플래너에 넣을 수 있는지 확인한다. 현재 시뮬레이션 개발 CAD는 10부품 사각 프레임이며 기어박스는 과거 후보다. 최종 제출 형상·실물 제작 조건은 별도 확정한다.

최종 제품은 한 팔과 지그로 지지할 수 있고, 파지·접근 공간이 있으며, 관측 가능한 완료 조건을 가진 약 10부품을 목표로 선정한다. 제품 부품 수와 로봇이 실제 설치하는 부품 수를 구분한다. 최종 목표를 단순 상자 배치로 대체하지 않는다.

## 8. 일정과 평가

기존 4주 목표를 이번 문서 작성일로부터 새로 시작하는 것으로 해석하지 않는다. 정확한 최종 제출일은 미확정이다. 이전 실물 포함 시간 배분은 현재 시뮬레이션 전용 요청에 적용하지 않는다. 다음 작업은 LLM 연결·선택 대안·외부 계획 연결·평가를 우선한다. 예상보다 삽입·실물 보정에 시간이 들면 새 스킬 생성·자유 배치 비전·추가 제품 일반화를 확장하지 않고 핵심 결합과 복구 검증을 우선한다.

모든 학습·평가를 끝내야 실물로 넘어가는 것은 아니다. 23의 제한된 sim v1 통과 뒤 실물 연결을 시작하고, 최종 비교는 25에서 수행한다. 장비 기종·예약·치수 확인은 앞서 할 수 있지만 실제 로봇 이동은 별도 작업이다.

| 조건 | 구성 | 비교 목적 |
|---|---|---|
| A | 고정된 실행·복구 규칙 + 공통 기본 스킬 | 결정론적 기준선 |
| B | 조립·복구를 함께 판단하는 단일 에이전트, 장기 경험 없음 | A/B로 LLM 판단 효과 |
| C | 조립 실행·실패 복구 멀티에이전트, 장기 경험 없음 | B/C로 역할 분리 효과 |
| D | C + 동결된 로봇 실행 경험 | C/D로 경험 검색 효과 |
| E | D + 검증된 축적 복구 절차 | D/E로 절차 재사용 효과 |

기본 제품 구성은 멀티에이전트다. 비교군 B는 구조 효과를 확인하기 위한 단일 정책으로 유지한다. 모든 에이전트 조건은 현재 episode의 관측·실패 이력을 사용할 수 있다. 기본 이동·파지·삽입 도구는 전 조건에 제공하고, E는 그 기본 동작으로도 구성할 수 있는 절차를 재사용하게 한다. 절차 한 번에 포함된 모든 물리 동작·시간·실패·비용을 센다.

B/C 구조 비교는 같은 모델·조립 후보·CAD·초기 상태·관측·도구·장기 지식 조건과 동일한 시스템 전체 예산/복구 한도로 수행한다. 에이전트마다 전체 예산을 따로 부여하지 않는다. 내부 교환·요약·재시도도 비용에 포함한다. 제품 계획 모듈 또는 그 출력을 고정하고, 실시간 호출 비용과 저장 결과를 읽는 평가를 구분한다. 모델 변경과 혼합 모델 routing은 구조 비교와 별도 축으로 평가하며, 멀티 구조가 자동으로 비용을 줄인다고 가정하지 않는다.

D/E에서 경험과 스킬은 개발 자료로 준비한 버전을 동결한다. 같은 시험 결과가 다음 조건에 유입되지 않게 한다. 경험 정보를 받은 규칙 선택기 없이 D/E와 A의 차이를 LLM 단독 효과로 주장하지 않는다. 전체 조립 시험과 동일하게 재현한 실패 조건에서 시작하는 복구 시험을 구분한다. 개발·평가 사례와 반복 수는 결과를 보기 전에 정하고, 전체 조합을 곱한 대규모 실험 대신 구조·경험·스킬·모델의 비교를 단계적으로 수행한다. 실물 반복 수와 최종 실험 예산은 장비 시간·검증된 동작 범위에 맞춰 별도로 확정한다.

전체 조립 성공률, 실패 후 복구 성공률(복구 시도·미시도·관측 불충분 포함 보고), 사람 개입 수, 재계획·재시도 수, 시간·API 비용을 기록한다. 조립 실행·실패 복구·기존 플래너의 비용을 각각 분리하고 총비용도 제공한다. sim/real 결과, 인식 기반 판정/평가용 정답 판정을 구분한다.

## 9. 이번 연속 구현의 완료 범위와 다음 작업

10부품 물리 실행은 23C단계에서 확인했다. 첫 정렬 오류의 같은 episode 복구, 기존 부품 보존, JSONL/CSV 기록도 포함한다. 코드와 단계 보고서는 `codex/simulation-progress` 브랜치에 커밋한다. 외부 분해 프로젝트는 읽기와 로더 확인만 했고 수정하지 않았다.

다음은 실제 LLM 정책 연결과 검증된 대안 확대다. 정상 행동 하나가 이미 정해진 장면에 LLM 호출만 추가해서 판단 성능 향상이라고 주장하지 않는다. 단일/역할 분리, 메모리/절차, 모델 변화는 조건을 분리해 비교한다. 실제 API 예산이 정해지기 전에는 유료 호출하지 않는다. 최신 실제 결과와 한계는 [CURRENT_STATUS.md](CURRENT_STATUS.md)를 따른다.
