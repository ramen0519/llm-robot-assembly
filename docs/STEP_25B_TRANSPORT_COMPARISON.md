# 25B: 같은 조건의 직접 경로와 대체 경로 실행 비교

작성: 2026-11-01. 전체 조립 통합 실행과 별개로, 완료한 [23F](STEP_23F_COMPOUND_TRANSPORT.md)의 슬리브 로그를 비교했다.

## 목적과 사용법

조립 성공률을 비교하려면 부품이나 장애물 배치가 달라진 실행을 같은 조건인 것처럼 섞으면 안 된다. `scripts/compare_transport_runs.py`는 실행 결과 두 개를 읽고, 기록된 설정에서 **transport_strategy 한 항목만 다를 때** 비교 보고서를 만든다. 새 시뮬레이션·API·로봇 명령은 실행하지 않는다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/compare_transport_runs.py --direct-run runs/component_probes/20261101T080854_643987Z_fe306d86 --fallback-run runs/component_probes/20261101T080656_722545Z_35a70fa7
```

실제 비교 결과: `runs/step25_transport/20261101T081611_585447Z_ac84ee8b`. `summary.json`과 사람이 읽는 `REPORT.md`를 생성했다.

| 전략 | 실제 전체 결과 | 로봇 설치 / 목표 | 시뮬레이션 시간 | 종료 실패 |
|---|---|---:|---:|---|
| 직접 경로만 | 실패 | 0 / 1 | 53.478초 | PLANNED_CONTACT |
| 직접 경로 거부 후 대체 경로 검사 | 성공 | 1 / 1 | 93.432초 | 없음 |

같은 슬리브·준비물·장애물에서 직접 TCP 경로는 사전 충돌로 중단했다. 대체 경로를 허용한 실행은 검사된 관절 보간 경로로 운반 후 삽입했다. 이 사례에서는 RRT 탐색을 실행하지 않았다. 사전 조립된 바닥판·기둥·첫 슬리브는 로봇 설치 수에 포함하지 않는다.

## 집계가 확인하는 것

- simulation 환경, 규칙 정책, 실제 API 호출 0회인 기록만 받는다. 유료 모델 평가를 조용히 0원으로 집계하지 않는다.
- 부품 registry, 초기 준비물, 목표 설치 수, simulator 버전과 기록된 소스 지문을 포함해 설정 전체가 같은지 확인한다. 운반 전략만 비교 변수다.
- 완료한 부품마다 해제·위치·방향·깊이·정지·침투량·지지의 8가지 판정과 최종 위치 오차가 있어야 한다.
- 전체 성공, 부분 설치, 초기 사전 조립 부품을 구분한다. 진행 중인 실행이나 물리 표본이 없는 실행은 집계하지 않는다.
- 성공 폴더에 남아 있는 사전 충돌 보고서를 최종 실패로 잘못 세지 않는다. 실제 선택된 계획 방법의 이름도 그대로 유지한다.
- 설정과 결과 JSON의 SHA-256을 남겨 어떤 파일을 비교했는지 추적한다.

저장된 설정·판정 기록을 검사하는 집계기다. 물리 실행을 재현하거나 파일의 진위를 인증하는 프로그램은 아니다. 입력 실행의 실제 물리 검증 근거는 23F를 따른다. 기록된 소스 지문 외의 모든 운영체제·하드웨어 조건까지 같다고 증명하지 않는다.

## 해석의 제한

실패한 실행은 일찍 멈췄으므로 시뮬레이션 시간이 짧다고 효율이 더 좋다고 할 수 없다. 실제 PC 실행 시간도 다른 물리 시험과 CPU를 공유한 개발 기록이므로 속도 우열 비교에 쓰지 않는다.

직접 경로의 모든 내부 계획 횟수는 기존 로그에 없으므로 누락을 0회 계산으로 취급하지 않는다. API 호출은 두 실행 모두 0회다. 고정 개발 사례 한 쌍이며 일반 성공률, LLM의 판단 효과, 멀티에이전트 우위, 스킬 학습 효과를 입증하지 않는다.

## 검사

```powershell
uv run --locked python -m unittest discover -s tests -p test_transport_comparison.py -v
```

4개 검사 PASS, 0.101초. 로그 `.scratch/step25b_tests.log`.

설정·소스가 다른 쌍 거부, 성공 근거가 빠진 결과 거부, 준비물의 설치 수 부풀리기 거부, API 기록 거부, 부분 설치와 전체 성공 분리, 실제 계획 방법 이름 유지 등을 확인했다. 이 검사는 명시적인 합성 로그 계약 검사이며 실제 조립 성공 횟수로 세지 않는다. 별도로 위의 실제 슬리브 실행 두 개를 집계했다.

전체 프레임 형식도 지원하지만, 이 보고서 시점에는 전체 프레임의 비교 실행이 진행 중이다. 결과가 확정되면 별도 보고서와 실행 폴더로 추가한다.
