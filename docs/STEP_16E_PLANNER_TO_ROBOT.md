# 16E단계: 검증된 분해 후보를 실제 로봇 시뮬레이션에 연결하기

작성: 2026-11-01. API·실물 명령 0회. 먼저 바닥판과 두 기둥의 작은 범위로 연결을 검증했다.

## 데이터가 움직임으로 이어지는 과정

1. `run_asap_native.py`가 생성한 `assembly_candidate.json`을 받는다.
2. `planner_candidate_input.py`가 원본 네이티브 보고서와 입력 파일 지문, 완전한 분해 순서, 역순의 로봇 선행조건을 다시 확인한다.
3. 현재 제품 CAD를 임시 폴더에 재생성해 원본 OBJ와 비교한다. 같은 제품 이름이나 크기 필드만 믿지 않는다. 임시 파일은 확인한 `runs` 경계 안에 만들고 닫힐 때 정리한다.
4. CAD 기준점과 로봇 부품 기준점의 변환을 현재 결합 목표와 대조한다. 부품 수·좌표·형상이 다르면 모터 동작 전에 중단한다.
5. 통과한 순서로 `run_frame_assembly.py`의 직렬 실행 순서만 정한다. 실제 파지·IK·운반·삽입과 완료 검사는 기존 실행기가 수행한다.

분해 후보는 로봇 성공 결과가 아니다. 실행 기록은 `planner_provenance`에 후보·원본 지문과 조건 출처를 저장하고, 성공한 실제 동작 순서는 `execution_order`에 따로 남긴다. 기존 설치 목록은 집합 성격의 정렬된 ID 목록이므로 시간 순서와 혼동하지 않는다.

## 실제 실행

```powershell
uv run --locked python scripts/run_frame_assembly.py --parts 3 --mode single --planner-candidate runs/asap_native/20261101T095751_655043Z_006a36d4/assembly_candidate.json --transport-strategy direct_then_rrt --snapshots
uv run --locked python -m unittest discover -s tests -p test_planner_candidate_input.py -v
```

입력은 16C에서 실제 ASAP/RedMax 분해 검사를 통과한 파일이다. 테스트용 가짜 성공 보고서를 물리 통합 실행에 사용하지 않았다.

실행: `runs/step23_frame/20261101T101741_839942Z_afe3e4d5`, **success**, 로봇 설치 **2/2**, `post_1 → post_2`, sim **172.558초**, API **0회**. 바닥판은 미리 고정한 지그 조건이며 로봇 설치 수에서 제외한다. 부품을 순간이동하거나 인위적으로 붙이지 않았다. 실제 접촉·마찰로 집고 설치했으며 각 부품의 위치·방향·지지·해제·속도·깊이 검사를 통과했다.

별도 로그 대조도 통과했다. 물리 측정 86,319행, 최대 시간 간격 2ms, 최대 최종 위치 오차 0.1221mm 미만, 먼저 설치한 기둥의 최대 위치 오차도 0.1221mm 미만이다. 정책 선택 6회, 재계획·정렬 복구 0회다. 이 실행이 기록한 소스 지문 13개는 감사 시점의 코드와 일치했다.

신규 계약 검사 **3개 PASS**, 1.050초. 합성 입력은 형식 검사에만 사용했다. 변경된 메시나 목표 좌표를 거부하고, 부품 수가 맞지 않는 경우 실제 샘플·설치 수 0에서 멈추는지 확인했다. 네이티브 성공과 로봇 성공을 같은 값으로 복사하지 않는다.

## 남은 범위

10부품 후보도 같은 입력 경계를 사용할 수 있지만, **이번 실제 연결 실행은 3부품**이다. 전체 10부품의 기존 순서 조립 시험과 외부 플래너가 고른 10부품 순서의 로봇 실행은 다른 시험이다. 후자는 이 기록으로 성공했다고 주장하지 않는다. 알려진 제품·결합 정보·파지 스킬을 쓰는 제한된 프로토타입이며, 임의 OBJ의 결합법을 자동 발견한 시스템은 아니다.
