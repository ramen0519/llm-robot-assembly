## 이번 단위의 목표

고정된 바닥판만 준비한 상태에서 기둥 4개, 슬리브 4개, 덮개 1개를 **같은 MuJoCo 장면**에서 차례로 설치한다. 바닥판까지 제품 총 10부품이며, 로봇이 집어 설치하는 부품은 9개다. 기둥·슬리브·덮개는 자유 물체이며 집기와 운반은 그리퍼의 접촉·마찰로 수행한다.

각 부품에서 Luna가 부품 기준 TCP 위치 X·Y·Z(mm)와 손가락 닫힘 방향(도)을 제안한다. MuJoCo 복사본에서 실행 가능성을 검사하고 실패 정보를 받으면 수정한다. 승인한 숫자와 본 실행에 전달한 숫자가 같은지 기록한다. 후보 검사용 복사본과 실제 조립 장면을 구분하며, 실제 장면의 모터 실행과 해제 후 관측을 성공 근거로 삼는다.

이번 순서는 사용자가 요청한 기둥 1~4 → 슬리브 1~4 → 덮개다. 이 순서의 발견이나 외부 분해 플래너 호출을 실험한 것은 아니다. 위에서 접근하는 조건은 고정하고, Luna가 그 조건 안의 네 파지 매개변수와 pick/insert/finish 또는 stop을 선택한다.

## 연결한 코드와 데이터 흐름

- scripts/run_frame_assembly.py의 --llm-config: 기존 전체 조립 실행기에 실제 단일 Luna 정책을 연결한다. 첫 기둥에서 만든 API 클라이언트와 비용 장부를 아홉 부품이 공유한다. 각 부품마다 예산을 새로 채우지 않는다.
- scripts/assembly_graph.py: 관측 → 파지 제안 → 복사본 물리 검사 → 수정 또는 본 실행 → 결과 확인 흐름을 기존 그대로 재사용한다. 부품별 파지 후보 상한은 3개다.
- scripts/frame_assembly_skills.py: 현재 설치한 부품 목록을 가지고 접근·집기·운반·삽입·해제·후퇴를 실행한다. 설치했던 부품의 위치·방향과 접촉을 움직이는 동안 검사한다.
- 이동은 Mink IK와 관절 제어로 수행한다. direct_then_rrt는 허용된 빈 그리퍼 접근·운반 구간에서 직선 계획이 막히면 기존 RRT-Connect 우회를 검사한다. 이는 모션 계층의 자동 우회이며, 별도 LLM 재계획 호출 수와 구분한다.
- 부품 경계마다 MuJoCo의 시간·관절·자유 부품·속도·제어 상태 등을 포함한 mjSTATE_INTEGRATION 지문을 비교한다. 앞 부품 끝 상태와 다음 부품 시작 상태가 다르면 중단한다.
- progress.json은 부품 설치 직후의 중간 기록이다. 전체 적분 상태 배열·모델 지문·MuJoCo 버전과 그래프 기록·남은 예산도 저장한다. restore_episode_data는 동일 모델에서 물리 상태를 복원하고 손상·모델 변경을 거부한다. 그래프나 API 비용 장부까지 이어 실행하는 자동 재개 기능은 아니다. 최종 성공/실패 판정은 result.json에 있다. graph_events.jsonl, llm_events.jsonl, 물리 trace CSV와 부품별 사진도 보관한다.

## 마지막 검사는 무엇을 뜻하나

아홉 번째 덮개의 해제·후퇴·안정 확인이 끝나면 다른 설치물의 위치와 방향을 다시 검사한다. 덮개 네 구멍의 위·아래 면에서 각 기둥 네 모서리가 안에 있는지, 네 슬리브 각각이 덮개를 실제 접촉력으로 받치는지 검사한다. 슬리브 네 개도 현재 장면에서 각각 기둥 관통을 재검사한다. 이 최종 검사 과정이 물리 상태를 바꾸지 않는지도 확인한다.
