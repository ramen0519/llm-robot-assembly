# STEP 57 · 설치 상태를 검증하고 남은 조립 이어가기

2026-11-26. 기존 코드를 reset하지 않고 `codex/general-mesh-v2`의 미커밋 작업 위에서 이어간다. 실물 명령·새 Astra 호출·E: 사용은 없다.

## 목적

첫 배터리 자동 실행에서 3, 4, 6번을 실제로 설치했지만 전체 30분 한도가 끝났다. 사용자가 요청한 대로, 시간 경과만으로 전체 개발 작업을 끝내지 않고 검증된 상태에서 나머지를 이어간다. 기존 결과의 상태는 `deadline` 그대로 보존한다.

## 이어가기 조건과 구현

`scripts/assembly_v2/resume.py`가 부모 실행의 보존 묶음 해시, 원본 목표·모델·저장 상태, 실제 주 장면 설치 이벤트를 대조한다. 부품이 목표 위치에 있다는 이유만으로 설치를 인정하지 않는다. 손에 들고 있거나, 후퇴가 끝나지 않았거나, 경질 접촉 위반이 있었던 상태는 자동으로 이어가지 않는다.

MuJoCo의 전체 적분 상태와 제어 참조를 복원하고 저장값과 정확히 같은지 검사한다. 이어 기존 설치 부품을 원래 완료 조건으로 다시 1초 정착·1초/501회 관찰한다. 이때 통과해야 남은 부품의 새 집기를 허용한다. 이는 목표 배치나 인위적 부착이 아니라 실제 저장된 장면을 이어가는 것이다.

`execution.py`의 같은 LangGraph 실행기를 사용하며, 완료된 부품만 작업 대기열에서 제외한다. 매 설치 후 빈 손 체크포인트도 남긴다. `artifacts.py`의 보고서와 감사에는 부모 실행·상태 출처·상속한 설치 목록이 포함된다. 영상은 새 회차에 실제로 진행한 상태만 담는다. 원래의 빈 바닥판부터 한 번에 수행한 회차나 실제 Astra 성공으로 표시하지 않는다.

`DevelopmentBudget`은 **API 없는 개발**의 전체 시간 제한만 제거한다. 취소, 개별 모션/IK/경로 검사 한도, 후보·재시도 한도와 모든 물리 기준은 유지한다. 유료 정책·연구 수집·평가에 이 옵션을 사용하면 거부한다. 제한 없음은 로그에서 `null`과 별도 모드로 표현한다.

## 발견한 문제와 수정

1. `battery_continuation01`: 로봇 동작 전 기본 메모리 경로의 지역 import 오류. 기존 CLI에서는 경로를 넘겨 가려져 있었다. 공통 설정 참조를 수정했다.
2. `battery_continuation02`: 전체 상태 복원과 3개 부품의 실제 연속 관찰 통과. 이어 무제한 시간을 JSON 숫자로 기록하면서 중단했다. 제한 없음 표현을 수정했다. 추가 설치는 없다.
3. `battery_continuation03`: 셀의 복사 집기를 시작했다. 기존 기하 검사에 좁은 위쪽 부위를 잡는 2mm/2.5mm 수정 후보가 있었지만, 개발 정책은 원래 후보 ID만 선택하고 있었다. 이를 수정하기 위해 복사 검사만 명시적으로 취소했다. 주 장면은 보존했다.
4. `policy.py`: 이미 생성된 전체 pose 대안을 개발 정책 선택지에 넣었다. 원래 후보와 생성 근거를 보존하며, 접근은 미검사로 표시한다. 실제 복사 집기·설치와 주 장면 검사는 그대로 필요하다. Astra의 자유 제안·선택 인터페이스는 바꾸지 않았다.
5. `battery_continuation04`: 수정한 후보를 실제로 검증하며 남은 조립 진행 중. 결과는 해당 폴더의 `result.json`, `events.jsonl`, `progress.json`을 기준으로 확인한다. 이 문서를 작성한 시점에 추가 설치 성공은 아직 확정하지 않았다.

관련 코드 검사 **176개 통과, 5.570초**. 상태 복원·실제 501회 관찰과 단위 검사를 구분한다. 최초 제한 환경의 라이브러리 읽기 권한 오류는 정상 프로젝트 권한으로 재검사해 해소했다.
