# 7단계: TCP의 위치와 방향 확인

목표는 기존 UR3e + 2F-85 모델에서 **집기 기준점의 위치와 방향을 읽고, 화면의 좌표축으로 확인하는 것**이다. 목표 위치로 이동하는 IK와 물체 파지는 이번 단계에 포함하지 않는다.

## TCP란?

TCP는 **Tool Center Point**, 즉 도구를 다룰 때 사용하는 기준점이다. 펜을 잡은 로봇이라면 펜촉, 집게라면 물체를 잡을 공간의 기준 위치를 선택할 수 있다. 반드시 도구의 무게중심이나 손목 회전 중심일 필요는 없다.

로봇에게 “이 위치로 가라”고 명령할 때는 어느 점이 그 위치에 도착해야 하는지 정해야 한다. 손목과 집게 끝은 떨어져 있으므로 둘을 혼동하면 도구의 실제 작업 위치가 어긋난다.

TCP 점에는 X·Y·Z축으로 이루어진 도구 좌표계도 붙인다. **위치**는 그 점이 어디에 있는지, **방향**은 도구가 어떻게 돌아가 있는지를 나타낸다. 같은 위치에서도 집게가 위를 보는지 아래를 보는지에 따라 가능한 작업이 달라진다. 위치와 방향을 함께 pose라고 부른다.

## 실행

기존 환경만 사용하며 새 패키지는 설치하지 않는다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/view_tcp.py
```

노란 TCP 점과 세 방향의 화살표를 표시한다. `Attachment`는 TCP와 구분하기 위한 손목 장착 기준점이다. 축 이름은 화살표 끝에 표시한다.

| 화면 색 | 의미 | 현재 모델에서의 의미 |
|---|---|---|
| 빨강 | TCP의 +X축 | Y·Z축에 직각인 나머지 도구 축 |
| 초록 | TCP의 +Y축 | 두 손가락 사이 폭을 재는 방향 |
| 파랑 | TCP의 +Z축 | 그리퍼 본체에서 손가락 끝을 향하는 방향 |

이번 뷰어는 `mj_step()`을 호출하지 않으므로 물리 시간이 진행하지 않는다. 마우스로 카메라를 돌려도 좌표계 정의가 바뀌는 것은 아니다. 확인이 끝나면 창을 닫는다. 자동 종료하거나 창 없이 숫자만 확인할 수도 있다.

```powershell
uv run --locked python scripts/view_tcp.py --seconds 5
uv run --locked python scripts/view_tcp.py --check
```

숫자 검사 성공 시 `TCP frame definition: PASS`가 출력된다. 이는 모델의 기준점·좌표 변환 검사 성공이며 실제 이동 성공을 의미하지 않는다.

## 어떤 점을 TCP로 사용했나?

원본 2F-85 모델에는 `pinch`라는 `site`가 있다. site는 질량이나 충돌을 만들지 않는 기준 위치·방향이다. 두 모델을 결합하면서 이름에 접두사가 붙어 `gripper_pinch`가 된다. 이번에는 이 기존 점을 **시뮬레이션의 명목 TCP**로 사용했다. 원본 모델 파일을 수정하거나 새 물리 부품을 추가하지 않았다. [MuJoCo site 공식 설명](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-site)

```xml
<site name="pinch" pos="0 0 0.145" ... />
```

여기서 `0 0 0.145`는 월드 좌표가 아니라 **부모인 그리퍼 본체 좌표계에서의 위치(m)**다. 그리퍼 본체에서 +Z 방향으로 145mm 떨어져 있다는 의미다.

손목의 `attachment_site`에서 TCP까지는 다음 오프셋이 쌓인다.

```text
손목 장착 기준 → 장착부: 7.0mm
장착부 → 그리퍼 본체:   3.8mm
그리퍼 본체 → TCP:    145.0mm
합계:                155.8mm
```

이 모델에서는 세 이동이 같은 Z축 방향에 놓이므로 합산할 수 있다. 일반적인 여러 좌표계의 오프셋은 방향을 맞추지 않고 단순히 더하면 안 된다.

또한 그리퍼 본체의 X·Y축은 장착 기준에 대해 Z축 주위로 -90도 회전되어 있다. 따라서 장착 기준점과 TCP는 **위치도 방향도 다르다**. 이것은 이 시뮬레이션 모델의 장착 관계이며, 실제 제조사 flange/tool0 또는 연구실 어댑터의 보정값과 동일하다고 가정하지 않는다.

## 월드 좌표와 TCP 좌표

월드 좌표계는 시뮬레이션 장면에 고정되어 있다. 현재 장면에서는 로봇 베이스의 원점이 월드 원점과 일치한다. TCP 좌표계는 그리퍼 본체를 따라 움직이고 회전한다.

저장된 초기 자세에서 읽은 값은 다음과 같다. 중력에 의해 자세가 안정화된 뒤의 값이 아니라, 물리 시간이 0초인 초기 자세의 값이다.

| 항목 | 월드 기준 값 |
|---|---|
| TCP 위치(m) | `[0.130998, -0.297500, 0.147550]` |
| TCP 위치(mm) | `[130.998, -297.500, 147.550]` |
| TCP +X 방향 | 대략 `[0, -1, 0]`, 월드 -Y 방향 |
| TCP +Y 방향 | 대략 `[-1, 0, 0]`, 월드 -X 방향 |
| TCP +Z 방향 | 대략 `[0, 0, -1]`, 월드 아래쪽 |

예를 들어 현재 자세에서 **TCP +Z 방향으로 10mm**는 월드 기준으로 거의 아래쪽 10mm다. 손목 방향이 바뀌면 TCP +Z도 바뀌므로 언제나 아래쪽이라는 뜻은 아니다. 좌표값의 부호는 화면의 왼쪽·오른쪽이 아니라 기준 좌표계에 의해 결정된다.

## 코드 읽는 순서

[실행 코드](../scripts/view_tcp.py)의 핵심은 다음과 같다.

```python
site = data.site("gripper_pinch")
position = site.xpos.copy()
rotation = site.xmat.reshape(3, 3).copy()
x_axis = rotation[:, 0]
y_axis = rotation[:, 1]
z_axis = rotation[:, 2]
```

`xpos`는 월드 기준 위치다. `xmat`은 3×3 회전 행렬이며 **열(column)** 하나씩이 도구의 X·Y·Z축을 월드 좌표로 표현한 방향이다. `.copy()`는 현재 값을 복사해 두어 이후 시뮬레이션 상태가 갱신될 때 이전 측정값이 함께 바뀌지 않게 한다. [MuJoCo 상태 필드](https://mujoco.readthedocs.io/en/stable/APIreference/APItypes.html#mjdata)

1. `load_robot_with_gripper()`가 기존 모델과 초기 관절 자세를 준비한다.
2. `read_tcp_pose()`가 위치와 회전 행렬을 읽는다. 상태를 바꿨다면 먼저 `mj_forward()`로 계산을 갱신해야 한다.
3. `check_tcp_frame()`이 부모 본체·로컬 위치·로컬 방향과 손목 기준 변환을 검사한다. 세 축이 서로 직각이고 길이가 1인지, 올바른 오른손 좌표계인지도 검사한다.
4. `add_tcp_overlay()`가 좌표축과 표시점을 그린다. 이 표시는 렌더링 장면에만 추가하므로 로봇의 질량·충돌·제어에 영향을 주지 않는다. [MuJoCo 사용자 표시 장면](https://mujoco.readthedocs.io/en/stable/python.html#passive-viewer)

현재 관절 각도에서 TCP 위치·방향을 구하는 것은 **정기구학(FK)**이다. 다음에 다룰 **역기구학(IK)**은 원하는 TCP 위치·방향을 주고 필요한 관절 각도를 구하는 것이다. 둘은 구분하며, IK만으로 충돌 없는 이동까지 보장되는 것은 아니다.

## 검사와 실제 확인 범위

2026-10-28, Python 3.11.15 / MuJoCo 3.17.0에서 `--check`, 5초 제한 뷰어 실행, 실제 렌더러의 좌표축 표시를 확인했다. 뷰어 종료 시 물리 시간은 0초였다.

손목 기준의 예상 TCP 위치 `[0, 0, 0.1558]`m 및 Z축 -90도 회전과 계산 결과가 일치해야 한다. 위치 오차의 크기와 회전 행렬 성분 오차는 각각 `1e-9` 이내로 검사한다. 초기 자세의 위치 변환 오차는 약 `2.8e-16`m, 회전 성분 오차는 약 `2.3e-15`였다. 이 값은 **모델 내부 계산의 일치 오차**이며 실물 정밀도나 보정 정확도가 아니다.

```powershell
uv run --locked python -m unittest discover -s tests -v
```

기존 검사 2개와 새 TCP 검사 3개, 총 5개 테스트가 통과했다. 새 [TCP 검사](../tests/test_tcp_frame.py)는 다음을 확인한다.

- 첫 관절 각도를 30도 다르게 설정한 별도 초기 자세에서 TCP 위치와 방향이 예상한 회전을 따른다. 이는 정기구학 검사이며 그 사이의 경로를 실행하거나 검증한 것은 아니다.
- 실제 7초 그리퍼 닫힘 물리 계산 중, 손가락 간격은 바뀌지만 TCP의 손목 기준 변환은 유지된다. 팔이 중력으로 조금 움직일 수 있으므로 월드 좌표까지 고정되어야 한다고 검사하지 않는다.
- TCP 위치를 10mm 틀리거나 방향을 90도 틀리게 정의한 시험 모델을 거부한다. 원본 모델 파일은 변경하지 않는다.

이 TCP는 그리퍼 본체에 고정된 명목 기준점이다. 손가락은 개폐 과정에서 움직이므로 실제 접촉면의 중심·끝점이 언제나 이 TCP와 일치하지는 않는다. 파지할 물체의 크기와 손가락 간격에 따른 접근 위치는 후속 집기 단계에서 확인해야 한다.

실물 TCP 보정, IK, 목표점 이동, 경로 충돌 검사, 물체 집기는 이번 단계의 완료 범위가 아니다.
