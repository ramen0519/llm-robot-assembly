# 21J · Luna가 제안한 파지로 덮개 하나 끼우기

2026-11-04, 실제 Luna가 파지 위치와 닫힘 방향을 제안하고 MuJoCo 로봇이 덮개 **1/1**을 설치했다. 손을 놓고 후퇴한 뒤 네 기둥의 관통과 네 슬리브의 지지를 포함한 검사 **10/10**을 통과했다. 최소 측면 여유는 1.898mm, 최종 1초의 최대 위치 오차는 0.116mm였다.

## 무엇을 조립하나

160 × 160mm 사각 덮개가 작업대 위에 놓여 있다. 별도 위치에는 바닥판, 기둥 4개와 슬리브 4개가 조립된 상태로 있다. 기둥은 덮개 구멍을 통과해 옆으로 밀리지 않도록 위치를 잡고, 슬리브 윗면은 덮개 무게를 받는다. 이번 로봇의 설치 목표는 **덮개 1개**다. 바닥판만 고정하고 나머지 제품 부품은 모두 접촉하면 움직일 수 있는 자유 물체로 둔다.

## Luna가 어디를 잡을지 정하는 방법

1. 덮개 본판은 두께 8mm이고 한가운데 30 × 25 × 30mm의 돌출 손잡이가 있다. 그리퍼는 최대 85mm까지 벌어지므로 판의 바깥쪽 두 면을 한꺼번에 잡을 수 없다. 모델은 손잡이가 포함된 전체 치수, 손잡이의 위치·치수, 네 구멍의 중심과 폭, 손가락 패드 치수를 받는다. 본판과 손잡이의 위치는 기존 CAD와 MuJoCo 충돌 형상에서 읽는다. 실행 설정의 `cover_grip=center`는 기존 CAD에서 돌출 손잡이가 달린 위치를 뜻한다.
2. Luna가 제안하는 네 숫자는 덮개 좌표계에서의 손끝 중심 X·Y·Z(mm)와 손가락이 닫히는 방향(도)이다. 기준점은 손잡이까지 포함한 **전체 외곽 상자의 중심**이다. 위에서 접근하는 조건은 고정한다. 기존 규칙 정책용 파지 좌표는 모델에 제공하지 않고, 실행할 때는 모델이 제출해 검사를 통과한 숫자를 사용한다.
3. 현재 세계 상태를 복사한 MuJoCo 장면에서 접근·손가락 닫기·들기·운반·삽입·해제·후퇴를 검사한다. 간섭이 있으면 실패 단계와 접촉 물체 이름·월드 좌표 등을 모델에 되돌린다. 후보는 최대 세 개다. 통과한 후보만 원래 장면에서 모터와 그리퍼를 구동해 실행한다.
4. 손을 놓고 후퇴한 뒤 1초 동안 위치, 각도, 속도, 삽입 깊이, 지지와 해제를 확인한다. 마지막에는 판의 실제 자세를 기준으로 네 구멍의 **아랫면과 윗면 각각에서** 기둥 네 모서리가 모두 구멍 안에 있는지 계산한다. 여유가 음수거나 기둥 끝이 개구부까지 닿지 않으면 실패한다. 네 슬리브 각각에서 수직 접촉 지지력도 측정해 어느 한 곳이라도 0.01N 이하이면 실패한다. 모서리와 구멍은 같은 CAD 치수를 사용하고, 상대 위치와 각도는 시뮬레이션에서 측정한다.

## 실행 결과

첫 실험에서 Luna는 (0, 0, −8), (0, +55, −16), (0, 0, −14)mm를 차례로 제안했다. 닫힘 각도는 모두 0°였다. 세 번 모두 접근 하강 중 오른쪽 패드가 본판에 닿았다. 원래 장면은 3.000초에서 정지했고 설치 수는 0개였다. 실행 폴더는 `runs/component_probes/20261103T110927_382597Z_1280007e`이며 실제 모델 생성 3회, 추정 비용은 0.001093375달러다.

모델이 본판을 구성하는 충돌 형상 이름의 `wall`을 돌출된 벽으로 해석한 설명을 로그에서 확인했다. 그래서 본판과 손잡이 각각의 위·아래 높이를 덮개 좌표로 제공하고, 접근 간섭 때 접촉한 형상이 평평한 판인지 손잡이인지 표시하도록 바꿨다. 패드의 예상 최저점과 본판 윗면의 높이 차도 제공한다. 이 값은 열린 그리퍼의 접근 참고값이며 손가락을 닫는 동안의 접촉은 계속 물리 시뮬레이션으로 확인한다. 재시험은 동일한 제품 형상과 검사 기준으로 새 장면에서 시작했다.

두 번째 실험에서 Luna는 손잡이 중심선에서 높이 −2, +2, +4mm를 차례로 선택했고, 모두 양쪽 접촉 유지 검사에서 거절됐다. 마지막 측정의 패드 간격은 각각 70.42, 52.04, 32.83mm로 줄었지만 세 후보 모두 왼쪽 접촉이 끊겼다. 원래 장면에서 설치 0개, 실행 폴더 `runs/component_probes/20261103T111408_445227Z_6225994b`, 생성 3회, 추정 비용 0.001440125달러였다.

원인을 더 자세히 전달하기 위해 같은 2F-85 모델을 빈 공간에서 닫고, 턱 간격별로 손가락 끝이 손끝 기준점 아래로 얼마나 내려오는지 측정했다. 이 개발 환경에서 측정한 패드 간격 79.90, 59.84, 39.59, 29.42mm에서 최저점은 손끝 기준점 아래 각각 6.52, 12.35, 15.96, 17.05mm였다. 같은 파지점이라도 그리퍼가 닫히면서 판에 걸릴 수 있다. 모델은 이 표와 본판 윗면 높이 −11mm를 함께 받는다. 거절 후에는 제안했던 높이에서의 예상 여유도 받는다. 이 표에는 덮개용 정답 위치나 각도가 없으며, 후보의 승인은 그대로 MuJoCo에서 실제 접촉을 검사해 결정한다.

세 번째 실행에서는 모델이 +30mm를 제안해 범위 검사에서 거절된 뒤 +18mm, 닫힘 방향 0°로 수정했다. 이 후보는 복사 장면에서 네 구멍 관통과 네 슬리브 지지를 모두 통과했고 원래 장면에서도 집기·운반·삽입·해제를 진행했다. 사용자의 인터넷 연결 중단 요청에 따라 후퇴 도중 종료했다. 최종 검사 미완료 상태로 남겼다. 마지막으로 기록된 시뮬레이션 시간은 123.024초다.

중단 폴더는 `runs/component_probes/20261103T112109_446565Z_80683bce`다. 모델 생성 요청 3회의 응답 사용량을 확인했고 추정 비용은 0.00106375달러다. 원래 로그를 대조한 `interruption.json`에 이를 기록했다. 11월 4일 재개 때 전체 물리 상태 체크포인트가 없어 새 장면에서 다시 실행했다. 당시 최종 코드의 실행 파일 지문 17개가 재개 시점과 일치했다.

재개 실행 폴더는 `runs/component_probes/20261104T015419_763567Z_a06f084c`다. 처음 +25mm 제안은 허용 범위 [−19, +19]mm를 벗어나 거절됐다. Luna가 (0, 0, +18)mm, 닫힘 방향 0°로 수정했고, 사전 검사를 통과한 그 숫자와 본 실행의 파지 명령이 일치했다. 두 후보의 검사 때 본 장면 시각은 모두 3.000초였으며, 그 뒤 실제 접촉·마찰로 집고 삽입한 기록이 있다.

최종 1초의 덮개 위치 오차 최대값은 0.1163mm였다. 전체 본 실행 동안 기존 기둥·슬리브의 설계 목표 대비 위치 오차 최대값은 0.2158mm였다. 네 구멍 관통, 네 슬리브 지지, 해제, 위치·방향·깊이·속도·침투 조건까지 열 검사를 모두 통과했다.

본 장면의 물리 추적은 66,159행이다. 손가락 닫기·들기·삽입 하강·해제·후퇴가 각각 한 차례씩 기록됐고, 마지막 `finish`에서도 현재 상태의 관통·지지를 다시 검사했다. 실행 파일 지문 17개도 최종 파일과 일치했다. `before.png`, `pick_lift.png`, `insert_alignment_check.png`, `insert_release.png`, `final.png`에 단계별 장면이 저장돼 있다.

재개 실행에서 실제 모델 생성은 4회, 입력 토큰 계산은 별도 4회였다. 입력 9,975토큰, 출력 336토큰, 설정 단가에 따른 추정 비용은 **0.001401375달러**였다. 이번 덮개 단계의 개발 실패와 사용자 중단 실행을 모두 합하면 생성 13회, 추정 **0.004998625달러**다. 21I까지 포함한 프로젝트 누적 추정은 **0.014700875달러**다. 인보이스와 대조한 금액은 별도로 확인해야 한다.

이번 성공 실행은 이미 조립된 네 기둥·네 슬리브 위에 덮개 한 개를 올리는 개발 배치다. 바닥판부터의 전체 Luna 조립과 새 형상에서의 성공률은 후속 검증 범위다.

## 회귀 검사

덮개·프레임 관련 검사 8개를 최종 피드백 코드로 통과했다. 특히 (1) 단일 기둥을 옆으로 4mm 옮긴 경우, (2) 다른 기둥의 끝을 10mm 낮춘 경우, (3) 슬리브 하나를 3mm 낮춰 접촉 하중이 사라진 경우를 각각 거절했다. 검사용으로 만든 자세이며 조립 실적에는 넣지 않는다. 별도 저위 파지 검사에서는 평평한 본판과 패드의 접촉을 기록하고 원래 장면의 위치·속도·시간이 그대로인지 확인했다.

11월 3일에는 기존 슬리브·모델 API 계약 검사 22개도 함께 실행해 최종 코드에서 총 30개를 통과했다. 11월 4일 재개 때 실행 파일의 지문이 일치해 이 테스트 결과를 유지하고 실제 모델의 끝까지 실행을 다시 확인했다. 기존 고정 파지 비교군의 재정렬 절차는 최종 코드로 다시 검증해 동결했다. 동결 묶음에는 경험 2개와 검증 절차 1개가 있다.

## 재현과 코드

프로젝트 키가 설정된 PowerShell에서 `C:\dev\llm-robot-assembly`로 이동해 실행한다. 이 컴퓨터에서는 `gpt-6-luna`를 지정한 21H의 로컬 모델 설정을 재사용했다. 생성 요청 한도는 실행당 7회이고 비용 상한은 0.02달러다. 다른 컴퓨터에서는 해당 옵션에 활성화된 프로젝트 LLM 설정 경로를 지정한다. 다시 실행하면 Luna가 다른 파지를 제안할 수 있다.

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/run_component_probe.py --component cover --cover-llm-config runs/step21h-budget.toml --snapshots
.\runtime\luna-venv\Scripts\python.exe -m unittest discover -s tests -p test_cover_grasp.py -v
```

- `scripts/frame_product.py`와 `scripts/frame_assembly_scene.py`는 판을 만들 때 사용한 네 구멍의 위치를 덮개 좌표로 기록한다.
- `scripts/post_grasp.py`가 로봇만 있는 장면에서 2F-85의 닫힘을 측정한다. `scripts/frame_assembly_skills.py`는 이 치수와 덮개 형상을 모델에 전달하고 개별 관통·지지를 검사한다. 기존 기둥·슬리브에서 사용하던 수치 파지와 동일한 관절 제어 경로를 사용한다.
- `scripts/run_component_probe.py`의 `--cover-llm-config`가 실시간 단일 Luna 정책을 사용한다. `result.json`의 `graph_state.grasp_trials`에서 거절과 승인을, `skill_results[0].proposed_grasp`에서 본 실행에 사용한 파지를 볼 수 있다. `result.cover_fit`에는 구멍별 통과 여유와 슬리브별 접촉 하중이 있다.
- 파지점 지정을 포함한 네 기둥·네 슬리브·덮개 **전체의 연속 Luna 실행**과 처음 보는 덮개에서의 성공률은 별도로 검증할 항목이다.
