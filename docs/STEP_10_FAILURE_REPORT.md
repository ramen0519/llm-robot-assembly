# 10단계: 실패를 FailureReport로 남기기

이번 단계의 목표는 **TCP 이동이 실패했을 때 실패 코드·발생 시점·목표와 실제 상태·접촉 정보를 JSON 파일로 보존하는 것**이다. 기존 모터 동작과 판정 기준은 유지한다. 추가 패키지는 없다.

JSON은 이름과 값을 짝지어 저장하는 텍스트 형식이다. 사람이 읽을 수 있고, 나중에 LangGraph가 필요한 필드를 골라 읽을 수도 있다. `FailureReport`는 그 파일에 담을 정보의 구조다. 아직 자동 복구, 원인 추론, LLM 호출이나 장기 메모리 검색은 하지 않는다.

## 실행하고 결과 찾기

PowerShell에서:

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/move_tcp.py --headless
```

`--headless`를 빼면 기존 이동 뷰어를 사용한다. 이번 단계에서는 위 명령으로 실제 물리 계산과 저장을 확인했으며, 새 뷰어 창을 직접 조작한 검사는 하지 않았다. 뷰어 종료 처리는 테스트에서 종료 신호를 주어 확인했다.

정상 조건에서는 `TCP physical motion: PASS`가 출력된다. 시작할 때 출력되는 `Run directory`가 이번 실행의 저장 위치다.

```text
runs/step10/<UTC시각_고유ID>/
    tcp_motion.csv          # 검사에 통과한 각 시점의 측정값
    result.json             # success / failed / cancelled
    failure_report.json     # 실패·중단한 경우에만 생성
```

매번 새 폴더를 만든다. 다음 실행이 성공해도 앞선 실패 기록을 덮어쓰지 않는다. `runs/`는 Git에서 제외되어 있고 OneDrive 밖에 있다. 이전 9단계의 고정 CSV 경로는 `run_motion()`의 저수준 기본값에만 남아 있다. 현재 CLI는 항상 실행별 폴더를 사용한다.

실패 검사를 재현하려면:

```powershell
uv run --locked python -m unittest discover -s tests -p test_failure_report.py -v
```

테스트는 임시 폴더에서 의도적으로 실패를 만들고 분류와 파일 내용을 검사한다. 종료 후 임시 파일은 정리된다. 테스트의 `OK`는 **의도한 실패를 제대로 검출·기록했다는 뜻**이며, 실패한 로봇 동작이 성공했다는 뜻은 아니다.

## 코드가 연결되는 순서

```text
move_tcp.execute_trial(): 실행 폴더 생성
  → IK / 사전 검사
  → run_motion(): 모터 실행, 실제 상태 검사, CSV 기록
  → assess_motion(): 마지막 0.5초의 도착·안정 판정
  → 성공이면 result.json
  → 실패이면 중단 → FailureReport 저장 → failed 또는 cancelled 반환
```

| 파일 | 역할 |
|---|---|
| `scripts/failure_report.py` | 실패 코드, 보고서 구조, 상태 복사, JSON 저장 |
| `scripts/solve_tcp_ik.py` | IK 계산 실패와 후보 자세 접촉에 코드를 붙임 |
| `scripts/move_gripper.py` | 공유 상태 검사의 접촉·관절·그리퍼·물리 이상에 코드를 붙임 |
| `scripts/move_tcp.py` | 실행 시점·목표를 연결하고 실패 보고서를 저장 |
| `tests/test_failure_report.py` | 실제 MuJoCo 계산 및 제한된 실패 주입으로 증거 보존 검사 |

검사 지점이 `FailureEvent`를 발생시키면 현재 동작을 빠져나온다. 실행 관리 함수가 이를 받아 `FailureReport`로 저장한다. 예외 문장에 특정 단어가 있는지 검색해서 분류하지 않는다. **보고서 저장은 상태를 복사할 뿐 `mj_step()`, `mj_forward()`나 reset을 호출하지 않는다.**

이번에 파일 저장까지 연결한 실행기는 `move_tcp.py`다. 과거의 단독 IK·그리퍼 CLI에는 공통 예외 코드만 연결했고 자동 JSON 저장은 추가하지 않았다.

## 보고서 읽는 방법

| 필드 | 의미 |
|---|---|
| `failure_code` | 프로그램이 구분하는 실패 종류 |
| `phase` | `ik`, `preflight`, `hold`, `move`, `settle`, `verify` 등의 검출 단계 |
| `detected_at_utc` | 보고서 생성 시 실제 UTC 날짜·시각. 한국 시각은 UTC+9 |
| `simulation_time_s` | 검출 당시 시뮬레이션 시간. 7초 동작은 약 7.0으로 기록 |
| `goal` | 월드 기준 목표 TCP 위치(m), 회전행렬, 위치·방향 허용 오차 |
| `actual` | 실패 순간 실제 관절 각도·속도, 입력 명령, TCP, 접촉 정보 |
| `actual.goal_error` | 실패 순간의 목표와 실제 TCP 사이 위치(mm)·방향(deg) 오차 |
| `last_valid_observation` | 마지막으로 개별 상태 검사를 통과한 관측. 없으면 `null` |
| `candidate` | 물리 실행 전 검사하던 계산 후보. 실제 움직인 상태와 구분 |
| `violations` | 기준을 넘은 측정 항목·값·임계값·측정 시점. 접촉 증거는 `actual.contacts` 또는 `candidate.contacts`에 기록 |
| `cause_hypotheses` | 원인 가설. 현재는 진단하지 않으므로 빈 목록 |
| `response` | 현재 대응은 항상 `stop_without_retry` |

현재 모델의 관절은 모두 hinge이므로 각도는 rad, 속도는 rad/s다. `ctrl` 배열의 팔 6개 입력은 rad, 마지막 그리퍼 입력은 0~255다. 순서에 대응하는 관절·구동기 이름을 `model`에 저장한다. TCP 회전은 기존 코드와 같은 3×3 회전행렬이며 **각 열이 월드에서 본 TCP X/Y/Z축 방향**이다. 향후 adapter의 quaternion 계약과 혼동하지 않는다.

`actual.source`는 `sim_ground_truth`다. MuJoCo 내부 상태를 읽은 값이며 카메라 인식 결과나 실물 관측이 아니다. 계산 후보는 `ik_candidate` 또는 `preflight_candidate`로 표시하고, 실제 실행 시간이 없으므로 후보의 시간은 `null`이다.

`valid: true`는 관측 데이터를 읽을 수 있다는 뜻이다. 동작 성공이나 재시도 허가를 뜻하지 않는다. 개별 상태 검사를 통과했어도 최종 목표에는 도착하지 못할 수 있다. 이 경우 최종 실패와 마지막 정상 관측의 시간이 모두 7초일 수 있다.

물리 경고·비정상 수치·갱신 여부 불확실 등으로 신뢰할 수 없는 값은 `null`과 `invalid_reasons`로 남긴다. JSON에 `NaN`을 쓰거나 읽지 못한 값을 0으로 위장하지 않는다. 관측을 무효로 표시한 경우 TCP·접촉이 누락될 수 있다.

## 처음 확인할 실패 코드

| 코드 | 뜻 | 현재 대응 |
|---|---|---|
| `IK_NOT_CONVERGED` | 제한된 계산 안에서 목표 각도를 구하지 못함. 절대 도달 불가라는 증명은 아님 | 물리 실행 시작 안 함 |
| `PLANNED_CONTACT` | IK 또는 사전 검사 후보에서 접촉 발견 | 후보와 실제 상태를 구분해 저장, 실행 시작 안 함 |
| `UNEXPECTED_CONTACT` | 실제 실행 상태에서 허용하지 않은 접촉 검출 | 추가 물리 스텝 없이 종료 |
| `TCP_NOT_REACHED` | 최종 위치 또는 방향 오차가 기준 초과 | 오차와 기준 저장 후 종료 |
| `NOT_SETTLED` | 마지막 구간 속도가 기준 미만으로 줄지 않음 | 속도와 기준 저장 후 종료 |
| `CANCELLED` | 창 닫힘 신호 또는 사용자 중단 | 상태를 cancelled로 저장 |
| `INCOMPLETE_RECORD` | 최종 판정에 필요한 연속 기록 부족 | 성공 판정 거부 |

입력·전제조건, 모델·제어, 이동 제한, 그리퍼 상태, 물리 상태의 이상도 별도 코드가 있다. 예상하지 못한 예외는 `UNCLASSIFIED_ERROR`로 남기고 임의로 IK 실패나 접촉 문제라고 단정하지 않는다. 모든 코드의 물리 실패 사례를 각각 검증한 것은 아니다.

## 실제 확인한 실패 예시

**이동 중 접촉:** 테스트용 장애물을 2초에 이동 중인 그리퍼 위치에 넣었다. 로봇 관절이나 접촉 배열을 직접 덮어쓰지 않고 MuJoCo가 접촉을 계산했다. 검출기 시험용 인위적인 배치이며 자연스러운 충돌 빈도나 복구 성능을 측정하는 실험은 아니다.

실제 보고서에서 읽은 값의 일부를 반올림하면:

```json
{
  "failure_code": "UNEXPECTED_CONTACT",
  "phase": "move",
  "simulation_time_s": 2.0,
  "response": "stop_without_retry"
}
```

마지막 정상 관측은 **1.998초**, 실패 관측은 **2.000초**다. CSV는 검사 중 예외가 발생한 2초 행을 포함하지 않지만, JSON의 `actual`에는 그 시점이 남는다. 접촉 3개가 저장됐고 그중 `test_obstacle_geom`과 `gripper_left_pad1`의 `signed_distance_m`는 약 **-0.016m**였다. 검출 후 추가 `mj_step()` 호출이 없음을 확인했다.

접촉에는 형상 ID·이름, 소속 body, 월드 위치, 부호 있는 거리, 침투 깊이를 저장한다. 이름 없는 형상은 ID와 body로 식별한다. 음수 거리는 모델 충돌 형상의 겹침을 뜻하며 힘 측정값은 아니다. 양수 거리의 접촉 후보가 포함될 수도 있다. 현재 빈 그리퍼 이동은 모델에서 검출한 접촉을 모두 금지하며, 향후 파지·삽입의 허용 접촉은 따로 정의해야 한다.

**목표 미도달:** 테스트에서 중력 보상만 끄고 기존 모터와 중력으로 7초간 실행했다. `TCP_NOT_REACHED`이며 마지막 구간의 최대 위치 오차는 약 **10.86133mm**, 방향 오차는 약 **2.12101도**였다. 기준은 각각 **1mm**, **0.5도**다. 실패를 최종 판정한 시각은 7초지만 가장 큰 위치 오차는 6.5초에서 측정됐으므로 `violations.sample_time_s`에 그 시각을 별도로 남긴다. 실제 실패 순간 위치 오차는 약 10.86120mm다.

개발자는 보상을 껐다는 것을 알지만 보고서는 이를 원인 진단으로 입력하지 않는다. 관측 결과와 시험용 정답을 분리한다.

## 검증 결과와 경계

2026-10-28에 전체 회귀검사 **20개 통과**와 정상 CLI 실행을 확인했다. 정상 마지막 구간의 최대 위치 오차는 약 0.004908mm로 기존 동작과 같았다.

새 검사 7개는 정상/미도달의 파일 분리, 실제 이동 중 접촉, 사전 계산 후보에만 주입한 접촉, IK 계산 예산 부족, 뷰어 종료 신호/불완전 기록, 비정상 수치의 strict JSON 저장, 로그 저장 실패를 확인한다. 후보 접촉 시험은 계획 경로의 완전성을 보장하지 않는다. 비정상 수치와 저장 오류는 해당 처리 경계를 직접 주입해 시험했다.

JSON 쓰기는 임시 파일을 완성한 뒤 이름을 바꾼다. 저장 실패 시 원래 동작 오류와 저장 오류를 콘솔에 함께 알리고 실패로 종료한다. 디스크 고장이나 프로세스 강제 종료에서도 로그가 반드시 남는다는 보장은 아니다.

이 단계는 **검출 → 중단 → 근거 보존**까지다. 보고서는 장면 복원용 전체 snapshot이 아니며, 재개·자동 후퇴·재시도·스킬 생성·장기 메모리 검색은 아직 없다. 이후 복구 한 가지를 구현할 때 이 보고서를 입력으로 사용하고, 상태를 다시 확인한 다음 새 동작을 검증한다.
