# 2단계: 공 하나로 중력과 바닥 충돌 확인하기

## 이번 단계의 목표

바닥 위에 공을 띄워 두고, MuJoCo의 물리 계산으로 떨어져 바닥에 놓이는지 확인한다. 장면 정의, 시뮬레이션 실행, 결과 판정의 역할을 구분하는 첫 예제다. 로봇 모델·IK·조립·에이전트는 이번 단계의 범위가 아니다.

## 파일별 역할

| 파일 | 하는 일 |
|---|---|
| [falling_ball.xml](../scenes/falling_ball.xml) | 바닥, 공, 중력, 접촉, 조명 정의 |
| [drop_ball.py](../scripts/drop_ball.py) | 장면을 읽어 3D 창에서 시뮬레이션 실행 |
| [check_drop.py](../scripts/check_drop.py) | 창 없이 실제 물리 계산을 실행하고 결과 판정 |

새 라이브러리는 추가하지 않았다. 앞 단계에서 설치한 MuJoCo와 Python 기본 라이브러리를 사용한다.

## 먼저 실행해 보기

PowerShell에서 다음 명령을 실행한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/drop_ball.py
```

체크무늬 바닥 위의 주황색 공이 떨어진다. 3초의 시뮬레이션이 끝날 때마다 초기 상태로 돌아가 새 실험을 반복한다. 창을 닫으면 종료된다. 실제로 확인한 자동 종료 명령은 다음과 같다.

```powershell
uv run --locked python scripts/drop_ball.py --seconds 8
```

`--seconds 8`은 창을 연 뒤 컴퓨터의 실제 경과 시간 약 8초 후 닫는 옵션이다. 화면 반복은 새 실험을 시작하는 초기화이며, 한 낙하 실험 도중에는 공의 위치를 직접 고치지 않는다.

수치로 검증하려면 다음 명령을 실행한다.

```powershell
uv run --locked python scripts/check_drop.py
```

이 명령은 3초 분량의 물리 계산을 최대한 빠르게 실행한다. 창을 띄우지 않으며, 모든 조건을 통과하면 종료 코드 0, 하나라도 실패하면 종료 코드 1을 반환한다.

## XML: 어떤 세계를 계산할지 정하기

MuJoCo의 장면 형식인 MJCF는 XML 문법을 사용한다. 태그에 물체와 조건을 적으면 MuJoCo가 읽어 물리 모델로 만든다.

```xml
<option timestep="0.002" gravity="0 0 -9.81" integrator="implicitfast"/>

<body name="ball" pos="0 0 0.6">
  <freejoint name="ball_free"/>
  <geom name="ball_geom" type="sphere" size="0.05" mass="0.1"/>
</body>
```

| 설정 | 이번 장면에서의 의미 |
|---|---|
| `gravity="0 0 -9.81"` | z축 아래로 중력가속도 9.81m/s² 적용 |
| `timestep="0.002"` | 한 번의 물리 계산이 시뮬레이션 시간 0.002초 진행 |
| `body pos="0 0 0.6"` | 공의 중심을 처음에 높이 0.6m에 배치 |
| `freejoint` | 공이 위치 3방향과 회전 3방향으로 자유롭게 움직이도록 허용 |
| `geom type="sphere"` | 구 모양의 시각·충돌 형상 |
| `size="0.05"` | 구의 반지름 0.05m, 즉 5cm |
| `mass="0.1"` | 공의 질량 0.1kg |

여기서는 m·kg·s 단위를 일관되게 사용한다. 공의 중심 높이와 바닥에서 공의 아랫면까지의 간격을 혼동하지 않아야 한다. 처음 간격은 0.6 - 0.05 = 0.55m다.

바닥은 `worldbody` 바로 아래의 `plane` 형상으로 정의해서 움직이지 않는다. 바닥의 높이는 0m다. 이 장면에서 바닥에 놓인 공의 중심 높이는 반지름과 같은 약 0.05m가 되어야 한다.

체크무늬, 색, 조명은 장면을 보기 쉽게 만든 시각 설정이다. 접촉 계산과 역할이 다르다.

## Python: 시간을 진행시키기

`load_scene()`에서 XML을 읽어 다음 두 객체를 만든다.

- `model`: 질량, 형상, 중력, 시간 간격 같은 모델 정보.
- `data`: 계속 변하는 위치, 속도, 접촉 정보와 시뮬레이션 시간.

물리 계산의 중심은 다음 한 줄이다.

```python
mujoco.mj_step(model, data)
```

MuJoCo가 중력과 접촉 등으로 생기는 운동을 계산해 `data`를 갱신한다. 낙하하는 위치를 우리가 매번 지정하는 방식이 아니다.

`drop_ball.py`는 물리 계산 8회 후 화면을 갱신한다. 8 × 0.002 = 0.016초 간격이므로 목표 표시 속도는 시뮬레이션 시간 기준 약 62.5회/초다. 계산이 빨리 끝나면 `time.sleep()`으로 잠시 기다려 눈으로 볼 수 있게 한다. PC 부하와 운영체제 스케줄링 때문에 정확한 실시간 실행을 보장하는 제어 루프는 아니다.

`viewer.sync()`는 현재 상태를 뷰어와 동기화한다. `viewer.lock()`은 뷰어와 실행 코드가 공유하는 상태를 동시에 수정하지 않도록 보호한다. `set_camera()`는 장면을 보기 좋은 각도로 맞춘다.

`mj_resetData()`는 새 반복 실험을 시작할 때만 쓴다. 별도의 수치 검증 코드는 중간 초기화 없이 한 번의 연속된 3초 실험을 검사한다.

## 무엇을 검사했는가

검사 코드는 매 물리 계산 뒤 `mj_forward()`를 호출해 새 상태의 위치와 접촉 정보를 갱신한다. `mj_forward()` 자체는 시간을 진행시키는 함수가 아니다.

공기 저항이 없는 자유낙하의 이론 높이는 `초기 높이 - 0.5 × 9.81 × 시간²`다. 충돌 전인 0.2초에 이 값과 실제 높이를 비교한다. 설정에서 중력을 잘못 바꾸더라도 발견할 수 있도록 이론 계산의 중력값은 독립적으로 9.81을 사용한다.

이 검사기는 이번 구·평면 장면을 위한 코드다. 모델 이름과 수직 낙하 조건을 전제로 하므로 범용 로봇 조립 판정기로 사용하지 않는다.

| 검사 | 통과 기준 |
|---|---|
| 중력에 의한 낙하 | 0.2초 높이가 이론값과 5mm 이내이고 아래로 이동 중 |
| 바닥 접촉 | 공과 바닥의 실제 접촉을 찾고 이론 접촉 시각과 0.01초 이내 |
| 과도한 바닥 관통 방지 | 공 아랫면이 바닥 아래로 들어간 깊이가 2cm 이내 |
| 안정 상태 | 마지막 0.5초 내내 바닥 접촉 유지, 중심 높이 오차 1mm 미만, 이동 속도 0.01m/s 미만 |

코드에서 `no fall through the floor`라고 출력하는 항목은 위의 2cm 겹침 한계를 뜻한다. 엄밀히 침투가 0이라는 뜻이 아니다. 기준은 이 입문 장면의 동작 확인용이며 정밀 조립 공차가 아니다.

## 실제 측정 결과

2026-10-26, MuJoCo 3.17.0, Windows 환경에서 확인했다.

| 항목 | 측정값 |
|---|---|
| 초기 중심 높이 | 0.600000m |
| 0.2초의 중심 높이 | 0.401838m, 이론값 0.403800m |
| 최초 바닥 접촉 | 약 0.334초, 이론값 약 0.334859초 |
| 충돌 중 최저 중심 높이 | 0.044355m |
| 최종 중심 높이 | 0.049930m |
| 마지막 0.5초 최대 높이 오차 | 약 0.000070m = 0.07mm |
| 마지막 0.5초 최대 이동 속도 | 출력 정밀도에서 0.000000m/s |

네 항목 모두 PASS였다. 이론과 낙하 높이가 조금 다른 것은 유한한 시간 간격으로 적분하는 수치 계산의 특성이다.

개발 중 기본 접촉 설정에서는 충돌 순간 최대 겹침이 약 2.02cm여서 검사가 실패했다. XML에 `solref="0.008 1"`을 설정해 접촉 반응 시간 상수를 0.008초로 줄이고 같은 기준으로 재검사했다. 첫 값은 반응 시간 상수, 두 번째 값은 감쇠비다. 접촉 솔버의 설정이며 실제 공의 재료를 실측한 값은 아니다.

수정 후 순간 최대 겹침은 약 5.65mm이고, 정지 후 겹침은 약 0.07mm다. MuJoCo의 부드러운 접촉 모델이므로 완전히 단단한 표면의 침투 0을 보장하지 않는다. 로봇 조립 단계에서는 물체 형상과 작업 공차에 맞춰 별도 검증해야 한다.

추가로 중력을 0으로 만든 장면과 바닥 충돌을 비활성화한 장면을 별도 메모리 모델에서 실행했고, 두 경우 모두 전체 검사에서 실패했다. 잘못된 동작을 성공으로 판정하지 않는지 확인한 대조 실험이다. 저장된 XML은 정상 조건을 유지한다.

3D 뷰어는 8초 제한으로 창 생성·정상 종료를 확인했다. 같은 모델의 초기 상태와 착지 후 상태를 MuJoCo로 렌더링한 이미지도 확인했다. 생성 이미지는 Git에서 제외된 로컬 `runs/step02/`에 저장했다.

## 직접 바꾸어 볼 부분

XML의 공 초기 높이를 `0.6`에서 `0.8`로 바꾸면 더 높은 곳에서 떨어진다. 파일을 저장하고 뷰어 명령을 다시 실행해야 바뀐 장면을 읽는다. 높이·반지름·중력 등을 바꿀 때는 수치 검사의 전제와 허용 범위도 함께 검토한다.

이번 단계에서 배울 핵심은 장면의 조건과 움직임 계산, 결과 판정을 서로 구분하는 것이다. 이후 로봇이 들어와도 이 구분을 유지한다.
