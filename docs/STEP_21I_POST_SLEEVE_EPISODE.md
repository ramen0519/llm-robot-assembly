# 21I · 빈 바닥판에 기둥을 설치하고 같은 기둥에 슬리브 끼우기

## 한 번의 실행에서 확인한 것

2026-11-03, 단일 Luna와 MuJoCo로 로봇 설치 **2/2**를 확인했다. 고정된 파란 바닥판과 작업대에 따로 놓인 주황 기둥, 초록 슬리브로 시작했다. 로봇이 기둥을 집어 소켓에 세우고 손을 놓았다. 이어 슬리브를 집어 방금 세운 기둥 위에서 내려 끼웠다. 마지막에 손가락을 열고 위로 물러난 뒤에도 기둥은 슬리브의 양쪽 구멍을 통과했고 두 부품 모두 지지됐다.

이전 슬리브 단독 시험에서는 장면을 만들 때 기둥을 소켓에 놓아 주었다. 이번에는 바닥판만 고정했다. 두 부품은 각각 자유롭게 움직이고 접촉, 중력, 마찰에 따라 자리 잡는다.

## 누가 무엇을 결정했나

- **작업 순서**는 이번 과제의 선행조건인 기둥 → 슬리브로 지정했다. 분해 플래너 호출은 이 실행에 포함되지 않는다.
- **Luna**는 현재 부품의 치수·자세, 목표 결합, 주변 부품의 설치 상태를 보고 행동과 파지를 제안한다. 파지의 네 숫자는 부품 중심에서의 X·Y·Z 거리(mm)와 손가락이 닫히는 방향(도)이다. 팔이 위에서 접근한다는 조건은 실행기가 정한다.
- **MuJoCo와 실행 코드**는 먼저 현재 물리 상태의 복사본에서 제안대로 집고 삽입까지 할 수 있는지 검사한다. 간섭이 발생하면 위치와 접촉한 물체를 Luna에 전달한다. 통과하면 원래 장면의 관절과 그리퍼를 제어해 실제 동작을 실행하고 결과를 다시 측정한다.
- **부품 전환** 때는 같은 로봇, 물리 상태, 정책 클라이언트와 요청 예산을 유지한다. 기둥을 손에서 놓고 설치 검증과 완료 판단까지 통과한 뒤에만 슬리브 작업으로 넘어간다. 슬리브 작업 중에도 기둥의 지지와 자세를 계속 검사한다.

## Luna의 제안과 물리 검증

아래 좌표는 작업대 좌표가 아니라 각 부품의 중심 기준이다. 두 부품 모두 손가락 닫힘 각도는 0°였다.

| 부품 | 첫 제안과 거절 이유 | 본 장면에서 실행한 수정 제안 | 손을 놓은 뒤 |
|---|---|---|---|
| 기둥 | (0, 0, 0)으로 잡으면 삽입 하강 경로에서 오른쪽 패드와 바닥판 벽이 간섭 | (0, 0, +12)mm | 소켓 삽입 깊이 최소 16.108mm, 최종 1초의 최대 위치 오차 0.124mm, 검사 8/8 |
| 슬리브 | (+15, 0, 0)으로 손가락을 닫는 도중 왼쪽 패드가 작업대에 닿음 | (0, 0, +8)mm | 최종 1초의 최대 위치 오차 0.087mm, 관통을 포함한 검사 9/9 |

두 부품에서 각각 `pick → pick → insert → finish`를 제안했다. 첫 번째 집기 제안은 각각 사전 검사에서 거절됐다. 본 장면의 기록에는 부품별 손가락 닫기·들어 올리기·삽입 하강·해제·후퇴가 한 차례씩 있다. 빈 그리퍼의 접근은 두 번 모두 충돌 검사를 통과한 기본 경로로 실행했다.

## 재현

로컬 폴더는 `C:\dev\llm-robot-assembly`다. 프로젝트 전용 환경과 키가 준비된 PowerShell에서 실행한다. 이 실행에는 `gpt-6-luna`, **두 부품 합계 생성 10회·0.03달러 상한**을 적용한 로컬 설정 `runs/step21i-budget.toml`을 썼다. 다른 환경에서는 키가 설정된 프로젝트의 활성 LLM 설정 파일을 해당 인수에 지정한다. 모델이 다른 파지를 제안하면 경로와 결과가 달라질 수 있다.

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/run_frame_assembly.py --parts 3 --mode single --empty-approach-strategy direct_then_rrt --post-sleeve-llm-config runs/step21i-budget.toml --snapshots
```

기대 결과는 `success`, `execution_order = ["post_1", "sleeve_1"]`, `robot_installed_parts = 2`이며 슬리브의 관통 검사도 통과해야 한다. 저장된 결과는 키나 재호출 없이 열어 볼 수 있다.

- 이번 실행 폴더는 `runs/step23_frame/20261103T105411_716880Z_b0d07399`다. `before_assembly.png`, `after_post_1.png`, `after_sleeve_1.png`는 같은 카메라로 찍은 순서별 장면이다.
- `result.json`의 `part_episodes`에 부품 전환 상태와 실제 사용한 파지 명령이 있다. `results`에는 손을 놓은 뒤의 물리 검사, `graph_states`에는 각 제안과 검증 결과, `skill_trace.csv`에는 모터를 움직인 본 장면의 측정값이 있다.
- 실제 생성 요청은 **8회**, 별도 입력 토큰 계산 요청은 8회였다. 입력 13,239토큰, 출력 719토큰, 설정 단가 기준 추정 **0.001987375달러**, 21H까지 포함한 프로젝트 누적 추정 **0.00970225달러**다.
