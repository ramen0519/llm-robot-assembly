# 33. 연구실 6셀 배터리팩: 저장된 2초 상태의 후속 진단

2026-11-25 · MuJoCo 3.17.0 · UR3e 1대 · Robotiq 2F-85 · 케이스 0번 고정

**결과: 2~3초 구간도 속도 기준에 실패했다. 복원과 반복 실행은 정확히 재현됐다.**

원본의 1~2초 검사는 실패로 유지한다. 이번 검사는 완성된 기준 장면의 별도 후속 진단이며, 로봇 조립이나 실제 Astra 실행이 아니다. API 0회, 비용 $0, 설치 작업 0회, 경험 등록 0건이다.

## 상태 복원 확인

- 저장 형식은 `mjSTATE_INTEGRATION` (마스크 16383), 프레임당 float64 583개다. 시간·관절 위치·속도·solver warmstart·제어 입력·외력·구속 활성 상태 등 현재 모델에 필요한 상태가 포함됐다.
- 상태를 복원한 직후 및 `mj_forward` 후 모두 저장 상태와 원소별 완전히 같았다. 원본 2초의 부품별 위치·회전·선속도·각속도와 차이도 모두 0이었다.
- 제어기의 팔 목표는 저장된 시작 프레임의 `qpos[:6]`에서 복원했다. 그리퍼 명령 0, 운반 중인 부품 없음, 동일한 원본 ArmPositionController를 사용했다. 신규 목표로 2초 자세를 지정하지 않았다.
- 같은 2초 상태에서 2~3초를 두 번 실행했다. 501개 전체 integration state와 501개 전체 부품 측정값이 모두 정확히 일치했다. 최대 상태 차이 0이다.
- 필요한 integration 상태 누락이 없어 0~2초 전체 재실행은 하지 않았다. 원본 0~2초를 새로 실행해서 일치시켰다고 주장하지 않는다.
- 원본 준비 입력 SHA-256: `fc738deae225f4099cfac9d4467ce0634c27590bf5fc6beefd968f923f020012`. 원본 모델·상태·목표·결과·코드 기록 7개 파일의 전후 SHA-256이 같다.

## 같은 프레임의 중복 계산 수정

`scripts/assembly_v2/verification.py`의 `contacts()` 한 번 안에서만 부품별 `near_goal` 결과를 재사용한다. 함수가 끝나면 캐시는 사라진다. 시간만으로 캐시를 재사용하지 않으며 같은 시각의 다른 복사 장면, qpos 변경, 다음 물리 단계에서도 반드시 새로 계산한다.

| 시뮬레이션 시각 | 접촉 수 | 기존 자세 계산 → 변경 후 | 기존 접촉 검사 → 변경 후(초) | 판정·근거 해시 |
|---|---:|---:|---:|---|
| 2.000 | 2966 | 5932 → 13 | 1.0186 → 0.0302 | 동일 |
| 2.500 | 3129 | 6258 → 13 | 1.1069 → 0.0311 | 동일 |
| 3.000 | 3121 | 6242 → 13 | 1.1714 → 0.0329 | 동일 |

후속 두 회차와 위 비교의 실제 경과는 84.69초다. 측정된 단일 접촉 검사 개선을 전체 조립 속도 향상률로 해석하지 않는다. 원본 verifier와 비교한 세 프레임 모두 접촉 판정·전체 접촉 근거 해시가 같고 integration state도 바뀌지 않았다.

v2 자동 검사 39개 통과. 새 검사는 한 호출 안의 중복 제거와 동일 시각의 qpos 변경/다른 복사 장면에서 캐시가 새지 않는 것을 확인한다.

## 유료 재실행 범위

기존 $7.50 승인은 종료된 한 회차용이므로 사용하지 않았다. 현재 조건으로 재실행하면 동일한 기준 장면 실패가 예상되어 Astra 회차를 권하지 않는다. 먼저 속도 진동 원인을 API 없이 분리 진단해야 한다.

물리 준비가 통과한 뒤 유료 한 회차를 새로 승인받는다면, 기존 범위를 기준으로 Astra high 최대 24응답 + 24회 입력 길이 조회, 비용 상한 $7.50, 조립 실행 상한 30분과 후처리 최대 3분을 제안한다. 입력 재검증은 별도이며 직전 회차에서는 약 11.71분이었다. 이는 실행 제안 상한과 과거 측정값이지 이번 추가 승인이나 성공 보장이 아니다. 실제 유료 명령은 실행하지 않았다.
