# 22F — 기둥 파지 로그를 경험 기록으로 변환

작성: 2026-11-10. 상태: **첫 저장 모듈 구현·기존 로그 변환 확인 완료**.

## 1. 이번에 만든 것

기존 실행 로그를 읽어 “무엇을 제안했는가 → 어떤 검사 결과가 나왔는가 → 원래 장면에서 실행했는가 → 어떤 검증 근거가 남았는가”를 연결하는 변환기다.

이 단계의 **경험(Memory)은 사실을 담은 구조화된 JSON 기록**이다. 자연어 교훈이나 실행 코드가 아니다. 예를 들어 “중앙을 잡으려다 간섭이 나서 높이를 12mm 올렸고, 그 설정으로 삽입 검증을 통과했다”는 사건과 수치·출처를 저장한다. “이런 기둥은 항상 12mm 위를 잡아라”라는 일반 규칙을 만들지는 않는다.

성공 기준:

1. 실제 저장된 기둥 로그의 제안·검사·실행·검증이 서로 연결된다.
2. 복사 장면의 검사 통과를 원래 장면의 조립 성공으로 세지 않는다.
3. 거절·중단·누락 자료가 성공으로 바뀌지 않는다.
4. 같은 입력의 재변환이 파일을 중복 생성하지 않는다.
5. 원본 로그와 기존 v1 메모리·레시피를 바꾸지 않는다.

## 2. 파일과 흐름

- `scripts/export_grasp_experience.py`: 표준 Python만 사용하는 읽기·변환·저장 모듈.
- `tests/test_export_grasp_experience.py`: 합성 로그로 기록 연결과 예외 처리를 검사한다. 실제 물리 성공 증거가 아니다.
- `runtime/memory/simulation/grasp_v2/`: 변환한 실제 로컬 경험 JSON. Git에서 제외한다.
- `runtime/validation/step22f_saved_log_check.json`: 기존 로그 6개 변환 및 원본 보존 검사 결과. Git에서 제외한다.

입력은 `resolved_config.json`, `graph_events.jsonl`, 선택적 `result.json`이다. 설정은 로봇·부품·목표·단위를, 그래프 로그는 사건 순서를, 결과 파일은 남아 있는 실제 측정값을 제공한다. 결과 파일이 없어도 기록된 사건을 읽을 수 있지만 측정값을 채워 넣지 않는다.

`build_export()`가 입력을 확인하고 사건을 연결한다. `validate_export()`는 내용 hash와 연결 참조를 확인한다. `save_export()`는 완성된 파일만 공개하며 기존 파일을 덮어쓰지 않는다. hash는 내용 변경을 확인하는 지문이지 물리 검증이나 서명 인증이 아니다.

새 API 호출, MuJoCo 실행, 로봇 명령, LLM 프롬프트 변경은 없다. 기존 `experience_memory.py`, `skill_recipes.py`, `frozen_knowledge.py`도 변경하지 않았다.

## 3. 기록 한 개와 시도 한 개의 차이

**기록(record)**은 제안·검사·실행·검증 중 한 사건이다. **시도(attempt)**는 하나의 파지 제안을 중심으로 연결된 사건 묶음이다. 파지 값을 바꿔 다시 제안하면 새로운 시도가 된다. 집기 이후 삽입 명령은 같은 파지 시도에 연결한다.

| stage | 뜻 | 저장하는 핵심 정보 |
|---|---|---|
| proposal | 그래프에 남은 행동 제안 | 행동, 부품/목표, 파지 XYZ·닫힘 방향, 제안 이유 |
| preflight | 복사 장면을 이용한 사전검사 | 수락/거절/미확인, 검사 위치, 접촉 쌍·거리, 패드 여유 |
| execution | 원래 장면의 실행 노드가 반환되거나 예외 처리됨 | 행동, 실패 증가 여부, 남아 있는 실제 접근 파지/TCP 결과 |
| verification | 실행 후 검증 사건 | 그래프 완료 표시와 원시 수치 검사 결과를 구분 |

각 기록에는 부품·목표·시도 ID, 관측 번호, 시뮬레이션 시각, 원본 파일과 행 번호/JSON 위치, 앞선 근거의 ID를 넣었다. 제안을 바꾼 시도에는 이전 거절 기록과 변경량(예: `z_mm: 12`)도 연결한다.

관측 번호는 부품별로 다시 시작하므로 번호만으로 연결하지 않는다. 부품·목표·행동·시각을 함께 확인한다. 당시 로봇·그리퍼, 부품 기준 좌표(mm), 회전(deg), MuJoCo/원본 코드 버전도 가능한 만큼 보존한다. 이전 로그에 원본 코드 hash가 없으면 비워 둔다.

시도 ID는 이후 결과 파일이 추가돼도 유지된다. 반면 원본 파일 묶음과 변환 내용의 ID는 내용이 달라지면 바뀐다. 후속 검색에서는 같은 시도의 여러 버전을 별도 물리 시도로 합산하면 안 된다.

원본: `runs/step21/20261103T090739_028883Z_46ffab9d` (기둥 트레이 위치가 X로 10mm 이동된 개발 실행).

|---:|---|---|

| 4 | 검사 거절 | `PLANNED_CONTACT`, 오른쪽 패드와 바닥판 벽의 간섭 |

총 **2개 파지 시도, 9개 사건 기록**이다. 종료 선언은 로봇 동작이 아니므로 사건 수에 넣지 않았다.

첫 후보의 패드 최하단 예상 위치는 소켓 테두리보다 **3.38mm 낮았고**, 수정 후보는 **8.62mm 높았다**. 이것은 접촉 로그의 침투 거리와 별개의 형상 수치다. 원래 장면의 마지막 삽입 기록은 최대 위치 오차 **0.1281mm**, 최소 깊이 **16.1078mm**, 8개 검사 통과였다. 이번에 새로 측정한 값이 아니라 과거 실행의 저장된 값이다.

실제 접근 결과의 `proposed_grasp`도 제안과 일치하는지 검사했다. 그래프에 적힌 제안만 보고 “그 값으로 실제 접근했다”고 가정하지 않는다.

## 5. 성공과 미확인 처리

- 복사 장면만 통과하고 실행 사건이 없으면 실제 실행은 `unknown`이다.
- 사전검사 거절은 실제 집기 실패로 세지 않는다.
- 실행 이벤트는 실행 노드의 반환/예외 처리 뒤에 기록된다. 명령 제출 영수증이나 시작 시각은 기존 로그에 없으므로 `null`이다.
- 실행 노드가 `running`이어도 실패 개수가 늘었다면 `reported_failure`로 저장한다.
- 검증 사건과 수치 결과는 부품·행동·시각으로 연결한다. 삽입은 목표 ID, 지지/해제 등 8개 검사, 위치 오차, 설정에 기록된 목표 깊이와의 일치를 확인한다.
- `recorded_measured_pass`는 과거 수치 검증 근거가 남았다는 뜻이다. 이번 코드에서 새 물리 실행을 통과했다는 뜻이 아니다.
- 그래프 검증만 있고 상세 수치가 없으면 `graph_verified_without_saved_measurements`로 보존한다.
- 시도 결과, 부품 그래프 상태, 설치 목록 반영 여부, 전체 실행 성공/실패를 분리한다.
- 실패한 `decide`에 남아 있는 이전 행동을 새 제안으로 복제하지 않는다.

대표적으로 21M의 post2는 삽입 검증 완료 사건 뒤 API 처리 오류로 중단됐다. 이번 입력 3개 파일에는 해당 수치 결과가 남아 있지 않아 수치 성공 집계에서 제외했다. 다른 LLM 로그에 남은 관측을 연결하는 기능은 이 단계에 포함하지 않았다. 실행 전체가 실패했다는 사실도 그대로 남긴다.

## 7. 재현 명령

프로젝트 루트에서 실행:

```powershell
cd C:\dev\llm-robot-assembly
.\runtime\luna-venv\Scripts\python.exe scripts/export_grasp_experience.py --run-dir runs/step21/20261103T090739_028883Z_46ffab9d --part post_1
```

결과 파일은 `runtime/memory/simulation/grasp_v2/<내용 hash>.json`이다. 처음 저장하면 `created: true`, 같은 입력을 다시 저장하면 `created: false`다. 저장 경로를 바꾸려면 `--output-dir`을 사용하되 원본 실행 폴더와 기존 v1 메모리 루트에는 쓸 수 없다.

전체 프레임 로그의 기둥 전부를 변환하려면 `--part`를 생략한다:

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/export_grasp_experience.py --run-dir runs/step23_frame/20261105T052814_462220Z_48e7b620
.\runtime\luna-venv\Scripts\python.exe -B -m unittest discover -s tests -p test_export_grasp_experience.py -v
```

이전 run 폴더는 Git에 없으므로 새 컴퓨터에서 예제 변환을 하려면 해당 로컬 로그가 필요하다. 합성 로그 테스트는 원본 run 없이 실행 가능하다. 새 패키지 설치나 API 키는 필요하지 않다.

## 8. 범위와 다음 단계

이 단계는 기둥·UR3e/2F-85·MuJoCo의 지원되는 로그 형식을 읽는다. 재개된 실행의 부모 기록 연결, 잘린 JSONL 복구, 모델 응답 ID/비용 로그 연결, 슬리브·덮개, 실물 관측은 아직 지원하지 않는다. 입력 파일은 각각 16MiB까지 읽는다. 읽는 중 원본이 바뀌면 저장하지 않고 다시 시도하도록 오류를 낸다.

`active_part_condition_id`는 해당 부품 설정의 지문이다. 주변 부품과 전체 장면이 같다는 보증이 아니다. 전체 설정과 원본 hash/참조, 남아 있는 설치 상태를 함께 남겼다. 누락된 실행 전 관측은 그래프의 observe 행 참조만 있고 좌표를 재구성하지 않았다.

이 JSON은 아직 Luna에 전달하지 않는다. 자동 교훈·Python 스킬 생성, 스킬 등록, 검색·동결·평가 분할도 후속 단계다. 다음 작은 단위는 현재 상황에 관련된 경험을 제한적으로 검색하는 기능이며, 출처·지원 조건·미확인 여부를 유지한 채 연결해야 한다.
