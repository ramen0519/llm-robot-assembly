# 23I단계: 전체 프레임에서 정책 재계획 한도를 공유하기

작성: 2026-11-01. 규칙 정책과 실제 MuJoCo의 통합 시험이다. 실제 LLM 호출은 0회다.

## 두 기둥에서 전체 부품으로

23H의 전체 재계획 한도를 2기둥에서 기둥·슬리브·덮개까지 확대했다. `--transport-replan-budget`은 전체 작업에서 0~9회, 부품 하나에서는 최대 1회다. 부품이 바뀌어도 전체 잔여 횟수를 다시 채우지 않는다. 정렬 복구는 별도 전체 한도 1회다.

직접 운반 경로가 **실행 전** 접촉 검사에서 거부되면 정책이 새 관측을 받고 `replan_insert` 또는 `stop`을 고를 수 있다. 재계획은 실패를 기록한 당시의 파지·관절·제어 명령·물리 모델·목표·설치물 정보가 유지되는 경우에만 허용한다. 실제로 움직였는지 불확실한 명령을 그대로 다시 실행하지 않는다.

빈 그리퍼 접근 우회는 별도 옵션이다. 물체를 잡은 운반 재계획과 섞어 세지 않는다. 우회 경로는 기존 IK·경로 계획·충돌 검사 코드가 만들고, 규칙 정책은 허용된 스킬을 고른다. LLM이 경로를 계산한 시험이 아니다.

## 실행

```powershell
# 바닥판 + 네 기둥
uv run --locked python scripts/run_frame_assembly.py --parts 5 --mode single --scenario first_alignment_offset --transfer-obstacle --empty-approach-strategy direct_then_rrt --transport-replan-budget 2 --snapshots
# 전체 10개 제품 부품: 고정 바닥판 + 로봇 설치 9개
uv run --locked python scripts/run_frame_assembly.py --parts 10 --mode single --scenario first_alignment_offset --transfer-obstacle --empty-approach-strategy direct_then_rrt --transport-replan-budget 9 --snapshots
```

네 기둥 기록은 `runs/step23_frame/20261101T094505_612205Z_eb62769c`다. 설치 4/4, sim 457.062초, 물리 측정 228,619행, 정책 선택 16회, 운반 재계획 2회, 정렬 복구 1회, API 0회로 성공했다. 최종 검사 최대 위치 오차는 0.1987mm 미만이다.

결과 JSON, 정책 이벤트와 실제 trace를 별도로 대조한 `evidence_audit.json`을 실행 폴더에 저장했다. 최종 `after_cover.png`도 확인했다. 성공 판정은 그림이나 LLM 자체 평가가 아니라 위 물리 측정과 완료 검사에 근거한다.

이 장기 실행은 시작 당시 모듈을 메모리에 불러온 뒤 끝까지 사용했다. 실행 중 다른 준비 작업에서 디스크의 `run_frame_assembly.py`, `insertion_scene.py`, `assembly_graph.py`가 갱신되어 기록된 소스 지문 12개 중 이 3개는 최종 디스크와 다르다. 당시 지문을 덮어쓰지 않았다. 따라서 이 결과를 마지막 커밋과 바이트까지 같은 전체 재실행이라고 주장하지 않는다. 최종 코드의 기본 경로는 아래 두 기둥 회귀 검사로, 새 후보 연결은 [16E 실제 두 기둥 실행](STEP_16E_PLANNER_TO_ROBOT.md)으로 별도 확인했다.

## 검사 범위

부품들은 처음부터 같은 물리 장면에 있고 설치 중 장면을 초기화하지 않는다. 먼저 설치한 부품의 위치·방향·지지·안정성과 로봇·그리퍼·운반 물체·기존 부품의 접촉을 계속 검사한다. 성공은 설치 개수만이 아니라 실제 삽입·해제·후퇴 후 각 결합의 8개 검사와 전체 설치물 검사로 판단한다.

범위 검사에서는 10부품 초기 장면의 설치 수가 0이고 재계획 예산이 9로 시작하는지 확인한 뒤 동작 전에 의도적으로 중단했다. 이 테스트의 초기 배치를 조립 성공으로 세지 않는다. 최종 외부 후보 입력 추가 뒤에도 두 기둥의 전역 한도·설치물 보존·비물리적 상태 변경 금지 검사를 다시 실행해 **1개 PASS**, 130.441초를 확인했다.

이번 전체 실행은 개발자가 정한 기존 프레임 순서를 사용한다. 외부 분해 플래너가 새로 고른 10부품 순서를 실행한 시험과는 다르다. 조건은 한 제품·고정 장애물·지정 실패·seed 3에 한정하며, 임의 조립 일반화와 실물 성공을 입증하지 않는다.
