# 8단계: TCP 목표 위치에서 관절 각도를 역으로 계산하기

이번 단계는 **TCP를 현재 위치보다 위로 30mm 옮기는 관절 각도 계산**이다. 집게의 방향과 손가락 벌림은 유지한다. MuJoCo의 실제 모델로 계산 결과를 확인하지만, 모터로 그 자세까지 이동시키지는 않는다.

## FK, IK, 모션플래닝의 차이

- **FK(순기구학)**: 관절 각도를 알 때 집게 끝의 위치와 방향을 계산한다. 앞 단계의 TCP 좌표 읽기가 여기에 해당한다.
- **IK(역기구학)**: 원하는 집게 끝의 위치와 방향을 주면 필요한 관절 각도를 찾는다. 이번에 구현한 기능이다.
- **모션플래닝(경로 계획)**: 시작 자세에서 목표 자세까지 장애물과 관절 제한을 고려한 이동 경로를 구한다. 목표 관절 각도만 찾았다고 경로까지 검증된 것은 아니다.
- **제어와 도착 판정**: 시간에 따른 관절 목표를 모터에 전달하고 실제 위치·속도로 도착 여부를 확인한다. 앞서 한 관절에서는 구현했지만, 이번 IK 결과를 따라 여러 관절을 움직이는 기능은 다음 단계다.

예를 들어 “TCP를 위로 3cm 올려라”는 명령을 실행하려면 IK로 최종 관절 각도를 구하고, 이동 경로를 검사한 뒤, 모터를 움직이고 실제 도착을 확인해야 한다.

## 이번 목표와 성공 기준

기준 좌표계는 **월드 좌표계**다. 위치 단위는 m, 내부 관절 각도는 rad, 터미널 출력은 읽기 쉬운 도 단위를 사용한다.

```text
초기 TCP: [0.130998, -0.297500, 0.147550] m
목표 TCP: [0.130998, -0.297500, 0.177550] m
차이:     [0.000000,  0.000000, 0.030000] m
```

집게 자체의 Z축은 초기 자세에서 아래를 향한다. 따라서 **월드 +Z로 30mm**와 **TCP의 로컬 +Z로 30mm**는 서로 다른 명령이다. 코드의 `DEFAULT_OFFSET_M`는 월드 좌표에 더하는 값이다.

성공 조건:

- TCP 위치 오차의 길이 1mm 이하.
- TCP 방향 차이 0.5도 이하. X·Y·Z 방향 전체를 유지한다.
- 모델에 설정된 관절 범위 준수. 비교에는 1e-8rad의 수치 허용오차를 둔다.
- 손가락 관절 8개가 초기 열린 각도를 유지. 허용오차 1e-9rad.
- 초기 자세와 각 IK 계산 후보에서 모델이 검출한 접촉이 없어야 함.
- 최대 200번의 계산 안에 수렴해야 함.

“수렴”은 반복 계산의 오차가 정한 기준 안으로 줄었다는 뜻이다. 계산이 실패하면 현재 시작 자세와 설정으로 해를 찾지 못했다고 기록한다. 모든 가능한 자세에서 절대로 도달할 수 없다고 단정하지 않는다.

## 추가한 도구

[공식 Mink 프로젝트](https://github.com/kevinzakka/mink)의 **mink 1.3.0**을 사용한다. MuJoCo 모델을 이용해 작은 관절 변경량을 반복 계산하는 기존 IK 라이브러리다. 라이선스는 Apache-2.0이며 원본 로봇·그리퍼 모델은 수정하지 않았다.

개발 중 실행한 설치 명령은 다음과 같다. 이미 설치했으므로 다시 실행할 필요는 없다.

```powershell
uv add "mink==1.3.0"
```

Mink의 의존성으로 DAQP 0.10.3, qpsolvers 4.13.0, SciPy 1.17.1도 설치됐다. DAQP는 Mink가 만드는 수학적 최적화 문제를 푸는 계산 도구다. MuJoCo 3.17.0은 유지했다. 직접 의존성은 `pyproject.toml`, 전체 버전은 `uv.lock`에 고정했다. 다른 컴퓨터에서는 `uv sync --locked`로 설치한다.

사용한 API는 [공식 tasks/limits 예제](https://github.com/kevinzakka/mink/blob/main/examples/docs/tasks_and_limits.py)를 참고했다. 손가락을 고정하는 `DofFreezingTask`는 약한 선호 조건인 `tasks`가 아니라 반드시 지켜야 하는 조건인 `constraints`에 전달한다.

## 코드와 데이터 흐름

실행 파일은 `scripts/solve_tcp_ik.py`다.

1. `load_robot_with_gripper()`가 기존 UR3e와 2F-85 모델을 초기 자세로 불러온다.
2. `read_tcp_pose()`가 현재 TCP 위치와 방향을 읽는다. 위치에 `[0, 0, 0.03]`을 더하고 방향은 그대로 목표로 지정한다.
3. `solve_tcp_pose()`가 **원래 상태와 별도인** Mink 계산용 상태를 만든다. 원래 `qpos`, `qvel`, `ctrl`, 시간은 바꾸지 않는다.
4. `FrameTask`로 TCP 목표를 설정하고, `ConfigurationLimit`로 관절 범위를 제한한다. `DofFreezingTask`로 손가락 관절을 고정해 팔 관절 6개만 사용한다.
5. `mink.solve_ik()`가 작은 변경량을 계산하고 `integrate_inplace()`가 계산용 관절 각도를 갱신한다. 매 후보에서 관절 범위·고정 조건·접촉과 TCP 정의를 확인한다.
6. `pose_errors()`가 MuJoCo의 순기구학 결과를 읽어 위치·방향 오차를 계산한다. 기준을 만족하면 `IKResult.success=True`, 횟수 제한에 도달하면 `False`를 반환한다. 접촉이나 잘못된 입력은 예외로 거부하며 실행 프로그램은 실패 종료한다.
7. 성공한 경우에만 별도의 정지 뷰어로 최종 자세를 표시한다.

`IK_DT=0.02`와 `VelocityLimit`의 1rad/s는 한 번의 **수치 계산 변경량**을 최대 0.02rad로 제한한다. 물리 시간이나 실제 모터 속도를 뜻하지 않는다. `lm_damping`은 계산을 안정시키기 위한 수치 설정이며 모터 감쇠 계수가 아니다.

이번 입력 방향은 3×3 회전 행렬이다. 공통 에이전트 pose 스키마의 quaternion은 아직 연결하지 않았다. 이후 연결 시 계획서의 `xyzw`와 MuJoCo 내부 `wxyz` 차이를 adapter에서 처리한다.

## 직접 실행

PowerShell에서 다음을 실행한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/solve_tcp_ik.py
```

터미널에는 초기·목표 TCP 좌표, 팔의 관절 각도 6개, 반복 횟수, 최종 오차가 출력된다. 화면의 분홍색 `Start`는 원래 TCP 위치, 노란색 `TCP`는 계산한 최종 TCP다. RGB 화살표는 TCP의 로컬 X·Y·Z축이다. 선은 두 점의 위치 차이를 표시하며 검증된 이동 경로가 아니다. 화면은 정지 상태로 시작하며 직접 창을 닫는다.

창 없이 계산과 검증만 실행한다.

```powershell
uv run --locked python scripts/solve_tcp_ik.py --check
```

5초 후 자동으로 창을 닫으려면 다음을 실행한다.

```powershell
uv run --locked python scripts/solve_tcp_ik.py --seconds 5
```

## 실제 확인한 결과

2026-10-28에 위 수치 검사와 5초 뷰어 실행·정상 종료, 정지 화면 렌더링을 확인했다.

```text
Iterations: 8; stop reason: pose_tolerance
Position error: 0.004801 mm (limit 1 mm)
Orientation error: 0.000023 deg (limit 0.5 deg)
TCP IK calculation: PASS
IK preview closed. Simulation time: 0.000 s
```

주요 관절은 어깨 약 -90.000→-89.518도, 팔꿈치 90.000→81.402도, 첫 손목 -90.000→-81.884도로 계산됐다. 팔꿈치를 굽히는 정도가 달라지는 동시에 손목이 보상하므로 집게 방향을 유지할 수 있다.

다음 명령으로 기존 검사 5개와 신규 IK 검사 4개, 총 9개가 통과했다.

```powershell
uv run --locked python -m unittest discover -s tests -v
```

신규 검사는 별도 MuJoCo 상태에서의 FK 확인·원래 상태 보존, 계산 횟수 부족 시 실패, 좁은 관절 범위를 넘지 않고 실패, 목표와 일치하더라도 바닥 접촉이 있는 자세 거부를 확인한다. 기존 검사에는 실제 시간 적분을 수행하는 그리퍼 물리 동작도 포함한다.

## 검증 범위와 다음 단계

이번 수치는 **가상 모델 안의 IK 계산 오차**이며 실물의 정확도나 조립 정밀도가 아니다. 화면에서 `qpos`를 지정하는 것은 계산된 자세의 정지 미리보기다. `mj_step()`을 호출해 모터가 도달한 결과가 아니므로 물리 이동·파지·조립 성공으로 집계하지 않는다.

접촉 검사는 현재 모델의 충돌 설정에 따라 초기 자세와 계산 후보에서 검출된 접촉만 확인한다. 충돌을 피해 경로를 찾는 기능은 없으며 후보 사이 연속 구간, 실제 제어 중 경로, 장애물 여유 거리, 실물 충돌 형상의 정확성을 보장하지 않는다. 물체는 아직 없고 명목 열린 그리퍼만 지원한다.

다음 작은 단계는 **계산된 팔 관절 목표를 구동기에 천천히 전달하고, 실제 TCP 도착 오차와 속도·이동 중 접촉을 확인하는 것**이다. 이 단계가 끝나야 물체 접근과 파지 동작을 이어갈 수 있다.
