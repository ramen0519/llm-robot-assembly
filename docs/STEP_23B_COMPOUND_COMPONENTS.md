# 23B단계: 구멍이 있는 부품과 덮개를 실제 접촉으로 조립하기

작성: 2026-11-01. 실물은 사용하지 않았다. 이 문서는 개별 결합과 다부품 장면의 개발 기록이며, 전체 10부품 연속 성공은 별도로 확인한다.

## 제품과 부품 수

개발용 제품은 바닥판 1개, 사각 기둥 4개, 기둥에 끼우는 슬리브 4개, 덮개 1개로 총 10개다. 슬리브는 가운데 구멍이 있는 짧은 사각 관이라고 생각하면 된다. 바닥판은 작업 시작 전에 고정하고 로봇이 나머지 9개를 조립한다. 덮개 위 손잡이는 덮개와 한 몸이며 별도 부품으로 세지 않는다.

이번 형상은 조립 시스템을 개발하기 위한 후보다. 기어가 작동하는 제품이나 최종 제작 설계를 완료했다는 뜻은 아니다. 구멍 24mm와 기둥 20mm 사이에는 한쪽 2mm 여유가 있다. 정밀 끼워맞춤·나사 체결·임의의 CAD 조립은 아직 지원하지 않는다.

## 화면에 구멍이 보이는 것과 실제로 통과하는 것은 다르다

물리 계산에서 속이 빈 부품을 하나의 볼록한 덩어리로 처리하면 구멍이 메워진 것처럼 충돌할 수 있다. 그래서 슬리브는 네 개의 막대, 덮개와 바닥판은 구멍 주변의 여러 직육면체로 구성했다. 인접한 실체 영역은 합쳐 불필요한 접촉 개수를 줄였다. CAD의 부피와 열린 구멍은 유지한다.

실제 낙하 시험에서 속이 빈 슬리브는 고정된 측정용 기둥을 통과하고, 구멍을 채운 대조 물체는 위에 걸리는 것을 확인했다. 이 시험은 구멍의 충돌 형상 검사이며 로봇 조립 성공으로 세지 않는다.

## 로봇이 하는 일

`FrameSkills`는 기존의 검증된 집기와 삽입 코드를 재사용한다.

1. 대기 부품이 안정됐는지 확인한다.
2. 파지점 위로 이동하고 천천히 내려간다.
3. 양쪽 손가락 접촉을 확인하고 실제 마찰로 들어 올린다.
4. 결합 위치 위로 옮겨 위치·방향 오차를 확인한다.
5. 허용된 상대 부품과의 접촉만 허용하고 내린다.
6. 깊이를 확인한 후 그리퍼를 열고 물러난다.
7. 위치·방향·깊이·지지·속도가 기준을 만족하는지 검사한다.

슬리브는 자기 기둥이 먼저 조립되어 있어야 집을 수 있다. 덮개는 기둥과 슬리브 8개가 모두 조립되어 있어야 한다. 부품을 순간이동시키거나 그리퍼에 강제로 붙이지 않는다. 모든 제품 부품은 전체 실행의 시작부터 존재하며 바닥판 외에는 자유 물체다.

## 검사에서 바꾼 점

넓은 부품은 지지력이 여러 접촉점으로 나뉜다. 접촉점 하나의 힘만 보고 지지 여부를 판단하던 코드를, 지정된 지지면에서 발생한 수직 방향 힘의 합으로 판정하도록 바꿨다. 힘이 있는 접촉이라는 근거는 계속 필요하다. 허용 접촉점의 최대 법선력 제한은 기존처럼 8N이고, 이 값은 부품 전체 힘의 합이라고 해석하지 않는다.

이전 부품도 매 물리 표본에서 확인한다. 위치 1mm, 방향 1도, 지지 상태 기준은 작업 중에도 유지한다. 접촉 중 결합 상대만 선속도 10mm/s·각속도 0.1rad/s 이내의 일시적 움직임을 허용한다. 다른 대기 부품에는 이 예외를 적용하지 않는다. 마지막 `insert_verify` 구간에는 모든 부품에 다시 선속도 1mm/s·각속도 0.01rad/s 이하의 정지 기준을 적용한다.

이 구분은 덮개 하강 중 실제 슬리브의 위치 오차 0.028mm, 각속도 0.012rad/s가 검출된 뒤 도입했다. 위치를 벗어난 부품, 과한 속도, 마지막에 흔들리는 부품을 통과시키는 변경은 아니다. 이러한 반례를 별도 검사한다.

## 설계 실패를 보존한 이유

- 덮개 가장자리 파지 시험은 들어 올릴 때 `PART_LOST`가 발생했다. 손잡이를 중심으로 옮겼다. 이것은 제품 설계 수정이며 에이전트의 자동 복구 성공이 아니다.
- 두 번째 슬리브의 뒤쪽 투입 위치는 팔과 그리퍼 사이의 자기 충돌이 경로 검사에서 검출됐다.
- 앞쪽으로 옮긴 첫 후보도 IK가 수렴하지 않았다. 5cm 안쪽으로 조정해 다시 검증한다.
- 덮개 접촉 중 순간 움직임으로 멈춘 기록도 남긴다. 이미 실패한 기록을 코드 수정 뒤 성공으로 바꾸지 않는다.

## 실행

```powershell
cd C:\dev\llm-robot-assembly
# 개별 결합 시험: 다른 부품은 시험 초기 조건으로 미리 조립
uv run --locked python scripts/run_component_probe.py --component sleeve_1 --snapshots
uv run --locked python scripts/run_component_probe.py --component cover --snapshots
# 모든 부품을 시작 위치에서 연속으로 조립
uv run --locked python scripts/run_frame_assembly.py --parts 10 --mode roles --scenario first_alignment_offset --snapshots
```

개별 결합 시험은 로봇이 실제 설치한 부품을 **1개**로 기록한다. 미리 준비한 부품을 로봇의 조립 실적으로 세지 않는다. 전체 실행의 `ten_part_assembly_complete`는 9개를 모두 설치하고 최종 상태를 확인했을 때만 true가 된다.

`--mode roles`는 현재 역할을 분리한 **규칙 정책**이다. LangGraph의 인계와 검증을 실행하지만 LLM API를 호출하지 않는다. 단일/다중 LLM 성능 비교가 완료됐다고 해석하면 안 된다.

## 파일과 한계

- `frame_assembly_scene.py`: 부품별 시작 위치, 목표, 파지점, 선행 조건, 접촉 관계.
- `frame_assembly_skills.py`: 복합 형상의 파지·삽입과 이전 부품 보존 검사.
- `run_component_probe.py`: 하나의 결합을 진단하며 초기 조립 부품을 명시.
- `run_frame_assembly.py`: 같은 물리 상태에서 여러 부품을 순서대로 설치하고 전체 결과 기록.

현재 제품 순서와 결합 정보는 설정에 있다. 외부 분해 플래너로 이 제품의 순서를 생성한 결과는 아직 연결하지 않았다. 경로는 Mink IK와 지역 중간점 경로이며, 임의 장애물을 우회하는 전역 계획기는 아니다. 위치·파지·지원 형상이 달라지면 새 물리 검증이 필요하다.
