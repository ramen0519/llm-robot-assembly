2026-11-11 · 개발용 10부품 프레임 · MuJoCo · UR3e와 Robotiq 2F-85 · Astra 단일 에이전트, 추론 강도 high

**결과 — 기둥 복구 후 같은 장면에서 슬리브까지 2/2 설치.** 성공 회차는 `runs/step23_frame/20261111T044515_041115Z_d2503821`이다. 해당 폴더의 `post_then_sleeve.png`는 두 부품의 설치 직후 저장한 물리 상태를 같은 카메라로 렌더링한 이미지다.

## 실험 질문

기둥을 잡을 수 있어도 그 위치로 계속 잡고 있으면 끼우는 도중에 손가락이 바닥판에 걸릴 수 있다. 조립 중에 이런 실패를 사전검사로 발견했을 때, 에이전트가 이전에 만든 스킬을 검색해 현재 상태에 적용하고, 같은 장면의 다음 조립 목표까지 수행하는지 확인한다.

전체 프레임의 고정 바닥판과 자유 부품 9개를 모두 장면에 둔다. 이번 회차의 설치 목표는 `post_1 → sleeve_1`이다. 슬리브는 첫 기둥이 설치되어야 끼울 수 있어서 연속 조립 여부를 확인할 수 있다. 이 시나리오에서는 첫 파지 높이를 기둥 중심 기준 +1 mm로 주며, 접촉 판정·복구 파지값·슬리브 파지값은 실행 중에 결정한다.

## 각 판단은 누가 했나

| 순서 | 담당 | 입력과 결과 |
|---|---|---|
| 1. 첫 후보 검사 | MuJoCo | 현재 장면 사본에서 +1 mm로 집고 삽입 경로를 검사한다. 접촉한 물체, 검사 단계, 파지 상태를 기록한다. |
| 2. 검색 | LangGraph와 Astra | 실제 거절 후 원래 장면을 재관측한다. Astra가 검색어를 작성하고, 검색 결과에서 읽을 문서와 사용할 스킬을 선택하거나 보류한다. |
| 3. 파지값 계산 | 등록된 스킬 코드 | 적용 조건과 증거를 대조하고, 이번 실패의 기하 측정값을 넣어 새 파지값을 계산한다. 저장한 ID로 명령을 즉시 실행할 수 없다. |
| 4. 기둥 설치 | 기존 검사·실행 노드 | 새 후보로 집기부터 해제까지 다시 사전검사한다. 현재 관측 및 파지값이 일치하면 원래 장면에서 로봇이 실제로 잡고 설치하고, 물리 검증기가 판정한다. |
| 5. 슬리브 설치 | Astra와 기존 조립 노드 | 같은 장면에서 슬리브의 형상·현재 자세를 읽고 파지 위치·방향을 제안한다. 설치 후 기둥이 슬리브 양쪽 구멍을 모두 통과하는지 검사한다. |

조립과 검색은 같은 API 호출·토큰·비용 한도를 사용한다. 등록 스킬의 적용 범위는 빈 바닥판의 첫 기둥과 확인된 패드–벽 간섭이다. 다른 부품과 다른 종류의 실패에는 기존 조립 정책이 적용된다.

## 첫 기둥에서 확인한 값

- `insert_lower/preflight`에서 오른쪽 손가락 패드와 소켓 벽이 겹쳤다. 첫 후보의 패드에서 소켓 테두리까지의 예상 여유는 −2.37 mm였다. 이 값은 잡은 자세를 목표 깊이까지 내렸다고 가정한 계산값이다.
- Astra의 검색어는 `post insert_lower PLANNED_CONTACT pad wall grasp`였다. 과거 실패 경험과 검증된 스킬을 모두 읽고 한 스킬을 선택했다. 저장된 함수는 새 관측으로 기둥 중심 기준 파지 높이 +4.37 mm를 계산했다. 이 후보의 예상 여유는 +1.00 mm였다.
- 두 후보를 검사한 전후의 원래 시뮬레이션 상태와 제어기 상태가 일치했다. 원래 장면에서 기둥을 집고 설치한 뒤 최종 검증 구간의 최소 삽입 깊이는 16.108 mm(목표 16 mm), 최대 위치 오차는 0.121 mm였다.

첫 실행 `20261111T044115_065780Z_47280946`에서는 스킬 선택과 파지 계산까지 수행한 뒤, 선택 기록과 계산 결과를 같은 이름으로 새로 저장하려다 집기 전에 중단했다. 두 파일을 분리하고 회귀 검사를 추가했다. 이 회차의 추정 비용은 $0.062875였고, 수정 후 회차에는 $0.63의 별도 상한을 적용했다.

## 코드와 검사

- 조립 실행기는 전체 작업대의 물체를 유지하며 목표 부품의 선행조건을 검사한다. 발생을 재현한 시나리오에서는 스킬 선택 기록, 재검사를 통과한 파지값, 원래 장면에서 로봇에 전달한 값이 모두 일치해야 기둥 복구를 인정한다. [조립 실행기](../scripts/run_frame_assembly.py)

- 스킬 검색, 문서 열람, 선택 영수증은 조립 API 원장과 연결된다. 검색 로컬 호출 수와 회차 누적 호출 수를 모두 기록한다. [스킬 선택기](../scripts/grasp_skill_selector.py)
- 그래프 분기, 공용 예산, 선택 기록 분리, 목표 순서·파지값 대조, 기존 조립·메모리·재개 경로를 포함한 관련 자동 검사 **37개**가 통과했다. 위의 Astra와 MuJoCo 통합 실행은 별도로 수행했다.
