# 22P · 조립 에이전트와 복구 에이전트의 인계

**2026-11-11 라이브 검증 완료.** 두 에이전트가 Astra high를 실제 호출한 새 MuJoCo 회차에서 기둥 4개, 슬리브 4개, 덮개 1개를 한 장면에 설치했다. 9/9개 설치, 복구 왕복 4회, 모델 생성 23회, 추정 비용 $1.20374.

**먼저 수행한 무과금 검증.** 22O에서 Astra high가 내린 결정을 재생해 새 무조코 장면에서 첫 기둥 복구부터 덮개까지 9/9개를 설치했다. 이 재생 시험의 실제 API 호출은 0회, 비용은 $0였다.

같은 프레임, 같은 외부 조립 순서, 같은 Astra high 설정과 무조코 실행기를 유지하고 판단을 두 에이전트로 분리했다. 조립 에이전트는 현재 부품의 파지와 삽입을 제안한다. 복구 에이전트는 관측된 실패와 인계 기록을 받아 스킬을 검색하거나, 수치 파지를 수정하거나, 작업을 중단할 수 있다. 두 에이전트의 모델 호출과 비용은 하나의 실행 예산에서 차감한다.

## 첫 기둥의 제어권은 언제 넘어가나

1. 개발 시나리오에서 첫 기둥의 파지 높이를 중심 기준 +1 mm로 준다. 무조코 사전검사에서 실제로 패드–소켓 벽 간섭이 검출된 경우에만 해당 스킬을 검색할 수 있다.
2. LangGraph가 원래 장면을 다시 관측하고 **조립 → 복구**를 기록한다. 실패 부품, 실패 단계, 거절 파지, 현재 관측 번호와 물리 상태의 식별값이 함께 전달된다.
3. 복구 에이전트가 검색어를 작성하고, 찾은 문서에서 읽을 자료와 적용할 스킬을 선택한다. 스킬 코드는 이번 실패의 예상 여유를 사용해 새 파지값을 계산한다. 검증된 스킬을 찾지 못해 보류하면 이유와 함께 멈춘다.
4. 새 파지의 사전검사를 통과한 뒤, 같은 원래 장면에서 집어 들어 올리고 양쪽 손가락의 접촉과 유지 상태를 검사한다. 이 검사가 통과해야 **복구 → 조립**으로 인계한다.
5. 조립 에이전트는 현재 관측과 인계 증거를 받아 기둥 삽입을 결정한다. 이후 부품도 같은 장면을 이어받는다. 다른 부품에서 수정 가능한 수치 파지 실패가 발생하면 복구 에이전트가 현재 부품의 접촉 정보로 새 좌표를 제안할 수 있다.

## 두 에이전트가 실제 모델을 호출한 회차

라이브 실행 폴더는 `runs/step23_frame/20261111T094837_356839Z_dfd0a272`다. 22O와 같은 외부 ASAP 조립 후보, 초기 배치 및 스킬 저장소로 새 장면을 시작했다. 실제 모델은 두 역할 모두 Astra high이며 검색과 조립 요청이 같은 $1.50 한도를 공유한다. 첫 기둥의 +1 mm는 접촉 실패를 재현하기 위해 지정한 시나리오 입력이다.

첫 기둥에서 복구 에이전트가 직접 만든 검색어는 `post insert_lower preflight PLANNED_CONTACT pad socket wall clearance grasp`였다. 검색, 문서 열람, 스킬 선택에 각각 1회씩 호출했다. 선택한 코드가 새 관측으로 파지 높이 +4.37 mm를 계산했다. 원래 장면에서 기둥이 99.474 mm 들린 31.518초에 조립 에이전트가 인계를 받아 삽입했다.

추가로 슬리브 1·2·4에서 집는 중 패드와 작업대의 접촉이 예상되어 복구 에이전트가 직접 파지 높이를 수정했다. 슬리브1은 −5 → +12 mm, 슬리브2는 −7 → +10 mm, 슬리브4는 −5 → +5 mm였다. 세 부품 모두 새 파지를 검사하고 원래 장면에서 집은 뒤, 조립 에이전트가 인계 기록을 받아 삽입했다. 슬리브3은 처음 제안한 +10 mm로 통과했다. 이 회차는 모델별·역할별 성능 비교 실험의 반복 표본으로 사용하지 않았다.

| 역할 | 실제 생성 호출 | 입력 토큰 | 출력 토큰 | 출력 중 추론 토큰 | 추정 비용 (USD) |

- 실제 생성 응답 23개를 그래프의 결정과 대조했다. 모든 요청은 Astra high였고 응답 ID는 22O에서 사용한 ID와 겹치지 않았다. 복구 역할의 6회는 첫 기둥의 검색·열람·선택 3회와 슬리브 1·2·4의 수치 수정 각 1회다. 과금 추정치는 실제 응답 사용량과 프로젝트 설정 단가로 재계산했다. 입력 계수 요청은 별도 23회, 미정산 요청은 0회였다.
- 네 차례의 복구 → 조립 인계를 해당 시각의 물리 기록과 대조했다. 모든 경우에 그리퍼 양쪽 패드가 접촉하고 부품이 작업대에서 떨어져 있었다. 첫 기둥의 인계 순간 패드 간격은 **19.802 mm**, 부품 바닥의 높이는 **99.474 mm**였다.
- 플래너가 정한 `post_1 → sleeve_1 → post_2 → sleeve_2 → post_3 → post_4 → sleeve_4 → sleeve_3 → cover` 순서를 모두 실행했고, 8번의 부품 전환에서 전체 물리 상태가 이어졌다. 덮개는 중앙 손잡이를 부품 중심 기준 +10 mm에서 잡는 첫 후보로 통과했다.
- 저장된 마지막 상태를 따로 복원해 모든 결합을 다시 검사했다. 최종 위치 오차의 최댓값은 **0.212 mm**, 최소 측면 여유는 슬리브 구멍 **1.754 mm**, 덮개 구멍 **1.796 mm**였다. 덮개가 슬리브 1~4에 전달한 수직 하중은 각각 **0.250, 0.168, 0.164, 0.218 N**이었다.
- 시뮬레이션 경과 **1,035.038초**, 실제 실행기 경과 **1시간 58분 10초**, 물리 기록 **517,699행**. 회차 폴더의 `live_role_audit.txt`는 독립 검증 결과, `live_measurements.json`은 인계 시각과 측정값, `native_assembly_stages.png`는 해당 회차의 세 설치 시점이다.
