# STEP 47 · 배터리 재시험 전 공통 실행 프로토타입

2026-11-26. 이번 작업은 배터리를 다시 실행하지 않고, 공통 프로그램의 빠진 연결을 보완하는 작업이다. 기준 HEAD는 `cf8add83cb2704c61ab4dc928119fb5276f1d33f`, 작업 브랜치는 `codex/general-mesh-v2`이다. 기존 미커밋 변경은 보존했으며 새 commit/push는 하지 않았다.

## 무엇을 연결했나

사용자는 제품의 목표 CAD 묶음 또는 분해 전달 결과를 넣는다. 공통 준비기가 단위·원본 해시·완성 위치·충돌 자산·초기 배치를 확인한다. 파지와 설치를 복사 장면에서 검사한 뒤, 주 장면에서 실제 접촉·마찰로 움직인다. 완료 검사가 통과해야 설치로 집계한다. 실패한 뒤 실제 설치까지 해결되고 최종 장면에서 유지된 사례만 다음 실행의 지침 후보가 된다.

### 오래 걸리는 한 동작을 이어가기

`assembly_v2/continuation.py`와 `MeshSkills.move`가 한 동작의 실행 시간을 나누어 관리한다. 기본값은 동작 실행 구간 60초, 같은 목표로 재계획 최대 2회다. 전체 실행 예산은 늘어나지 않는다.

- 이 작은 구간의 시간만 초과한 경우 현재 위치·속도·접촉·최초 파지의 미끄러짐을 다시 확인한다.
- 현재 상태를 그대로 둔 채 원래 목표까지 경로를 다시 검사한다. 상태를 되돌리거나 부품을 목표로 옮기지 않는다.
- 사용자 취소, 전체 시간 초과, 물리적 충돌은 단순 시간 구간 만료와 구분한다. 무조건 재시도하지 않는다.
- `continuations.jsonl`, 중단 상태와 컨트롤러 정보를 저장한다. 이 동작은 Python의 제한된 실행 기능이며 모델 판단으로 기록하지 않는다.

프로세스가 종료된 뒤 새로운 시간·비용을 자동으로 부여해 재개하는 기능은 아니다. 최종 중단 상태를 보존하고 원인을 반환한다.

### 놓은 뒤에는 다시 집지 않기

`begin_release`가 실제 놓기 시작 시점과 그때의 벌림 폭을 기록한다. `finish_release`는 벌리기·후퇴·완료 관찰 중 남은 동작을 수행한다. 원 CAD 목표가 바뀌었거나 부품이 허용 위치·각도를 벗어나면 재개하지 않는다. 조립/복구 역할은 이 상태에서 `finish_release` 또는 중단을 제안할 수 있다. 원래 파지 변환을 임의로 다시 만들지 않는다.

기존 전체 동작과 새 해제 동작 모두 동일한 물리 검사를 사용한다. 여러 부품 시험에서 full-open 해제 중 이웃 기둥 접촉이 확인되어, 개발 정책도 이 복사 검사 실패에 한해 제한된 벌림·후퇴 계획을 새로 제안하도록 연결했다. 실제 Astra에는 같은 선택지를 조언하며 선택과 모든 재검사는 그대로 모델/실행기 역할에 둔다. 종료 시에는 성공·실패와 무관하게 마지막 상태를 저장한다. 저장 오류가 원래 물리 실패를 덮어쓰지 않게 했다.

### 실패 기록과 다음 실행의 검색

- 실패·취소로 끝나도 `incidents.json`, `guidance_candidates.json`과 종료 근거를 남긴다.
- 검색 조건의 행동은 **실패했던 행동**을 사용한다. 다음에 하려는 복구 행동으로 조건이 바뀌어 과거 경험을 놓치는 문제를 수정했다.
- 실제 Astra 경로에서는 기존 모델이 지침을 작성한다. 미실행 행동·실패한 행동의 수치를 성공한 해법으로 등록하지 못한다.
- API 없는 연결 검사에는 명시적 `--development-learning`을 추가했다. 실제 실패와 실제 설치 기록에서 이미 수행한 파지값·제한된 동작 계획만 복사한 사실 기반 개발 지침을 생성한다. 이것은 LLM 생성이 아니다.
- 위 옵션은 `scripted`, `development`, 별도 메모리 디렉토리에서만 허용한다. 연구 수집·평가나 기본 공유 메모리에는 넣지 못한다.
- `memory_use.json`은 검색됨, 재검사 실패, 실제 사용 후 최종 설치 유지 등을 구분한다. 검색되었다는 사실만으로 효과나 인과관계를 주장하지 않는다.

### 입력·초기 배치와 파지 후보 보완

실제 시험에서 기존 안정 자세 순위가 긴 기둥을 무조건 눕혀, 집을 때와 설치할 때 필요한 손 방향이 달라지는 문제를 확인했다. 기존 확률 값은 무작위로 떨어질 때의 자세 확률이지, 작업대에 놓은 뒤 버틸 확률이 아니다.

현재는 원 메시 받침면의 볼록 다각형과 무게중심으로 지지 여유를 계산한다. 받침면 경계까지 3mm 이상이고 최소 전도각 10도 이상인 후보에서는 목표와 회전 차이가 작은 자세를 우선한다. 이런 후보가 없으면 기존 안정 자세 순위를 사용한다. 이는 초기 후보 선택 기준이며 실제 정착 성공은 MuJoCo가 따로 판정한다. 완료 기준은 완화하지 않았다.

파지 후보에는 설치했을 때 예상되는 TCP 방향도 포함한다. 개발 정책은 현재 자세의 top 파지에만 고정하지 않는다. Astra에는 기하학적 힌트를 제공할 뿐 선택을 강제하지 않는다. 이 힌트는 실제 파지 상대변환, IK, 경로, 접촉 검사를 대신하지 않는다.

### 사용자 화면과 모델 응답 처리

UI에 설치 개수·현재 부품·주 장면/복사 검사·판단 주체·등록 수를 쉬운 문장으로 표시했다. 자세한 원본 기록도 유지한다. 실행기·결과·영상은 CLI와 공통이다.

Astra가 허용되지 않는 행동 형식으로 응답한 경우, 결산된 동일 모델 이력에 거부 이유를 넣어 한 번만 재요청한다. 같은 예산·이력을 공유하며 알 수 없는 과금 오류를 재시도하지 않는다. 이번 작업에서는 이 부분을 계약 검사로만 확인했고 실제 Astra를 호출하지 않았다.
