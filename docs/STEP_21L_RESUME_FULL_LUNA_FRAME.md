# 21L · 실패 이력과 물리 상태를 보존하며 전체 Luna 조립 재개

**검증 중단 (2026-11-05).** 재개 실행 runs/step23_frame/20261105T043034_373981Z_418b3b58은 7개 설치를 기록한 뒤, 슬리브 4의 pick/insert를 마친 다음 완료 응답 요청이 APITimeoutError로 실패했다. 전체 성공은 아니다. 생성 요청 누적 32회 중 1회의 사용량이 불명확하다. 알려진 추정 비용은 $0.010577625, 미확정 예약액은 $0.002524다. 앞 실행의 14회 비용을 포함하므로 중복 합산하지 않는다. 덮개는 시작하지 않았다. 이후 물리 검증 직후 완료하는 구조로 보완한다.

## 이번 단위의 목표

빈 바닥판에서 시작한 10부품 프레임 작업을 끝까지 마친다. 바닥판은 고정하고, 기둥 4개·슬리브 4개·덮개 1개는 로봇이 접촉·마찰로 집어 설치한다. 이번에는 21K에서 세 기둥을 설치한 후 중단된 **같은 물리 상태**를 이어간다. 서로 다른 시험에서 성공한 부품 수를 합산하는 방식이 아니다.

Luna는 각 부품 기준 파지 X·Y·Z(mm), 손가락 닫힘 각도(도), pick/insert/finish 또는 stop을 제안한다. 위에서 접근하는 조건과 요청한 기둥 1~4 → 슬리브 1~4 → 덮개 순서는 고정이다. 조립 순서 발견이나 외부 분해 플래너 호출은 이번 시험에 포함하지 않는다.

## 수정한 원인과 좌표 설명

21K 실행 runs/step23_frame/20261105T030121_883788Z_80d0f9b2는 네 번째 기둥의 파지 후보 3개가 모두 거절되어 stopped로 끝났다. 부품 중심 파지 (0,0,0,0)는 바닥판 구멍 벽에 간섭했고, 이후 (-10mm 높이, 45도)와 (-10mm 높이, 0도) 후보도 거절되었다. 이전 세 기둥은 설치 상태로 남았다. 총 생성 요청 14회, 설정 단가 기준 비용 $0.00454225다.

입력에는 부품의 +Z가 위쪽이라는 설명과, 아래를 향하는 TCP의 +Z 축에 관한 패드 치수 설명이 함께 있었다. Luna는 위로 옮긴다고 설명하면서 음수 높이를 제안했다. post_grasp.py의 도구 입력 설명과 openai_policy.py의 지시에서 **파지 좌표는 부품 기준이며, z_mm을 늘리면 위로 움직인다**는 구분을 명시했다. 특정 성공 파지점이나 정답 목록을 주지는 않는다. 좌표 설명을 보완해도 제안은 반드시 MuJoCo 검사를 거친다.

## 안전하게 이어갈 수 있는 범위

frame_resume.py와 run_frame_assembly.py의 --resume-run은 다음 조건에서만 작동한다.

- 같은 부품·결합·장면 설정, MuJoCo 버전과 모델 지문을 사용한다.
- 앞 부품들의 성공 결과와 부품 경계 상태가 연속이어야 한다.
- 현재 부품은 후보 3개가 모두 거절되어 멈췄고, 실제 pick/insert를 실행하지 않은 상태여야 한다.
- 저장 상태가 손상됐거나 관측을 정확히 재현하지 못하면 모델 요청 전에 거부한다.
- 동일 부품에서 이 재시도는 한 번만 허용한다. 기존 3개 실패를 전달하고 추가 후보는 최대 3개다.
- API 요청·토큰·비용과 전체 상한은 이전 기록에서 그대로 이어받는다. 사용량을 모르는 요청이 있거나 비용과 로그가 맞지 않으면 재개하지 않는다.

이전 21K는 마지막 성공 부품의 mjSTATE_INTEGRATION 전체 배열을 저장했지만, 이후 중단 시점의 배열은 저장하지 않았다. 따라서 세 번째 기둥 종료 상태를 정확히 복원한 후 **기록된 3초 정지 유지 동작만** 재현했다. 그 결과의 전체 보고 관측이 이전 중단 기록과 정확히 일치함을 확인했다. 불확실한 집기나 삽입은 재실행하지 않았다. 새 코드는 이 종류의 중단 시점도 전체 상태로 저장한다.

이는 시뮬레이션 전용 기능이다. 재개 구간에는 설치물 3개가 있지만, 앞 실행의 빈 바닥판부터 이어지는 물리 기록·사진·API 기록과 상태 지문을 함께 보존한다. 결과의 resume, segment_execution_order, segment_wall_elapsed_s와 초기 설치 목록으로 구간을 구분한다. 멈춤 없이 한 프로세스에서 끝난 실행으로 표기하지 않는다.

테스트 API는 메모리 안의 가짜 응답이며 실제 Luna 성공으로 계산하지 않는다. 실행 중 LLM이 새 Python 동작 코드를 만드는 기능도 아니다. 기본 스킬과 검증 도구는 기존 실행 코드다.

## 실행

기존 환경과 OPENAI_API_KEY가 준비된 PowerShell에서 새 빈 장면으로 시작하려면:

```powershell
cd C:\dev\llm-robot-assembly
.\runtime\luna-venv\Scripts\python.exe scripts/run_frame_assembly.py --parts 10 --mode single --llm-config runs/step21k-budget.toml --transport-strategy direct_then_rrt --snapshots
```

이번 중단 상태에서 이어간 명령:

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/run_frame_assembly.py --parts 10 --mode single --llm-config runs/step21k-budget.toml --transport-strategy direct_then_rrt --snapshots --resume-run runs/step23_frame/20261105T030121_883788Z_80d0f9b2
```

로컬 설정 runs/step21k-budget.toml은 키를 포함하지 않으며, 모델 gpt-6-luna·전체 생성 50회·전체 토큰 300,000·추정 비용 $0.15의 상한을 둔다. 재개 전 14회도 이 한도에 포함된다. 다른 컴퓨터에서는 config/llm.example.toml을 기준으로 활성화한 모델·단가·예산 설정을 준비한다. --viewer를 추가하는 새 실행은 모델을 다시 호출한다. 저장한 사진·기록 확인에는 추가 호출이 없다.

## 마지막 검증과 남은 범위

손을 뗀 뒤 덮개 네 구멍에 대한 각 기둥의 관통, 네 슬리브 각각의 덮개 지지력, 기존 설치물의 위치와 방향, 네 슬리브의 기둥 관통을 현재 장면에서 검사한다. 최종 검사 자체가 적분 상태를 바꾸지 않는지도 확인한다. TCP가 도착했다는 이유만으로 조립 성공으로 처리하지 않는다.

실행기는 Mink IK, 관절 제어, 기존 RRT-Connect를 사용한다. direct_then_rrt는 허용된 접근·운반 구간의 모션 계층 우회이며, LLM의 별도 작업 재계획과 구분한다.

현재는 정해진 CAD·결합 치수·초기 배치와 시뮬레이터 정답 상태를 사용한다. 처음 보는 임의 조립품, 카메라 인식, 다중 LLM 비교, 실물 동작을 검증한 결과는 아니다. 같은 부품의 실패 이력은 전달하지만 이전 부품의 성공 파지를 다음 부품의 스킬·메모리로 자동 학습시키지는 않는다. 기존 동결 지식 묶음도 이번 전체 실행에서는 사용하지 않았다.
