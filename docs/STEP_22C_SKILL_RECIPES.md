# 22C단계: 경험에서 절차 후보를 만들고 별도로 물리 검증하기

작성: 2026-11-01. 이번 단계는 LLM 없이 제한된 형태의 절차 축적 과정을 구현했다.

## 메모리와 스킬을 이번 코드에서 구분하면

메모리는 “이 조건에서 정렬이 6mm 틀어졌고, 재정렬 후 실제 삽입에 성공했다”라는 **과거 사건**이다. 원본 실행과 실패·측정 근거의 지문을 함께 저장한다.

이번에 추가한 절차 후보는 “같은 조건에서 이 실패가 나면 `recover_alignment` 다음에 `insert`를 사용할 수 있다”라는 **다시 실행할 절차의 데이터**다. JSON으로 단계와 적용 조건을 저장한다. 자연어 설명만 믿고 실행하거나 새 Python 코드를 생성하지 않는다. 각 단계의 실제 움직임은 이미 구현된 스킬 함수가 맡는다.

```json
{
  "status": "candidate",
  "trigger_failure": "ALIGNMENT_OUT_OF_TOLERANCE",
  "steps": ["recover_alignment", "insert"],
  "generation_method": "fixed_template_from_recorded_sequence",
  "contains_generated_python": false
}
```

위 예시는 설명용 일부 필드다. 실제 파일에는 조건 지문·원본 경험 ID·후보 ID도 있다. 현재 생성기는 성공 기록에서 정해진 두 단계 형식을 추출하는 코드다. LLM이 새로운 복구 방법을 발명했거나 학습했다고 표현하지 않는다.

## 후보가 곧 실행 가능한 검증 스킬은 아니다

1. 성공 경험에서 해당 순서가 실제로 기록됐는지 확인해 `candidate`를 만든다.
2. 새로운 MuJoCo episode를 만든다. 이전 실행의 최종 자세를 복사해 성공 상태를 만들지 않는다.
3. 같은 6mm 오정렬을 발생시키고, 후보를 읽는 정책이 재정렬과 삽입을 선택한다.
4. 각 명령은 기존 LangGraph의 현재 관측·허용 스킬·복구 예산·물리 검사를 통과한다.
5. 실제 삽입과 해제·후퇴 후 판정이 성공한 경우에만 `sim_validated_for_recorded_case`로 등록한다.

검증 중 실행 코드나 모델 파일이 바뀌면 등록을 거부한다. 등록된 후에도 코드(외부 경로 계획기 소스 포함), 로봇 모델/메시, 의존성 잠금 파일이 바뀌면 이전 등록본은 검색 결과에서 제외한다. 현재 방식은 보수적이어서 관련 없는 실행 스크립트 수정도 재검증을 요구할 수 있다.

한 번 통과한 범위는 **첫 기둥·지정된 환경·6mm 오정렬 사례**다. 10부품 전체, 새 형상, 다른 실패, 실물에서 통하는 범용 스킬로 승격하지 않는다. 현재 그래프의 허용 행동과 예산이 우선하며, 등록본이 있어도 이미 예산을 썼으면 멈춘다.

## 저장 위치와 실행

OneDrive 밖의 `C:\dev\llm-robot-assembly\runtime\skills\simulation`에 저장한다.

- `candidates`: 경험에서 추출한 절차 후보.
- `validated`: 새 물리 실행을 통과한 제한된 등록본과 증거 위치.
- 실제 물리 검증 로그: `runs/step22_recipes/<run_id>`.

```powershell
uv run --locked python scripts/skill_recipes.py create --experience <성공경험_JSON_경로>
uv run --locked python scripts/skill_recipes.py validate --candidate <생성된후보_JSON_경로>
uv run --locked python -m unittest discover -s tests -p test_skill_recipes.py -v
```

꺾쇠괄호 부분에는 파일 경로를 넣는다. `validate`는 실제 시뮬레이션을 새로 실행한다. API나 실물 로봇은 호출하지 않는다.

## 남은 범위

LLM의 후보 생성·선택, 여러 대안 중 선택 효과, 10부품 작업으로의 절차 적용, 별도 시험셋에서의 일반화는 아직 검증하지 않았다. 이 단계는 축적의 저장→후보→물리 재검증→조건 제한 등록 과정이 동작한다는 근거다. 조건 검색과 정책에 실제 활용되는 효과를 구분해야 한다.
