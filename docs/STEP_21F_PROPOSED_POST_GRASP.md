# 21F · Luna가 첫 기둥의 파지 위치와 닫힘 방향을 제안한다

## 무엇을 구현했나

이전 21E에서는 Luna가 `pick`을 선택하면 코드가 기둥 중심보다 6mm 위를 고정 방향으로 잡았다. 21F에서는 정책이 기둥 중심 기준의 `x_mm`, `y_mm`, `z_mm`와 `jaw_yaw_deg`를 숫자로 제출한다. 각도는 기둥의 +X에서 +Y 쪽으로 재며 0°는 두 손가락이 X축을 따라 닫히는 방향이다. 이 첫 단위에서는 팔이 위에서 수직으로 접근한다. TCP는 그리퍼에 고정한 가상의 기준점이다. 숫자로 제안한 TCP와 실제 손가락 접촉점은 서로 다를 수 있다.

1. Luna는 20×20×60mm 기둥의 현재 자세, 손가락 패드 치수, 그리퍼 방향, 소켓 깊이 등으로 파지를 제안한다. 정답 좌표나 후보 ID는 입력에 없다.
2. LangGraph의 `check_grasp`가 현재 MuJoCo 상태를 복사한다. 동일한 관절 제어와 접촉·마찰로 접근, 집기, 운반, 삽입, 해제, 후퇴를 검사한다. 복사본의 시간과 결과는 본 실행과 별도로 기록한다.
3. 충돌하면 어느 단계에서 어느 두 물체가 만났는지, 접촉 위치와 거리, 집기에 성공했다면 손가락 아랫면과 소켓 턱의 높이 차이를 Luna에 돌려준다. 원래 장면을 다시 관측하고 Luna가 좌표·각도를 수정하거나 중단한다. 세 후보가 모두 거절되면 집기 전에 종료한다.
4. 통과한 제안과 현재 관측 번호가 일치할 때 원래 장면의 그리퍼가 같은 목표로 움직인다. 실제로 잡힌 부품과 TCP의 상대 자세를 측정해 삽입 목표를 계산한다. 기둥은 자유 물체이며 모터·마찰·중력으로 움직인다.
5. 원래 장면에서 손을 놓고 물러난 뒤 1초 동안 소켓 바닥 지지, 손가락 해제, 위치, 방향, 깊이, 선속도, 각속도, 침투량의 여덟 조건을 모두 검사한다. 마지막 `finish`에서도 현재 상태를 다시 측정한다.

## 실제 실행 기록

세 실행 모두 실제 Luna API를 사용했다. 첫 실행 뒤 충돌 피드백을 보완했으므로 성능 비교 표본으로 합산하지 않는다.

|---|---|---|---:|---:|
| 초기 피드백, 기본 배치 | (0, 0, 0, 0) → (5, 0, 0, 0) → (0, 0, 0, 90) | 세 번 모두 소켓 벽 접촉, 원래 장면에서 집기 전에 종료 | 3 | 0.00066775 |

트레이를 옮긴 실행에서 중앙 파지의 오른쪽 패드가 삽입 경로에서 소켓 벽과 접촉했다. 잡힌 상태로 계산한 패드 아랫면은 최종 턱 높이보다 3.38mm 낮았다. Luna가 두 번째 요청에서 높이를 12mm 올리고 닫힘 각도를 유지했다. 여유가 8.62mm로 바뀌었고 원래 장면에서 같은 제안으로 설치했다. 두 후보의 검사 시점에 원래 장면은 모두 3.000초였다.

이번 추정 비용 합계는 0.002276375달러(모델 생성 10회)다. 21E까지의 0.00073255달러를 합하면 0.003008925달러다. 입력 토큰 계산 요청은 생성 횟수에서 별도로 기록한다.

## 재현

저장소 루트 `C:\dev\llm-robot-assembly`에서 실행한다. 유료 실행은 이 프로젝트 전용 키가 현재 프로세스의 `OPENAI_API_KEY`에 등록되어 있어야 한다. 아래 로컬 설정은 기존 설정을 복사해 모델 요청 최대 5회, 실행당 최대 추정 비용 0.02달러로 둔 것이다. 표준 장면은 `--scene-case nominal`을 쓴다. 같은 명령이라도 모델이 제안하는 자세와 수정 횟수는 달라질 수 있다.

```powershell
.\runtime\luna-venv\Scripts\python.exe scripts/run_assembly_graph.py --mode single --scenario nominal --scene-case tray_x_plus_10mm --propose-grasp --llm-config runs/step21f-budget.toml --snapshots
```

새 복제본에서는 프로젝트의 로컬 LLM 설정을 준비하고 `--llm-config`에 해당 경로를 지정한다. 키 없이 실행하는 회귀 검사는 중앙 파지가 소켓 벽에 걸리면 원본 상태가 보존되는지, 수정된 파지로 조립되는지, 세 번 거절하면 중단되는지, 수치와 실제 닫힘 축의 좌표 변환이 맞는지를 확인한다.

```powershell
.\runtime\luna-venv\Scripts\python.exe -m unittest discover -s tests -p test_post_grasp.py -v
```

## 코드와 적용 범위

- `scripts/post_grasp.py`가 부품 좌표·손가락 방향을 TCP 목표로 변환한다. `scripts/assembly_skills.py`는 제안받은 목표로 접근하고 실제 양쪽 패드의 접촉을 확인한다.
- `scripts/assembly_policy.py`와 `scripts/openai_policy.py`가 Luna와 주고받는 숫자와 관측 정보를 정의한다. `scripts/assembly_graph.py`에서 재관측·재제안·실행 흐름을 볼 수 있다.
- `scripts/insertion_skills.py`가 복사본 검사를 수행하고 `scripts/workcell_verification.py`가 접촉 정보를 기록한다. `scripts/run_assembly_graph.py`의 `--propose-grasp`로 새 방식을 선택한다. 고정 파지는 기본 비교군으로 남기고 경험 기록에서 두 조건을 구분한다.
- 이번 범위는 위치를 알 수 있는 수직 사각 기둥 한 개와 고정 소켓이다. 위에서 접근한다는 제약은 개발자가 정했다. CAD와 목표 결합, 시뮬레이터가 알려주는 현재 자세를 사용한다. 임의 형상의 OBJ, 기울어진 부품, 처음 보는 조립품, 전체 10부품에 대해서는 추가 시험이 필요하다. 외부 분해 플래너는 이 단일 결합 실행에서 호출하지 않는다.
