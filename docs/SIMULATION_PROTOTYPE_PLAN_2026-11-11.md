# 시뮬레이션 프로토타입 설계와 개발 순서

2026-11-11 회의용. 구현 현황은 개발 브랜치의 `8fc6fea`까지 확인했다. 이번 설계의 대상은 UR3e와 2F-85를 사용하는 MuJoCo 시뮬레이션이다.

## 1. 무엇을 보여줄 것인가

**부품 형상과 결합 목표를 받은 에이전트가 파지를 제안하고, 삽입 중 예상되는 간섭을 물리 검사에서 찾아내고, 과거 경험을 이용해 다음 행동을 결정하는 조립 시스템**을 만든다. **주 연구 질문은 동일한 현재 물리 근거와 시도 한도를 주었을 때, 검색한 경험과 검증 스킬이 미사용 조립 구성에서 복구 성공·재시도·총비용을 어떻게 바꾸는가이다.** 조립·복구 역할 분리와 모델 등급은 그다음에 한 변수씩 비교한다. 구체적인 선행연구 28편과 설계 근거는 [문헌 비교 보고서](ASSEMBLY_SKILL_MEMORY_LITERATURE_2026-11-11.md)에 있다.

‘처음 보는 조립품’의 첫 시험 범위로 **이미 지원하는 수직 삽입·끼움 방식으로 구성한 새 제품 구성**을 제안한다. 예를 들어 개발 프레임과 부품 수나 결합 배치가 다른 조립체 하나를 평가 전용으로 보관한다. 같은 제품의 트레이 위치만 바꾸는 시험은 초기 배치 변화로 별도 집계한다.

## 3. 입력부터 완료 판정까지

1. **제품 입력**은 부품별 형상과 식별자, 목표 결합 관계·자세, 작업대와 지그 설정이다. MuJoCo에서 부품의 현재 자세, 설치 상태, 그리퍼 접촉을 읽는다. 최초 시연은 이 시뮬레이터 관측값을 사용한다.
2. **제품 계획 모듈**은 기존 분해 프로젝트의 출력에서 조립 순서 후보를 가져온다. 조립 측에서 부품 ID, 방향·단위, 목표 결합, 선행조건을 대조한다. 분해 모듈의 버전과 출력은 회차에 기록한다.
3. **조립 에이전트**는 다음 부품과 현재 장면을 보고 파지 위치 XYZ, 손가락이 닫히는 방향, 다음 스킬을 제안한다. 접근·집기·삽입 동작은 기존 실행기가 제공한다.
4. **실행기와 검증기**는 같은 현재 상태의 복사 장면에서 IK·경로·간섭·집기·삽입을 검사한다. 통과한 제안은 원래 시뮬레이션 장면에서 실행하고, 해제 뒤 부품의 위치·기울기·삽입 깊이·지지와 기존 설치 부품 보존을 확인한다.
5. **복구 에이전트**는 실패 단계, 부딪히는 형상, 어떤 제안을 이미 시도했는지, 현재 손에 부품이 있는지를 받는다. 새 파지 제안, 들고 있는 부품의 재정렬, 경로 재계획, 보류 중에서 현재 상태에 맞는 행동을 선택한다. 실제 명령은 한 실행기가 순서대로 보낸다.
6. **경험과 스킬 저장소**는 적용 조건, 근거가 된 회차, 제안값, 사전검사 결과, 원래 장면 결과를 연결한다. 조립·복구 에이전트는 같은 저장소와 실행 도구를 사용한다. 스킬 생성은 별도 개발 과정으로 두고 평가할 때는 저장 버전을 고정한다.

예를 들어 기둥을 중심보다 1mm 높게 잡은 회차에서 **경험**은 “집기는 성공, 삽입 전 오른쪽 패드와 바닥판 벽의 간섭, 예상 여유 −2.37mm”라는 기록이다. **교훈**은 이를 근거로 “이 형상에서 파지를 높이면 여유가 커질 수 있지만 수정량이 충분한지 확인해야 한다”는 적용 조건이 있는 가설이다. **스킬 후보**는 현재 관측을 받아 파지값 또는 보류를 반환하는 함수다. 기존 후보에서 나온 +1mm는 현재 장면에서 거절됐고 그 실패도 저장됐다. ## 4. 구현 순서와 각 단계의 통과 기준

| 순서 | 구현할 한 단위 | 다음으로 넘어갈 때 확인할 결과 |
|---|---|---|
| 1. 실패 근거로 후보 수정 | 기둥 Z=0과 +1mm에서의 집기 성공, 삽입 경로 거절, 접촉 쌍, 예상 여유 −3.37→−2.37mm를 연결한다. 후보 입력 v2는 출처·단위·관련 결정과 결측 상태를 표현한다. 수정 또는 보류를 받는다. | v1 후보 재생을 보존한다. 같은 초기 상태에서 같은 현재 근거를 이용하는 기하 규칙과 LLM을 시험한다. 여유 변화·사전검사·본 장면 완료를 각각 기록한다. |
| 2. 첫 검증 스킬 확보 | 사전검사를 통과한 후보를 원래 장면에서 실행한다. 등록 시 근거 회차, 검증한 적용 조건, 배제 조건, 미검증 범위를 기록한다. | 최종 자세·깊이·지지를 독립 검증하고 다음 개발 회차에서 검색·재계산·재검사한다. 같은 조건 재현과 다른 조건 전이의 증거를 구분한다. |
| 3. 단일 에이전트 본 흐름에 연결 | LangGraph에 관측·경험 검색·제안·물리검사·실행·실패 후 재관측을 연결한다. 같은 자료에서 프로그램이 자동 검색한 조건과 LLM이 검색·읽을 기록을 선택한 조건을 비교할 수 있게 한다. | 한 회차에서 읽은 문서 ID, 사용한 근거, 계산 또는 직접 제안한 파지, 복구와 중단 사유가 추적된다. 사용할 스킬이 없으면 기존 직접 제안 경로로 진행한다. |
| 4. 외부 계획으로 전체 프레임 조립 | 외부 10부품 순서를 입력으로 전달하고 부품·결합 매핑과 선행조건을 검사한다. | 동일 회차에 외부 계획 식별자, 부품별 제안과 실행 결과, 원래 장면에서 9/9 설치 및 최종 검증 결과가 남는다. 실패 시 막힌 부품과 이유를 특정한다. |
| 5. 실제 멀티에이전트 연결 | 조립과 복구를 각각 LLM 역할로 두고 실패 시 제어권을 넘긴다. 작업 전체에 하나의 호출·비용·재시도 한도를 적용한다. | 새로 발생한 실패가 복구 역할에 전달되고, 그 판단이 검증기를 거쳐 재개 또는 중단으로 이어진다. 두 역할의 호출 기록과 합산 비용을 확인한다. |
| 6. 새 구성 시연과 성능 비교 | 개발 사례·스킬을 동결하고 보관해 둔 새 조립체로 전체 작업을 실행한다. 규칙·단일·멀티 조건과 메모리·스킬 조건을 비교한다. | 미사용 제품 구성의 원래 장면에서 목표 부품 전체 설치와 완료 검사까지 통과한 회차를 시연한다. 모든 평가 회차의 성공·실패·비용을 표로 공개한다. |

1단계는 **실패 근거를 읽고 다음 후보를 판단하는 기능**이 완료 기준이다. 2단계의 물리적 복구 성공과 독립적으로 평가한다. 기둥에서 처음부터 끝까지 연결한 뒤 슬리브·덮개에는 각 형상에 맞는 조건과 검증 사례를 추가한다.

## 5. 비교 실험과 회의 시연

- **구조 효과**는 단일 Luna와 조립 Luna + 복구 Luna를 비교한다. 외부 순서, 작업 장면, 모델, 관측, 도구, 장기 지식, 총예산과 복구 한도를 맞춘다. 기존 규칙 정책을 기준선으로 함께 표기한다.
- **모델 효과**는 스킬 코드를 작성한 모델과 조립·복구를 판단한 모델을 각각 기록한다. 같은 교훈·관측으로 작성 모델을 비교할 때에는 실행기와 판정기를 고정한다. 단일 정책의 Luna 대 Astra, 두 역할의 Luna + Luna 대 Luna + Sol은 모델 비교 쌍이며 추론 설정과 전체 예산도 남긴다.
- **메모리·스킬 효과**의 네 조건은 ① 현재 관측·여유 수치로 계산하는 기하 규칙, ② 현재 실패만 보는 LLM, ③ 같은 LLM + 검색된 과거 경험·교훈, ④ 같은 경험·교훈 + 검증 코드다. ②/③은 장기 기억, ③/④는 실행 코드의 추가 효과를 본다. 같은 기둥–벽 간섭에서만 적용하는 수치 규칙의 목표 여유와 보류 조건은 개발 자료로 정하고 시험 전에 고정한다. 모든 조건에 현재 관측·실패·좌표계·시도 한도·검증기를 동일하게 제공한다.
- **지표와 시험 설계**는 전체 완성 회차/시작 회차, 설치 부품 수, 첫 제안 통과, 간섭 해결, 실패 후 본 장면 완성, 보류·개입·예산 소진, 토큰·모델 호출·모의실험 소요 시간을 포함한다. 정해진 동일 실패에서 시작하는 복구 시험과 정상 시작 전체 작업을 별도 집계한다. 스킬 작성·검증에 든 초기 비용과 다음 회차의 검색·재검사 비용을 각각 보고한다. 초기 배치 변화, 부품 치수 변화, 새로운 결합 배치를 구별하고, 시험용 구성·초기 상태·반복 수·예산·성공 판정은 개발 전에 분리하거나 평가 전 동결한다.
- **최종 시연**은 새 제품 구성 입력 → 외부 순서 읽기 → 파지 제안 → 사전검사에서 간섭 발견 → 복구 판단·스킬 조회 → 재검사 → 원래 장면 조립 → 최종 측정값과 비용 출력 순서다. 회의에서는 지금 확보한 9/9 조립 사례와 +1mm 거절 사례가 서로 다른 실행이라는 점을 밝혀 보여줄 수 있다.
