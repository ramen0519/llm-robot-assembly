# 22D단계: 시험에 사용할 메모리와 스킬 절차 고정하기

작성: 2026-11-01. API 없이 구현한 첫 결합의 지식 입력 계약이다.

## 왜 필요한가

두 정책을 비교하면서 첫 번째 실행의 성공 기록이 두 번째 정책에만 추가되면, 같은 정보로 비교한 것이 아니다. 그래서 시험 전에 사용할 경험과 검증된 절차를 하나의 JSON 묶음으로 복사한다. 각 실행은 그 묶음을 한 번 읽고 자기 실행 폴더에도 보관한다. 실행 도중 경험 저장소를 다시 검색하거나 새 성공을 자동 등록하지 않는다.

메모리는 과거 사건이다. 예를 들어 “이 환경에서 정렬 오류가 났고 재정렬 후 성공했다”라는 기록이다. 스킬 절차는 “이 실패에 `recover_alignment` 다음 `insert`를 사용한다”라는 적용 조건이 있는 순서다. 실제 움직임은 기존 Python 스킬이 수행한다. 이번 묶음에는 생성된 Python 코드를 넣지 않는다.

## 구현 경계

- `frozen_knowledge.py`: 경험·검증 절차의 복사, 내용 지문, 조건·구현 버전 검사, 최대 3개 문맥 요약.
- `run_assembly_graph.py`: 물리 동작 전에 묶음을 확인하고 `frozen_knowledge.json`과 사용한 ID/모드를 기록.
- `assembly_graph.py`: 경험과 절차를 정책의 참고 데이터로 전달하고 이벤트에 ID 기록.
- `openai_policy.py`: 절차가 기존 허용 행동이나 현재 관측을 대체하지 않는다는 지시 유지.

코드·모델·조건이 다르거나 기록 내용이 바뀌면 거부한다. 절차는 현재 코드에서 독립적인 물리 재검증을 통과한 등록본만 동결한다. 개발 기록만 입력하며, 평가 중 새 기록을 유입하는 기능은 없다. 묶음은 읽은 뒤 메모리에 복사하므로 원본 파일이나 반환된 요약을 바꿔도 실행 도중 참고 데이터가 바뀌지 않는다.

이 무결성 검사는 실수로 바뀐 파일과 호환성 문제를 검출하는 장치다. 서명 기반 외부 자료 인증 체계는 아니다. 과거 경험은 참고 근거이며 성공을 보장하거나 물리 실행 권한을 주지 않는다.

## 비교 옵션

| 옵션 | 정책에 들어가는 참고 데이터 |
|---|---|
| 묶음 옵션 생략 | 경험·절차 추가 정보 없음 |
| `--knowledge-mode memory` | 과거 경험 요약만 |
| `--knowledge-mode recipes` | 현재 검증된 절차 요약만 |
| `--knowledge-mode both` | 두 종류 모두 |

현재 절차는 **조언용 순서 데이터**다. 새 실행 도구를 추가하거나 두 동작을 한 번의 LLM 호출로 묶지 않는다. 따라서 이 옵션으로 비교할 수 있는 것은 절차 정보를 제공하는 효과다. 호출 수 절감을 구현했다고 주장하지 않는다. 규칙 정책은 이 조언을 읽어 추론하지 않으므로, 실제 효과 비교는 LLM을 연결한 뒤 같은 조건·묶음·예산으로 진행해야 한다.

## 실행 방법

```powershell
# 원본 경험에서 이미 만든 후보를 현재 코드로 재검증
uv run --locked python scripts/skill_recipes.py validate --candidate <후보_JSON>
# 완료된 첫 결합 실행의 조건으로 지식 묶음 생성
uv run --locked python scripts/frozen_knowledge.py --run-dir <첫_결합_실행_폴더>
# 출력된 고정 파일을 입력하고, 같은 조건에서 실행
uv run --locked python scripts/run_assembly_graph.py --mode single --scenario alignment_offset --knowledge-bundle <출력_JSON> --knowledge-mode both
uv run --locked python -m unittest discover -s tests -p test_frozen_knowledge.py -v
```

꺾쇠 부분은 실제 경로로 교체한다. 저장 위치는 OneDrive 밖 `runtime/knowledge/simulation`이다. `--llm-config`를 함께 주기 전까지는 API가 호출되지 않는다. 기존 `--memory`는 변경 가능한 개발 저장소를 검색하는 구형 개발 옵션이며 동결 묶음과 동시에 사용할 수 없다.
