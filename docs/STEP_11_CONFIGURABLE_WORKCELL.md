# 11단계: 실제 작업 환경으로 바꾸기 쉬운 작업대 장면

이번 단계는 **한 설정 파일을 읽어 작업대·로봇 설치 위치·시험 부품·목표 영역을 배치하고, 부품이 실제 접촉으로 안정되는지 확인하는 것**이다. 현재 치수는 사용자가 측정한 연구실 값이 아니라 예시다. 집기·이동 경로·삽입·실물 연결은 수행하지 않는다.

## 수정할 파일과 실행 명령

- `config/workcell.example.toml`: Git에 보관하는 재현용 예시.
- `config/local.workcell.toml`: 이 PC에서 수정할 개인 설정. Git 제외. 현재는 예시를 복사한 상태이며 `example_unmeasured`로 표시한다.
- `scripts/workcell_scene.py`: 설정 검사, 좌표 변환, 장면 구성, 관측 읽기.
- `scripts/view_workcell.py`: 로봇을 제어기로 유지하고 부품을 3초간 안정화한 뒤 판정.

TOML은 이름과 값을 적는 설정 파일이다. 코드의 여러 숫자를 찾아 수정하는 대신 이 파일을 수정하고 다시 실행한다. Python 3.11의 기본 `tomllib`을 사용하므로 새 패키지를 설치하지 않는다.

이 PC에 준비된 개인 설정으로 창 없이 검사:

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/view_workcell.py --config config/local.workcell.toml --check
```

화면으로 보기:

```powershell
uv run --locked python scripts/view_workcell.py --config config/local.workcell.toml
```

3초 동안 물리 계산과 안정화 검사를 수행하고 결과를 저장한다. 이후 창은 정지 화면으로 남아 배치를 살펴볼 수 있다. 창을 닫으면 종료된다. 검사 중간에 닫으면 완료로 인정하지 않는다. 이번 구현은 headless 실행과 오프스크린 렌더링을 확인했고, 대화형 뷰어의 마우스 조작은 직접 검사하지 않았다.

다른 PC에서 처음 clone했다면 개인 파일은 없으므로 다음과 같이 만든다. 이미 있으면 덮어쓰지 않는다.

```powershell
if (-not (Test-Path -LiteralPath config/local.workcell.toml)) {
    Copy-Item -LiteralPath config/workcell.example.toml -Destination config/local.workcell.toml
}
```

`--config`를 생략하면 **항상 example 파일**을 읽는다. 개인 설정을 수정했으면 위처럼 `--config config/local.workcell.toml`을 지정한다. 예전 `move_tcp.py`는 여전히 10단계의 별도 장면을 사용한다. 새 작업대에서 목표를 바꾸며 이동하는 연결은 12단계에서 구현한다.

## 좌표를 어디서부터 측정하는가

**월드(world)**는 시뮬레이션 전체 기준이다. 바닥이 Z=0이고 위쪽이 +Z다. 예시는 작업대 상판 중심 바로 아래 바닥을 원점으로 잡았다.

**작업대 기준(table_top)**은 상판 윗면의 정중앙이 원점이다. 화면의 흰 점이 원점이고 빨강은 +X, 초록은 +Y, 파랑은 +Z다. 길이는 m, 설정의 회전은 deg를 사용한다. `yaw_deg`는 위에서 내려다볼 때 반시계 방향으로 회전하는 각도다.

**로봇 베이스 기준(robot base)**은 로봇 모델의 설치 원점이다. 상판 중심에서 이 원점까지의 X·Y 거리와 장착판 높이, 작업대 축에 대한 회전을 입력한다. 로봇 베이스 +X의 실제 방향은 실물 좌표 정합 때 확인해야 한다.

```text
월드 / 바닥
  └─ 작업대 상판 중심: 월드 위치 + 작업대 yaw
       ├─ 로봇 베이스: 작업대 X·Y 위치 + 장착판 높이 + 로봇 yaw
       ├─ 시험 부품: 작업대 X·Y 위치 + 부품 높이의 절반 + 시작 간격
       └─ 목표 영역: 작업대 X·Y 위치 + 목표 yaw
```

설정에서 가로·세로·높이는 모두 **전체 길이**다. MuJoCo의 일부 형상은 반길이를 요구하지만 코드 안에서 변환한다. `0.04m = 40mm`, `0.05kg = 50g`다.

| 설정 | 실측 시 넣을 값 |
|---|---|
| `table.top_center_world_m` | 상판 윗면 중심의 월드 `[X, Y, Z]`. 예시 `[0, 0, 0.75]` |
| `table.size_xy_m` | 상판 가로·세로 전체 길이. 예시 `[1.0, 0.8]` |
| `table.thickness_m` | 상판 두께. 예시 `0.04` |
| `table.leg_width_m` | 단순한 사각 다리의 너비. 예시 `0.04` |
| `table.yaw_deg` | 월드에 대한 작업대의 회전 |
| `robot.base_xy_table_m` | 상판 중심에서 로봇 베이스 원점까지의 X·Y 거리 |
| `robot.mount_height_m` | 상판에서 로봇 설치면까지 높이. 장착판이 없으면 `0.0` |
| `robot.mount_size_xy_m` | 장착판/받침의 전체 가로·세로. 로봇 yaw에 맞춰 회전 |
| `robot.yaw_deg` | 작업대 축에 대한 로봇 베이스의 회전 |
| `part.size_m`, `part.mass_kg` | 시험 부품의 전체 치수와 질량 |
| `part.spawn_xy_table_m`, `part.yaw_deg` | 시작할 부품 중심의 작업대 X·Y 위치와 회전 |
| `part.spawn_clearance_m` | 상판 위에서 시작할 간격. 예시 `0.005` |
| `target.xy_table_m`, `target.size_xy_m`, `target.yaw_deg` | 배치 목표 영역의 위치·크기·회전 |
| `contact.friction` | 부품과 상판에 적용할 MuJoCo 마찰 파라미터 3개. 현재는 미식별 예시값 |

예를 들어 상판 높이를 0.75m에서 0.90m로 바꾸려면 `top_center_world_m`의 마지막 숫자를 수정한다. 로봇 밑에 25mm 장착판이 있다면 `mount_height_m = 0.025`로 둔다. 로봇 베이스의 월드 높이는 자동으로 **0.925m**가 된다. 부품과 목표 높이도 상판과 부품 치수로 다시 계산하므로 개별 Z값을 고칠 필요가 없다.

장착판 높이가 0보다 크면 실제 충돌 형상을 가진 상자형 받침을 생성한다. 높이가 0이면 받침 형상은 생성하지 않는다. 네 다리와 받침은 단순화한 형상이다. 실제 작업대가 캐비닛이거나 별도 기둥·지그가 있다면 해당 형상을 추가해야 정확한 충돌 모델이 된다.

좌표 변환은 `월드 위치 = 작업대 중심 + 작업대 회전 × 작업대 기준 위치`로 한곳에서 계산한다. 나중에 실물 명령으로 바꿀 때는 로봇 베이스 기준 변환을 적용하는 adapter가 필요하다. 지금 설정은 자동 캘리브레이션이나 로봇 제조사 좌표계와의 정합 결과가 아니다.

## 실제 상태와 설정상의 목표를 구분하기

주황색 물체는 질량 50g, 크기 40×30×40mm의 **시험용 부품**이다. 움직일 수 있는 free joint를 사용하고 중력·접촉으로 상판에 놓인다. 그리퍼에 붙이는 weld나 강제 추종은 없다. 제품 부품 약 10개 목표는 그대로이며 이 블록이 최종 제품 설계는 아니다.

초록색 영역은 `place_a`라는 **시각적 배치 목표**다. 물리적인 지그가 아니고 충돌 형상도 없다. 목표에 해당하는 부품 중심 높이는 상판 높이 + 부품 높이의 절반으로 계산한다. 이 점은 TCP 목표와 다르다. 실제 집기·놓기에서는 부품과 그리퍼 사이의 관계를 반영해야 한다.

`part_a`, `place_a` 같은 ID를 사용하므로 이후 스킬은 좌표 숫자 대신 대상 ID를 받을 수 있다. 초기 위치는 설정에서 읽지만, 실행 중 부품 위치는 `observe_workcell()`이 MuJoCo의 현재 상태에서 읽는다. 관측에는 다음을 구분한다.

- 부품·로봇 상태: `sim_ground_truth`.
- 목표: `configured_target`.
- 위치: 기준 좌표계와 m 단위 명시.
- 자세: `quaternion_xyzw`로 이름에 순서 명시. MuJoCo 내부의 wxyz를 관측 경계에서 변환.
- 설정의 출처: `example_unmeasured` 또는 `measured_nominal`. 후자는 실측 공칭값이라는 표시이며 실물 검증 완료라는 뜻은 아니다.

카메라 관측을 붙일 때는 이 관측 경계를 확장하고 실제 위치 추정값을 사용한다. 설정에 적힌 시작 좌표를 실제 카메라 관측인 것처럼 취급하지 않는다.

## 검사와 저장 결과

로봇은 기존 힘 제한 모터와 중력 보상으로 초기 자세를 유지한다. 부품은 5mm 위에서 시작해 실제 접촉으로 안정된다. 로봇이나 부품의 자세를 실행 도중 덮어쓰지 않는다.

- 전체 3초 동안 부품–상판 외의 예상하지 못한 접촉, 관절 한계, 그리퍼 상태, 엔진 경고를 검사.
- 마지막 0.5초 동안 상판 접촉 유지, 높이·수평 위치 오차 1mm 미만, 자세 오차 0.5도 미만, 부품 선속도 1mm/s 미만, 각속도 0.01rad/s 미만, 로봇 관절 속도 0.5도/s 미만 확인.
- 접촉 침투는 초기 충격 중 3mm 이하, 마지막 구간 1mm 미만으로 구분. **장면 안정화용 기준이며 삽입 정밀도나 실제 재료 변형 기준이 아니다.**

MuJoCo는 접촉을 부드러운 제약으로 풀기 때문에 형상이 조금 겹친 상태에서 안정될 수 있다. 접촉 파라미터는 별도 검증 대상이다. [공식 solver parameters 설명](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)

기본 예시의 첫 접촉은 0.032초였고 초기 최대 침투는 약 2.077mm, 마지막 구간 높이 오차는 약 0.108mm였다. 처음 시도한 전체 구간 1mm 제한은 초기 충격에서 실패했으며, 그 결과도 이전 run에 보존했다. 이후 초기 충격과 안정 구간을 분리한 기준으로 검사했다.

각 실행은 새 폴더에 다음을 저장한다.

```text
runs/step11/<실행ID>/
    resolved_config.json    # 그 실행에 실제 사용한 설정 사본
    workcell_check.json    # 판정·측정값·관측·설정 해시
```

설정을 바꿨더라도 이전 실행이 어떤 값으로 수행됐는지 추적할 수 있다. 파일들은 Git 제외다. 여기의 보고서는 **작업대 장면 안정화 검사**이며, 10단계 TCP 이동의 `FailureReport`나 조립 성공 보고서와 구분한다. 특히 자유 물체의 위치·쿼터니언을 관절 각도라고 저장하지 않는다.

2026-10-28 검증: 기존 검사 20개와 새 작업대 검사 6개가 통과했다. 새 검사는 기본 물리 안정화, 월드 이동·작업대 높이 1.05m·작업대 90도 회전·로봇 90도 추가 회전·30mm 받침을 함께 바꾼 경우, 지지 없이 정지한 물체의 실패, 부품–그리퍼 초기 겹침 거부, 잘못된 설정·UR3 혼동 거부, 회전된 부품 경계·다른 TOML 경로 적용을 포함한다. 기본 장면은 렌더링으로도 확인했다.

```powershell
uv run --locked python -m unittest discover -s tests -p test_workcell.py -v
```

## 지금 지원하는 범위

수평 사각 작업대, 네 개의 단순 다리, 상판 위 UR3e + 2F-85, 선택적인 상자형 받침, 자유롭게 놓인 상자 부품 하나와 목표 영역 하나를 지원한다. 부품·목표·받침이 회전을 고려해 상판 안에 들어오는지 검사하며, 잘못 쓴 설정 키와 비정상 숫자는 거부한다.

`robot.model`을 `ur3`로 적는다고 UR3로 변환되는 것은 아니다. 현재는 UR3e만 지원하므로 다른 모델은 명시적으로 거부한다. 기울어진 작업대, 바닥에 별도 설치한 로봇, 실제 CAD 지그·복잡한 부품·RGB-D 카메라에는 별도 구현이 필요하다. 원본 모델·라이선스는 유지하고 조합 단계에서 배치를 변경한다. 모델 조합에는 MuJoCo의 편집 가능한 `MjSpec`을 사용한다. [공식 Model Editing 설명](https://mujoco.readthedocs.io/en/stable/programming/modeledit.html)

설정 파일만 바꿔 장면을 만들 수 있다는 것은 그 위치까지 로봇이 도달하거나 충돌 없이 집을 수 있다는 뜻은 아니다. 다음 12단계에서 현재 자세에서 출발하는 이동·경로 검사를 이 작업대 장면에 연결하고, 13단계에서 실제 파지를 검증한다.
