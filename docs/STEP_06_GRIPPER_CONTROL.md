# 6단계: 2F-85를 천천히 닫고 다시 열기

이번 단계의 목표는 **팔이 초기 자세를 유지하는 동안 그리퍼를 닫았다가 다시 열고, 실제 측정값으로 동작 완료를 확인하는 것**이다. 물체가 없는 장면에서 개폐만 검증한다. 물체를 집는 스킬과 IK는 다음 단계다.

## 실행

새 패키지를 설치할 필요 없다. 기존 프로젝트 환경을 사용한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/move_gripper.py
```

열림 유지 1초 → 닫기 4초 → 닫힘 유지 2초 → 열기 4초 → 열림 유지 2초, 총 13초의 시뮬레이션을 실행한다. 계산이 느린 PC에서는 실제 경과 시간이 더 길 수 있다. 창은 완료 후 자동으로 닫히며 다음 결과를 출력한다.

```text
Gripper open/close: PASS
```

검사 완료 전에 창을 닫으면 실패로 종료한다. 창 없이 같은 물리 계산을 실행하려면 다음 명령을 사용한다.

```powershell
uv run --locked python scripts/move_gripper.py --headless
```

## 명령값과 실제 상태는 다르다

이 모델은 `gripper_fingers_actuator`라는 구동기 하나로 두 손가락을 움직인다. actuator는 힘을 만들어 관절을 움직이는 모터의 시뮬레이션 표현이다. 원본 모델의 tendon과 연결 제약이 모터의 작용을 양쪽 손가락에 전달한다.

- `data.ctrl`: 구동기에 보내는 명령. 이 그리퍼는 0이 열림, 255가 닫힘 방향의 끝 명령이다.
- `data.qpos`: 물리 계산 결과의 실제 관절 각도.
- `data.qvel`: 실제 관절 속도.

**0~255는 mm도 각도도 아니다.** 팔의 구동기는 목표 각도를 rad로 받지만, 이 그리퍼 구동기는 원본 XML에 정의된 별도의 입력 범위를 사용한다. 127.5를 입력했다고 실제 간격이 정확히 42.5mm가 되는 것도 아니다. 연결 기구의 형상과 접촉·부하 때문에 입력과 간격은 단순 비례하지 않는다.

핵심 동작은 다음과 같다.

```python
command, phase = command_at(float(data.time))
data.ctrl[motor_id] = command
mujoco.mj_step(model, data)
mujoco.mj_forward(model, data)
```

`mj_step()`은 힘과 운동을 계산해 다음 상태로 진행한다. `mj_forward()`는 갱신된 관절 상태에서 형상 위치와 접촉 정보를 다시 계산한다. 초기화 이후 `qpos`를 직접 수정해서 손가락을 이동시키지 않는다. 원본 모델 파일과 모터 파라미터도 변경하지 않았다.

## 코드 읽는 순서

[실행 코드](../scripts/move_gripper.py)는 이번 개폐 실험 하나를 담당한다.

1. `load_robot_with_gripper()`: 5단계에서 만든 로더로 팔과 그리퍼를 결합하고 초기 상태를 설정한다.
2. `command_at()`: 시각에 따라 열기·닫기 목표를 계산한다. 움직이는 4초 구간은 `3s² - 2s³` 곡선을 사용해 목표값 변화가 부드럽게 시작하고 끝나게 한다. 이는 목표값의 특성이며 실제 속도는 물리 계산 결과로 확인한다.
3. `run_cycle()`: 팔의 6개 목표값을 유지하면서 그리퍼 명령을 바꾸고, 0.002초마다 물리 계산과 측정을 수행한다.
4. `measure_state()`와 `check_path_sample()`: 패드 간격, 팔의 변화, 관절 한계, 연결부 오차, 충돌을 측정하고 경로 중 이상을 검사한다.
5. `assess_cycle()`: 닫힘과 다시 열림의 마지막 0.5초 관측으로 완료 여부를 판단한다.

## 간격은 어떻게 측정하나?

원본 모델에서 각 손가락의 접촉면은 두 개의 상자형 충돌 형상(`pad1`, `pad2`)으로 표현된다. 양쪽 상자의 중심 거리에서 각 상자의 두께를 빼서 두 쌍의 간격을 계산한다. 상자 회전도 반영하고, 그리퍼 본체의 닫힘 축 방향으로 투영한다.

따라서 이것은 **시뮬레이터 충돌 형상 기준의 방향성 간격**이다. 실제 제품의 폭 센서나 보정된 실물 그리퍼 간격은 아니다. 두 구간을 따로 확인해서 한 지점만 가까워졌는데 전체가 닫혔다고 판단하지 않도록 한다.

닫힌 상태에서는 손가락 패드끼리 닿는다. 이 예상 접촉만 허용하며, 팔·그리퍼의 다른 부위나 바닥과의 접촉은 실패 처리한다. 검사 대상은 모델에 활성화된 충돌 형상이며, 원본의 충돌 제외 설정은 유지한다. 충돌 형상 자체가 실제 장비와 정확히 일치한다는 검증은 별도 과제다.

MuJoCo의 부드러운 접촉 제약은 작은 겹침을 허용한다. 투영 간격의 작은 음수와 엔진이 계산한 접촉 침투량은 별개의 값이므로 각각 검사한다.

## 완료 기준과 실제 측정

2026-10-28, 기존 Python 3.11.15 / MuJoCo 3.17.0 환경에서 창 없는 실행과 13초 뷰어 실행을 확인했다. 열린 상태·닫힌 상태·다시 열린 상태의 실제 시뮬레이터 렌더링도 확인했다.

| 검사 | 이번 장면의 통과 기준 | 실제 결과 |
|---|---|---|
| 최초 열린 간격 | 두 구간 모두 80~90mm | 약 85.130900 / 85.121838mm, 초기 유지 마지막 0.5초 평균 |
| 닫힌 간격 | 마지막 0.5초, 두 구간 모두 -0.1~2mm | 가장 큰 간격 약 0.824656mm |
| 다시 열린 간격 | 마지막 0.5초, 두 구간 모두 80~90mm | 가장 작은 간격 약 85.121511mm |
| 초기 간격으로 복귀 | 최초 열린 평균과 차이 1mm 이하 | 최대 약 0.000336mm |
| 닫힘·재열림 끝의 안정성 | 마지막 0.5초 전체 관절 속도 0.5도/초 미만 | 최대 약 0.000001381도/초 |
| 팔 자세 유지 | 초기 각도 대비 최대 변화 2도 이하 | 약 1.070551도 |
| 좌우 구동 관절 각도 차이 | 0.5도 이하 | 약 0.000117도 |
| 관절 한계 초과 | 0.001rad 이하 | 약 0.000501rad |
| 손가락 연결 제약의 최대 성분 잔차 | 0.2mm 이하 | 약 0.138619mm |
| 허용한 패드 접촉 침투량 | 0.1mm 이하 | 약 0.032717mm |
| 다른 부위 접촉 / 엔진 경고 | 없어야 함 | 없음 |

연결 제약 잔차는 네 막대로 연결된 손가락 기구의 접속점이 수치적으로 얼마나 어긋났는지 나타낸다. 5단계의 열린 상태 유지 검사는 0.1mm 기준을 사용했다. 이번에는 완전히 닫을 때 패드 접촉과 구동기 하중이 생기므로, 개폐 시험 기준을 별도로 0.2mm로 명시하고 실제 잔차도 보고한다. 이는 이 모델의 개폐 동작 확인용 허용값이며 정밀 삽입 성능이나 실물 안전 한계가 아니다.

간격 복귀 오차가 작다는 결과 역시 동일한 시뮬레이션 조건의 반복성이다. 실제 그리퍼에 같은 정밀도가 있다고 해석하지 않는다.

## 실패 판정도 확인하기

정상 시연뿐 아니라 잘못된 실행이 성공으로 판정되지 않는지 검사한다.

```powershell
uv run --locked python -m unittest discover -s tests -v
```

[회귀검사](../tests/test_gripper_cycle.py)는 다음 실패를 재현한다. 새 의존성 없이 Python 기본 `unittest`를 사용한다.

- 닫기 명령을 억제하고 계속 열린 상태로 실제 13초 물리 계산: 닫힘 기준 미달로 거부.
- 중간까지만 있는 측정 기록: 전체 실행 미완료로 거부.
- 메모리 안의 시험 모델에서 바닥을 높여 로봇과 충돌하게 만든 상태: 예상치 못한 접촉으로 거부. 원본 모델은 수정하지 않는다.

## 저장되는 기록과 확인 범위

매 물리 스텝의 시간, 동작 단계, 명령값, 두 패드 간격, 관절 속도, 팔의 자세 변화, 연결 오차와 접촉량을 `runs/step06/gripper_cycle.csv`에 저장한다. 정상 13초 실행은 초기 상태를 포함해 6,501개 측정 행이다. CSV는 매 실행마다 덮어쓰며, 중단되면 그때까지 작성한 기록을 남긴다. 전체 기록이 존재한다는 사실과 성공 판정은 구분한다. 결과 파일과 확인용 이미지는 Git에서 제외한다.

이번 결과로 확인한 것은 **현재 초기 자세에서 물체 없이 그리퍼를 닫고 다시 여는 동작**이다. 물체 파지·유지 힘, 무게를 든 상태, 이동 중 안정성, 삽입, 실물 제어는 검증하지 않았다. 다음 작은 단계는 집기 기준점(TCP)의 위치·방향을 확인하고, 기존 IK 기능으로 그 기준점을 목표 위치로 이동시키는 것이다.
