## 2. 무엇을 비교하나

질문은 두 가지다. **이전 제품에서 겪은 실패와 복구를 읽으면 새 제품의 완주율과 파지 재시도 횟수가 달라지는가? 같은 기록을 읽은 상태에서 검증된 코드까지 실행할 수 있으면 추가로 달라지는가?**

| 조건 | 에이전트가 쓸 수 있는 정보와 행동 | 해석 |
|---|---|---|
| A · 현재 회차 | 현재 형상·관측·치수, 이번 회차의 후보·접촉·실패 기록. 복구 에이전트가 직접 수정값을 제안할 수 있다. | 기준선 |
| B · 경험 추가 | A + 개발 데이터에서 동결한 과거 경험과 스킬의 적용 조건·서술 근거. 검색어와 조회 결과를 남긴다. | B−A가 장기 기억을 제공한 효과 |
| C · 경험과 코드 | B와 같은 과거 자료와 검색 기회 + 현재 관측을 검증된 함수에 넣어 파지값 또는 보류를 받는 권한. 제안값은 같은 MuJoCo 사전검사를 통과해야 한다. | C−B가 경험을 제공한 상태에서 실행 코드를 추가한 효과 |

예를 들어 B는 “예전에는 패드가 작업대에 닿았고 파지를 높여 설치했다”를 읽고 이번 파지 높이를 직접 정한다. C는 해당 유형의 등록 함수가 있을 때 현재 측정값으로 수정 후보를 계산할 수 있다. **세 조건 모두** 집기·삽입·놓기, IK, 경로계획, 충돌 검사, 실패 후 재관측을 사용한다. A에서 끄는 기능은 다른 회차의 장기 지식 접근이다. 외부 플래너는 조건마다 한 번씩 돌리지 않고 한 제품에서 얻은 동일한 계획 파일을 공유한다.

### 현재 스킬의 한계와 시험 착수 기준

현재 등록된 기둥 함수는 원래 제품의 `post_1/mate_post_1`, 빈 설치 상태, 특정 조건 지문 및 삽입 전 패드–벽 간섭에서 검증됐다. 새 제품에서 키워드가 일치해도 실행 범위를 벗어날 수 있다. 22S에서 기둥을 복구한 주체는 새 높이를 제안한 에이전트였다. 현재 스킬 선택기는 과거 경험 문서도 제공하고, 선택 결과가 보류이면 그래프가 중단될 수 있다. 명령행 스위치 하나만 바꾸면 B와 C의 차이가 코드 실행으로 한정된다고 가정할 수 없다.

**평가 제품을 열기 전에** 기존 네 기둥·삼각형 개발 자료에서 다음을 확인한다.

1. 새 배치를 파일로 주입하는 공통 실행 경로, 현재 관측·실패 요약·사전검사·예산이 모든 조건에서 같다. A에는 과거 카드·수정값·원본 로그가 들어가지 않는다. B와 C에는 같은 검색 기회와 카드 내용·선택 근거가 들어간다. B에는 실행 코드·현재 관측으로 계산한 스킬 출력이 들어가지 않는다. 모델이 스스로 B의 기록을 해석해 같은 수치를 제안하는 것은 허용한다.
2. 실행 스킬을 비교하려면 개발 자료에서 배치·부품 이름에 독립적인 적용 조건을 물리적으로 검증한다. 적용 가능한 개발 사례에서 **계산→사전검사→원래 장면의 설치**, 범위 밖 사례에서 실행 거절을 모두 기록한다. 코드·조건을 바꾼 경우 별도 평가판을 고정한다. 적용 대상이 없을 때의 수치 재제안 경로와 위험·불확실성으로 인한 보류 규칙은 B·C에 동일하게 적용하도록 개발 장면에서 확인한다.
3. 이 요건을 만족하면 아래의 A/B/C 18회를 진행한다. 요건을 충족하지 못하면 **현 슬리브 경험만 사용하는 B와 A를 12회** 비교하는 축소안으로 전환한다. 축소안에서는 B−A의 대상이 슬리브 경험 1건임을 표시한다. 같은 평가 제품에서 결과를 본 뒤 스킬을 만들거나 C를 소급해 덧붙이지 않는다. 이후 스킬 비교에는 별도의 미사용 제품이 필요하다.

실험 시작 전에 위 두 경로 중 하나를 기록한다. 18회 계획으로 시작한 뒤 자연 발생 실패 또는 적용 가능한 스킬 실행이 0회여도 배정된 C를 집계한다. 이때 보고할 수 있는 값은 **스킬 사용을 허용한 시스템의 성과와 적용 기회 0회**다. 스킬이 실행된 경우의 효과는 미측정으로 남긴다.

## 3. 새 제품과 공통 시작 상태

- **제품 한 개.** 평가 전용 10부품 사다리꼴 구멍 배치 프레임을 지정한다. 160 mm 정사각 바닥판의 중심을 원점으로 기둥 1~4의 XY를 차례로 (−44, −36), (+44, −36), (−27, +38), (+27, +38) mm로 정한다. 바닥판과 덮개 모두 이 네 위치에 구멍이 있다. 기둥 4개·슬리브 4개와 덮개 1개는 트레이에서 출발한다. 기둥 단면·슬리브 치수·끼움 방향·덮개 손잡이는 개발 제품과 같다. 이번 질문은 같은 끼움 방식에서 **결합 배치가 바뀔 때의 전이**다.
- **개발·평가 분리.** 22R의 네 귀퉁이 프레임과 22S의 삼각 프레임은 개발용이다. 새 제품에서는 CAD 부품·목표 대응, 시작 형상의 비중첩, 고정 바닥판, 검증기 입력, 공통 네이티브 분해 계획의 수용 여부만 사전 확인한다. 제품별 파지 정답·스킬·예시 프롬프트는 주지 않는다. 파지 시험·완주 연습은 기존 개발 제품에서만 한다. 제품이나 계획이 성립하지 않으면 사유를 기록하고 본시험을 보류한다.
- **시작 상태 여섯 개.** 바닥판·로봇 초기 자세와 트레이 지지면을 고정한다. 자유 부품 9개의 초기 위치를 각 기본 트레이 슬롯 안에서 아래 XY만큼 평행 이동한다. Z와 방향은 유지한다. 각 블록의 컴파일 모델, 초기 전체 물리 상태, 트레이 좌표, CAD·외부 계획·검증 기준의 해시를 첫 모델 호출 전에 보관한다. 조건이 바뀔 때마다 해당 블록의 동일 초기 상태에서 새 회차를 시작하고 해시를 다시 확인한다.
- **검색 시점.** B/C는 동일한 사전 지정 규칙으로 슬리브 첫 후보 직전에 검색한다. 기존 저장 규약에 맞춰 원천 슬롯 번호 1을 제외한 모든 슬리브(2·3·4)를 대상으로 하며, 이 번호 선택의 한계를 함께 기록한다. 기둥 관련 과거 자료를 제공하는 정식 3조건판은 같은 측정 실패 유형에서 B·C 모두 같은 텍스트에 접근한다. 검색·적용 실패도 기록한다. 자연 발생 실패를 사용하며 첫 파지값이나 간섭을 인위적으로 주입하지 않는다.

| 블록 | 트레이 슬롯 기준 이동 (mm) | A/B/C 순서 | 축소 시 A/B 순서 |
|---|---|---|---|
| 1 | (0, 0) | B A C | B A |
| 2 | (+4, 0) | A B C | A B |
| 3 | (−4, 0) | B C A | B A |
| 4 | (0, +4) | C B A | B A |
| 5 | (0, −4) | C A B | A B |
| 6 | (+3, −3) | A C B | A B |

블록은 1→6으로 실행한다. Python 3.11에서 `itertools.permutations('ABC')`의 여섯 순서를 `random.Random(20261112).shuffle`로 배정해 각 조건이 첫째·둘째·셋째가 되는 횟수를 두 번씩 맞췄다. 축소 시 C를 제거한다. 같은 초기 상태로 짝지으면 시작 배치의 영향을 줄일 수 있다. API의 응답은 같은 물리 상태에서도 달라질 수 있다. [NIST의 블록 실험 설계](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm)

## 4. 한 회차에서 무엇을 세나

| 지표 | 사전 정의 |
|---|---|
| **완주 성공률** | 조건별 독립 물리 검증 통과 회차 / 시작 회차. 원래 장면에서 9/9 설치, 부품 간 8개 상태 경계 연속, 그리퍼 해제·후퇴, 기존 설치물 보존, 각 기둥의 슬리브·덮개 관통 및 네 슬리브의 개별 지지를 확인한다. 미완주·보류·예산 소진은 성공 0. |
| **파지 재시도 횟수** | 각 도달 부품에서 사전검사기에 제출된 파지 후보 수를 `k`로 하여 `max(k−1, 0)`을 합산한다. 첫 후보 거절 후 수정 후보 1개를 검사해 성공하면 재시도 1회. 첫 거절 후 그대로 중단하면 재시도 0회와 중단 1건. 에이전트 제안과 코드 제안에 같은 규칙을 적용한다. |
| **중도 종료 해석** | 시작 회차별 재시도 총수, 도달 부품 수(첫 후보 검사에 진입), 설치 수/9, 중단된 부품·사유를 나란히 낸다. 보조로 도달 부품당 재시도, 두 조건 모두 도달한 같은 부품에서의 재시도, 첫 후보 통과 수/첫 검사를 한 부품 수를 표시한다. 미도달 부품은 미측정으로 둔다. |
| **실물리 동작과 검색** | 원래 시뮬레이션 장면의 재집기·재삽입은 같은 부품에 대한 같은 동작의 두 번째 실행부터 별도로 센다. 복사본의 충돌 판정, 도구 호출 횟수, 경로계획기의 내부 재탐색, 역할 인계는 파지 재시도에 중복 가산하지 않는다. 메모리는 대상·검색·적중·다음 제안에 전달된 카드 ID, 스킬은 대상 실패·조회·범위 일치·계산·보류·사전검사 통과·본 장면 설치를 별도 열로 기록한다. |
| **비용과 시간** | 조건별 모델 호출·입력/출력 토큰·비용·실제 소요시간. 검색·선택 호출도 합산한다. 모델명·반환 모델 ID(제공 시)·서비스 오류를 기록한다. |

성공 판정·공차는 세 조건이 공유하는 개발판 검증기에서 정하고 평가 전에 고정한다. 부품별 후보 한도 3회, 에피소드당 모델 생성 최대 36회, 출력 상한과 공통 비용 한도는 동결 설정을 따른다. 비어 있는 그리퍼와 운반 경로에 같은 `direct_then_rrt`를 사용한다. 같은 조건 안에서도 직전 회차의 메시지·로그·새 경험을 다음 회차로 넘기지 않는다. 동결 입력은 읽기 전용으로 제공하고 회차 출력은 별도 폴더에 기록한다.

## 5. 비용, 중단과 결과 해석

| 설계 | 회차 | 회차당 제안 상한 | 전체 제안 상한 |
|---|---:|---:|---:|
| 경험과 코드 모두 비교 | 6개 시작 상태 × 3조건 = 18 | $1.50 | $27 |
| 현 슬리브 경험을 먼저 비교 | 6개 시작 상태 × 2조건 = 12 | $1.50 | $18 |

예산은 대안별 상한이다. 이전 시연의 $1.50 승인은 새 실험 예산에 포함하지 않는다. 이번 설계의 유료 호출은 0회다. 실제 실행은 선택한 한 가지 설계의 총액이 확정된 후에 시작한다.

- **중단과 누락.** 시작은 빈 장면·모델·계획 해시를 확인하고 회차 기록을 연 시점으로 정한다. 그 이후에는 API 장애·잘못된 응답·검증 실패도 해당 회차에 기록하고 분모에 남긴다. 기술 장애는 별도 사유로 표시하고, 복구 후 다음 예정 회차부터 진행한다. 좋은 결과가 나올 때까지 같은 칸을 다시 실행하지 않는다. 전체 시험이 조기 종료되면 예정·시작·누락 수와 완성된 짝 수를 모두 밝힌다.
- **비교표.** A·B·C마다 성공 수/시작 수와 재시도 총수·회차 평균을 보고한다. B−A와 C−B는 같은 블록의 결과를 빼서 성공률 차이(%p), 한쪽만 완주한 쌍의 수, 회차당 재시도 차이(회)를 표시한다. 함께 비교 가능한 블록 수와 6개 원자료를 공개한다. 성공률과 재시도는 함께 읽는다. 일찍 멈춘 조건에서 재시도가 적었다는 이유로 개선으로 판정하지 않는다.
- **해석 범위.** 한 조건 6회에서는 1회가 약 16.7%p다. 중간에 결과가 유리해도 미리 정한 횟수를 유지한다. 이 시험은 지정 제품과 6개 초기 상태에서의 탐색적 크기 추정이다. 스킬 단독 효과, 메모리와의 상호작용, 신제품 전반의 성공률에는 별도 시험이 필요하다.

**다음 개발 단위**는 기존 개발 장면에서 A/B/C 입력·검색 결과·실행 권한을 대조하는 무과금 검사다. 이후 공통 평가판·제품·시작 상태와 지식 해시를 묶어 봉인하고 유료 비교에 들어간다.
