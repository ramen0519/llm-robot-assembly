# 9단계: IK 결과로 실제 모터를 움직이고 TCP 도착 확인하기

이번 단계는 **열린 그리퍼를 유지하며 TCP를 위로 30mm 이동시키는 물리 시뮬레이션**이다. 8단계에서 계산한 관절 각도를 기존 위치 모터에 전달하고, 실제 관절 움직임·접촉·TCP 위치·방향으로 결과를 판정한다. 새로운 패키지 설치는 필요 없다.

## 앞 단계와 달라진 점

8단계는 “목표 TCP를 만들 관절 각도”를 계산하고 정지 자세를 표시했다. 이번에는 다음 순서로 물리 시간이 진행된다.

```text
현재 자세 → IK로 목표 관절 각도 계산 → 중간 자세 사전 검사
        → 모터 목표를 천천히 변경 → 실제 움직임과 접촉 확인 → 도착 판정
```

MuJoCo에서 세 값의 차이가 중요하다.

| 값 | 의미 | 이번 단계에서의 사용 |
|---|---|---|
| `qpos` | 실제 관절 각도 | 현재 상태를 읽는다. 실행 중 목표 각도를 직접 덮어쓰지 않는다. |
| `qvel` | 실제 관절 속도 | 너무 빠른 움직임과 마지막 안정 상태를 확인한다. |
| `ctrl` | 모터 제어 입력 | 시간에 따라 목표를 바꾸고 중력 보상을 포함한다. |

`mujoco.mj_step()`이 중력, 관성, 모터 힘과 접촉을 계산해 실제 `qpos`와 `qvel`을 갱신한다. 따라서 목표값을 전달했다는 사실만으로 도착했다고 판단하지 않는다.

## 실행 순서와 목표

목표 위치는 월드 좌표계에서 초기 TCP보다 30mm 위다. 방향은 초기 방향을 유지한다.

- 0~1초: 초기 팔 자세 유지.
- 1~5초: 팔 관절 6개의 목표 각도를 부드럽게 변경.
- 5~7초: 최종 목표를 유지하며 안정화.
- 6.5~7초: 이 구간 전체에서 위치·방향·속도가 기준을 만족해야 성공.

관절 목표는 `smoothstep`으로 보간한다. 시작과 끝의 목표 속도가 0이므로 갑자기 최대 속도로 출발하거나 멈추는 명령을 피할 수 있다. 여기서 보간은 두 각도 사이의 중간 목표값을 만드는 뜻이다. **관절 공간에서 보간하므로 TCP 경로가 완벽한 직선이라고 보장하지 않는다.**

팔이 움직이는 동안 그리퍼 모터에는 열린 상태인 0을 전달한다. IK 계산에서는 손가락 관절을 고정했지만, 물리 실행 중에는 손가락도 중력과 연결 기구의 영향을 받으며 움직인다. 패드 간격과 연결 오차를 검사해 열린 상태가 유지되는지 확인한다.

## 중력 보상을 추가한 이유

기존 위치 모터에 IK 각도만 전달해 7초 동안 실행했을 때, 마지막 0.5초의 최대 위치 오차는 **약 10.86mm**, 방향 오차는 **약 2.12도**였다. 로봇은 멈췄지만 목표 위치보다 처져 있었다.

현재 모델의 위치 모터는 목표와 실제 각도의 차이가 생기면 그 차이를 줄이는 힘을 낸다. 팔과 집게의 무게를 받치려면 힘이 필요한데, 단순 위치 제어에서는 작은 각도 차이가 남은 채 평형을 이룰 수 있다.

그래서 현재 자세에서 무게를 지탱할 토크를 미리 계산해 모터 명령에 더했다. **토크**는 관절을 회전시키는 힘이고, **중력 보상**은 무게 때문에 처지는 효과를 상쇄하도록 토크를 보태는 기능이다.

현재 팔의 모터 식을 단순하게 쓰면 다음과 같다.

```text
모터 토크 = Kp × (ctrl - 실제 각도) - Kd × 실제 각속도
ctrl = 보간한 목표 각도 + 중력 보상 토크 / Kp
```

`Kp`는 각도 오차에 얼마나 강하게 반응하는지, `Kd`는 움직임을 얼마나 감쇠하는지 정하는 계수다. 이 식에 맞는 기존 모터 설정과 기어비 1인지 실행 전에 검사한다. `ctrl`에는 보상용 오프셋이 있으므로 CSV의 `reference_rad`와 `ctrl_rad`가 다른 것은 정상이다.

중력 토크는 별도의 계산용 상태에 실제 관절 각도를 복사하고, **계산용 속도만 0**으로 둔 뒤 `qfrc_bias`를 읽어 구한다. `qfrc_bias`는 일반적으로 중력·코리올리·원심력 항을 포함하고, 속도를 0으로 두면 여기서는 중력 항만 남는다. 실제 움직이는 로봇의 속도를 0으로 덮어쓰는 것이 아니다. 근거: [MuJoCo 동역학과 구동기 설명](https://mujoco.readthedocs.io/en/stable/computation/index.html), [위치 모터 설정](https://mujoco.readthedocs.io/en/stable/XMLreference.html#actuator-position).

보상은 기존 구동기를 통해 전달하므로 원래의 모터 힘 제한이 적용된다. 중력을 끄거나 `qfrc_applied`로 별도의 무제한 힘을 더하지 않는다. 원본 모델의 질량·힘 제한·게인은 수정하지 않았다. 이 보상 계산을 실물 UR 제어기에 그대로 보내는 기능은 구현하지 않았다.

## 코드의 역할

실행 파일: `scripts/move_tcp.py`

| 함수/클래스 | 역할 |
|---|---|
| `prepare_motion()` | 기존 IK를 호출하고 명목 이동 경로의 중간 자세를 사전 검사 |
| `reference_at()` | 현재 시간에 맞는 중간 관절 목표 계산 |
| `ArmPositionController` | 모터 구조 확인, 중력 토크 계산, 보상된 `ctrl` 전달 |
| `measure_motion()` | 실제 TCP·관절·그리퍼 상태와 접촉 검사 |
| `run_motion()` | 물리 계산, 기록, 뷰어 갱신, 이상 시 중단 |
| `assess_motion()` | 전체 기록과 마지막 0.5초의 실제 도착·안정 판정 |

기존 `solve_tcp_ik.py`, `view_tcp.py`, `move_gripper.py`의 계산·측정 기능을 재사용한다. 이번 함수 분리는 계산, 제어, 검증을 구분하기 위한 것이며 에이전트·스킬 저장·실물 연결은 아직 추가하지 않았다.

## 충돌과 상태를 확인하는 방법

**이동 전:** 시작 관절 각도와 IK 목표 사이의 중간 자세를 최소 101개 확인한다. 관절 간격은 최대 0.25도로 제한하고, 이번 목표에서는 101개를 검사했다. 별도 계산용 상태만 바꾸므로 이 단계에서 실제 로봇 상태는 움직이지 않는다.

**이동 중:** 초기 상태와 매 0.002초 물리 계산 뒤 실제 상태를 검사한다. 7초 동안 3,501개 상태가 기록된다. 현재 모델의 로봇팔·그리퍼·바닥에 대해 활성화된 접촉을 확인한다. 이번은 물체 없는 이동이므로 손가락 패드끼리의 접촉도 허용하지 않는다.

추가 검사:

- 모든 관절의 최대 속도 15도/초 이하, 팔의 목표 추종 오차 2도 이하.
- 관절 범위 초과 최대 0.001rad. MuJoCo의 부드러운 관절 정지점에 대한 수치 허용치다.
- 그리퍼 양쪽 구동 관절 차이 0.5도 이하, 연결 기구 잔차 0.2mm 이하.
- 두 패드 구간의 열린 간격 각각 80~90mm.
- 유한한 상태값, 엔진 경고 없음, 모터 입력 범위 준수.

충돌·과속 등 검사를 실패하면 더 이상 `mj_step()`을 호출하지 않고 실패로 끝낸다. 자동 재시도는 없다. 이는 **시뮬레이션 중단**이며 실물 로봇의 비상정지 기능은 아니다.

## 직접 실행하기

PowerShell에서 실행한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/move_tcp.py
```

뷰어에서 로봇팔이 위쪽 목표로 천천히 움직인 뒤, 총 7초의 물리 시간이 지나면 창이 닫힌다. IK 계산·창 초기화 시간이 별도로 걸릴 수 있다.

- 분홍색 `Start`: 시작 TCP 위치.
- 작은 청록색 점: 목표 위치. 도착하면 노란 TCP 점과 겹친다.
- 노란 `TCP`와 RGB 축: 실제 움직이는 TCP 위치와 방향.

창 없이 같은 물리 실행과 검사를 수행하려면:

```powershell
uv run --locked python scripts/move_tcp.py --headless
```

마지막에 `TCP physical motion: PASS`가 출력되면 이번 시뮬레이션의 이동·도착 검사를 통과한 것이다. 창을 일찍 닫으면 미완료 실패로 끝낸다.

기록은 Git에 포함하지 않는 `runs/step09/tcp_motion.csv`에 저장한다. 실제 실행이 시작될 때마다 덮어쓰며, 오류로 중단되면 중단 전까지의 정상 측정 기록을 남긴다. 검사 실패 시각과 이유는 터미널에 출력된다. 사전 IK/경로 검사에서 실패하면 새 물리 실행 기록은 만들지 않는다.

CSV에는 실제 TCP 위치·목표 오차·속도·접촉 수, 관절 목표·실제 각도·모터 입력·상태 측정 시점의 모터 토크, 그리퍼 간격·연결 오차가 포함된다. 모터 토크는 단위 기어비의 현재 모델에서 Nm 단위다.

2026-10-28에 창 없는 실행, 뷰어 실행과 정상 종료, 물리 실행 후 화면 렌더링을 확인했다.

| 마지막 0.5초 전체에서 측정한 최댓값 | 결과 | 성공 기준 |
|---|---:|---:|
| TCP 위치 오차 | 0.004908mm | 1mm 이하 |
| TCP 방향 오차 | 0.0000254도 | 0.5도 이하 |
| 전체 관절 속도 | 0.000279도/초 | 0.5도/초 미만 |
| TCP 선속도 | 0.000896mm/초 | 1mm/초 미만 |
| TCP 각속도 | 0.0000241도/초 | 0.5도/초 미만 |

전체 이동 중 팔 관절의 최대 속도는 약 3.193도/초, 손가락까지 포함하면 약 4.756도/초였다. 최대 팔 목표 추종 오차는 약 0.639도, 관절 범위 초과는 약 0.0001585rad, 그리퍼 연결 잔차는 약 0.00752mm였고 검출된 접촉은 0건이었다.

이 값은 동일 모델을 제어와 평가에 사용한 가상환경 결과다. 실물 정밀도나 모델 오차가 있는 환경의 성능으로 해석하지 않는다.

실행한 회귀검사:

```powershell
uv run --locked python -m unittest discover -s tests -v
```

기존 9개와 새 물리 이동 검사 4개, 총 **13개가 통과**했다. 새 검사는 다음을 확인한다.

1. 실제 7초 물리 실행 후 목표 도착, 모터 힘 제한 유지, 미완료 기록 거부.
2. 중력 보상을 끄면 안정적으로 멈췄더라도 처진 자세를 도착으로 인정하지 않음.
3. 목표는 30mm 위인데 명령이 초기 자세에 머물면 성공으로 처리하지 않음.
4. 사전 검사를 통과한 뒤 2초 시점에 테스트용 장애물을 그리퍼 앞에 강제로 배치하면 실제 MuJoCo 접촉 검출로 즉시 중단. 이 장애물 순간 배치는 실패 주입용이며 실제 조립 동작이 아니다. 로봇 좌표나 접촉 결과를 조작하지 않았다.

## 남은 범위

이번 검증은 **초기 자세에서 가까운 목표 하나로 움직이는 현재 장면**에 한정된다. 중간 자세 사전 검사와 2ms 간격의 실제 검사이며, 수학적인 연속 충돌 방지 보장이나 장애물을 우회하는 범용 경로 계획은 아니다. 모델에서 제외된 충돌 쌍이나 실물 형상의 정확성을 검증한 것도 아니다.

부품·파지 물체·조립된 부품은 아직 장면에 없다. 물체를 추가하는 단계에서 충돌 검사와 허용 접촉 조건도 함께 확장해야 한다. 현재 이동 성공을 파지·삽입·실물 성공으로 집계하지 않는다.

다음 작은 단계에서는 물체 하나를 놓고 그 위의 접근 자세를 정해, 같은 이동·검증 기능을 재사용할 수 있다.
