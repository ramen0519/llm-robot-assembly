## 결론

**현재 설정에서는 0.004초를 개발 실행에 사용하는 것이 적절하다.** 0.01초는 잡고 있는 물체를 유지하는 짧은 시험에서는 통과했지만, 새 장면의 첫 계산에서 그리퍼 관절 한도 검사를 통과하지 못했다. 0.004초에서는 작은 개발용 조립체의 움직이는 부품 2개를 같은 주 장면에서 모두 설치했다. 영상 저장까지 197.843초(약 3분 18초), API 0회, 비용 $0이다.

기준 기본값과 `config/completion.v1.2.json`은 0.002초 그대로다. `--physics-timestep 0.004` 또는 UI 선택으로 개발 실험에 적용한다. 0.01초도 명시적 실험 옵션으로 제공하지만, 이번 결과에서 정상 전체 조립을 확인한 설정은 아니다.

이 변경은 영상 배속이 아니라 **물리 계산과 제어 갱신의 시간 간격 변경**이다. 1초를 계산할 때 0.002초는 500번, 0.004초는 250번, 0.01초는 100번 계산한다. 처리량은 줄지만 접촉·제어 응답도 달라질 수 있다.

## 문제와 수정

1. 완료 검사와 실행기에는 0.002초·501개 관측이 고정되어 있었다. 기준 프로파일은 보존하고 0.004초/0.01초의 별도 개발 프로파일을 만들었다. 해시와 결과의 `validation_regime`을 구분한다.
2. 손가락을 닫는 루프가 2,000회로 고정되어 있었다. 간격만 0.01초로 바꾸면 원래 4초 동작이 20초가 된다. 열기 3초, 닫기 4초, 제한 해제 최대 6초 등 기존 시간을 유지하도록 횟수를 계산하고, 해제 명령 변화도 초당 변화량으로 바꿨다. 0.002초에서는 기존 시간과 명령 변화량이 동일하다.
3. 0.01초의 새 장면 시작 검사가 실패했다. 아래 관절 한도를 완화하거나 실패 검사를 생략하지 않고 실패 기록을 보존했다. 이후 0.004초로 새 장면을 만들어 끝까지 실행했다.
4. 서로 다른 계산 간격의 결과나 경험을 섞지 않도록 프로파일 해시, 결과, 완료 증거, 검색 필터, audit, UI와 보고서에 구분을 연결했다. 0.004초/0.01초는 현재 `development` 전용이며 `collection`/`evaluation`에서는 거부한다.

XYZ 각 축 5mm, 상대 회전 3도, 최종 경질 관통 0.5mm, 이동속도 1mm/s, 회전속도 0.01rad/s, 그리퍼 이격 5mm, 해제 후 정착 1초와 관찰 1초를 그대로 유지했다. 정의된 삽입의 깊이·정렬 검사도 유지했다. 다만 관측 간격이 바뀌므로 초기 경계를 포함해 501/251/101개가 된다. **251개 통과를 기존 501개 기준의 검증 완료로 보고하지 않는다.**
