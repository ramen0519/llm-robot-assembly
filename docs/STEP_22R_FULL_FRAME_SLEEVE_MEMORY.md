# 22R · 슬리브 경험 검색을 포함한 빈 바닥판부터 덮개까지의 조립

**2026-11-11. 빈 바닥판에서 시작해 첫 기둥의 간섭을 복구하고, 한 장면에서 기둥 4개·슬리브 4개·덮개 1개를 설치했다. 슬리브2·4는 검색 후 첫 파지로 원래 장면 설치까지 각각 성공했다.** 두 역할이 실제 Astra high를 호출했고, 최종 상태를 독립적으로 복원해 결합을 다시 측정했다.

## 시험 조건

MuJoCo의 UR3e와 2F-85, 고정 바닥판과 자유 부품 9개를 사용한다. 저장된 ASAP 분해 계획의 역순, 각 부품의 트레이 초기 배치, 등록된 기둥 복구 스킬은 22P와 같다. 조립·복구 에이전트는 같은 Astra high 모델과 한 회차 $1.50의 합산 예산을 공유한다.

첫 기둥의 첫 파지만 중심보다 +1 mm 높은 위치로 주어 간섭을 재현한다. 복구 역할이 현재 관측으로 스킬을 검색·선택하고 원래 장면에서 집기가 검증된 후 조립 역할에 돌려준다. 슬리브2·4는 각각 첫 후보를 제안하기 직전에 22P의 슬리브1 경험을 검색한다. 이 경험은 첫 파지 −5 mm에서 패드가 작업대에 닿았고, +12 mm에서 사전검사와 원래 장면 설치가 검증됐다는 기록이다. 슬리브2·4의 과거 파지나 정답은 카드에 담기지 않는다.

이번 실행 폴더는 `runs/step23_frame/20261111T134520_867280Z_047a16bf`다. 빈 장면에서 외부 계획을 처음부터 따랐으며, 22Q의 부품별 체크포인트는 사용하지 않았다. 각 검색·파지·삽입 결정의 실제 응답은 `llm_events.jsonl`, 검색 결과는 `memory_search/sleeve_2/retrieval.json`과 `memory_search/sleeve_4/retrieval.json`에 있다.

### 어떻게 판정하는가

- 에피소드가 빈 바닥판에서 시작하고, 9개 설치를 완료하며, 부품 사이 8번의 경계에서 전체 물리 상태와 설치 목록이 이어져야 한다.
- 첫 기둥은 개발용 후보의 실제 접촉 거절, 복구 역할의 새 검색과 스킬 선택, 검증된 파지로 집기, 조립 역할로의 인계와 삽입 기록을 대조한다.
- 대상 슬리브별로 새 관측에서 검색어를 생성했는지, 슬리브1 카드가 다음 모델 요청에 포함됐는지, **첫 후보**가 거절 없이 통과했는지 확인한다. 통과한 수치와 원래 장면의 실제 파지 수치가 일치해야 한다. 집어 들기, 삽입, 해제, 지지와 기둥 관통을 각 부품에 대해 확인한다.
- 덮개 설치 후에는 저장된 마지막 상태를 복원해 네 구멍의 관통과 네 슬리브 각각의 지지력을 다시 측정한다.

## 실측 결과

1. 첫 기둥에서 그리퍼 패드–소켓 벽 간섭으로 +1 mm 후보가 거절됐다. 복구 에이전트가 검색·열람·선택한 저장 스킬은 현재 관측으로 +4.37 mm를 계산했다. 원래 장면에서 양쪽 패드 접촉을 유지하며 기둥 바닥이 작업대에서 99.474 mm 떨어진 31.518초에 조립 에이전트에 제어권을 돌려줬다. 조립 에이전트가 기둥 삽입과 해제를 완료했다.
2. 슬리브2와 4는 서로 다른 최초 관측에서 각각 검색어를 작성했다. 두 검색 모두 22P 슬리브1 경험을 반환했다. 실제 파지 응답은 이전 −5 mm의 작업대 접촉과 +12 mm의 검증 성공을 인용하고, 현재 부품의 중심 XY와 외벽을 잡는 방향을 선택했다. 두 부품 모두 첫 파지 거절 0회, 재파지 0회, 복구 인계 0회였다.
3. 총 521,177개 물리 기록에서 원래 장면의 집기·삽입·해제와 부품 전환 8회의 연속성을 확인했다. 외부 순서대로 기둥1 → 슬리브1 → 기둥2 → 슬리브2 → 기둥3 → 기둥4 → 슬리브4 → 슬리브3 → 덮개를 설치했다.
