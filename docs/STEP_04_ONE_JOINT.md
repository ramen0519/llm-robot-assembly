# 4단계: UR3e 관절 하나를 천천히 움직이고 도착 확인하기

이번 목표는 첫 관절 `shoulder_pan_joint`의 목표 각도만 바꿔, 약 -90도에서 -60도로 움직인 뒤 실제 도착 여부를 확인하는 것이다. 밑부분의 수직 축을 중심으로 팔 전체가 좌우로 돌아간다. 그리퍼, IK, 물체 집기는 이번 구현에 포함하지 않는다.

## 실행하기

PowerShell에서 다음 명령을 실행한다.

```powershell
cd C:\dev\llm-robot-assembly
uv run --locked python scripts/move_one_joint.py
```

창이 열리면 초기 자세에서 1초간 기다리고, 4초 동안 목표 각도를 부드럽게 바꾸고, 2초 동안 마지막 목표를 유지한다. 총 7초의 시뮬레이션을 한 번 실행한 뒤 창을 닫고 결과를 출력한다. 실제 벽시계 시간에는 모델 로딩 시간이 추가되고, 컴퓨터가 느리면 더 오래 걸릴 수 있다. 완료 전에 창을 닫으면 실패로 종료한다.

창 없이 같은 물리 계산과 도착 판정을 빠르게 실행하려면:

```powershell
uv run --locked python scripts/move_one_joint.py --headless
```

정상 완료 시 마지막에 `One-joint motion: PASS`가 출력된다. 실패하면 프로그램 종료 코드가 1이 된다. 실행 후 `runs/step04/one_joint.csv`에 이번 실행의 3,500개 측정 행을 저장한다. 같은 명령을 다시 실행하면 이 CSV는 새 결과로 덮어쓴다. 도중에 중단되면 새 CSV를 저장하지 않으므로 이전 실행 파일을 이번 결과로 혼동하지 않는다.

## 파일과 실행 흐름

- `scripts/move_one_joint.py`: 목표값 생성, 물리 실행, 상태 검사, CSV 저장과 도착 판정.
- `scripts/view_ur3e.py`: 기존 `load_robot()`과 `set_camera()`를 재사용한다. 이 파일의 정지 뷰어는 그대로다.
- `scenes/ur3e_preview.xml`: 기존 바닥과 UR3e 장면을 그대로 사용한다.
- `models/universal_robots_ur3e/ur3e.xml`: 원본 관절·구동기 설정을 그대로 사용한다.

전체 흐름은 `모델 로딩 → 초기 자세 설정 → 목표값 변경과 물리 계산 반복 → 실제 상태로 도착 판정`이다. 패키지를 새로 설치하지 않았고 기존 MuJoCo 환경에서 실행한다.

## 목표값과 실제값을 구분하기

| 값 | 의미 | 이번 예제의 단위 |
|---|---|---|
| `data.ctrl[actuator_id]` | 모터에 보내는 목표 관절 각도 | rad |
| `data.qpos[qadr]` | 물리 계산 결과인 실제 관절 각도 | rad |
| `data.qvel[vadr]` | 물리 계산 결과인 실제 관절 회전 속도 | rad/s |

`actuator`는 모터 같은 구동 장치를 시뮬레이터에 표현한 것이다. 이 모델은 목표 각도와 실제 각도의 차이에 따라 토크, 즉 회전시키는 힘을 만든다. MuJoCo가 그 힘, 관성, 중력 등을 계산해 다음 순간의 실제 각도를 구한다.

이 모델의 구동기는 단순화하면 `토크 = Kp × (목표 각도 - 실제 각도) - Kd × 실제 회전 속도`인 PD 위치 제어 형태다. P항은 목표 쪽으로 당기고 D항은 과도한 회전을 줄인다. 계산된 힘에는 모델의 한계도 적용된다. 이번에는 기존 이득값을 수정하지 않았다.

모든 MuJoCo 모델에서 `ctrl`이 각도인 것은 아니다. 구동기 종류와 설정에 따라 힘·속도 등일 수 있다. 이번 UR3e의 `general` 구동기는 고정 gain과 affine bias로 위치 제어를 구성하고 있다. [MuJoCo 공식 구동기 문서](https://mujoco.readthedocs.io/en/stable/XMLreference.html#actuator-general)와 [position servo 문서](https://mujoco.readthedocs.io/en/stable/XMLreference.html#actuator-position)를 참고한다.

화면과 로그는 이해하기 쉽게 도(deg)로 표시한다. 계산에서는 `math.radians(-60)`으로 라디안(rad)으로 바꿔 입력하고, 결과를 `math.degrees(...)`로 다시 도 단위로 바꾼다. 180도가 π rad다.

관절 ID, `qpos`의 주소, `qvel`의 주소, 구동기 ID는 일반적으로 같은 숫자라고 가정하면 안 된다. 코드가 관절 이름과 `jnt_qposadr`, `jnt_dofadr`를 사용해 각각 찾는 이유다.

## 왜 4초에 걸쳐 목표를 바꿀까?

처음부터 -60도만 보내면 모터는 곧바로 약 30도의 큰 오차를 줄이려 한다. 이번에는 `commanded_angle()`이 목표값 자체를 조금씩 바꿔 부드럽게 출발하고 멈추게 한다.

이동 진행률을 0~1 사이의 `s`라고 하면 `3s² - 2s³`이라는 곡선을 사용한다. 시작과 끝에서 목표 각도가 변하는 속도가 0이 되는 smoothstep 곡선이다. 실제 관절은 이 목표 곡선을 모터 힘으로 따라가므로 이동 중에는 약간 뒤처질 수 있다.

| 시뮬레이션 시간 | 목표값 |
|---|---|
| 0~1초 | 초기 약 -90도 유지 |
| 1~5초 | 약 -90도 → -60도로 부드럽게 변경 |
| 5~7초 | -60도를 유지하며 안정화 |

첫 관절의 목표값만 바꾸고 나머지 5개 구동기에는 초기 자세의 목표값이 유지된다. 다른 관절을 완전히 고정하는 것은 아니다. 이 관절들도 중력을 받으면서 위치 제어로 자세를 유지하므로 작은 오차가 생긴다.

## 물리 계산의 핵심

`run_motion()`의 반복문 안에서 하는 일은 다음과 같다.

```python
data.ctrl[actuator_id] = commanded_angle(float(data.time), start_rad, target_rad)
mujoco.mj_step(model, data)
mujoco.mj_forward(model, data)
check_state(model, data)
```

1. 현재 시간에 맞는 목표 각도를 모터에 보낸다.
2. `mj_step()`으로 0.002초, 즉 2밀리초만큼 물리 시간을 진행한다.
3. `mj_forward()`로 새 관절 위치에 맞춰 형상·접촉 정보를 갱신한다. 이 함수 자체는 시간을 추가로 진행하지 않는다.
4. 실제 상태가 유한한 값인지, 관절 범위를 벗어났는지, 예상치 못한 접촉이나 엔진 경고가 있는지 확인한다.

실제 관절 각도인 `qpos`를 매번 원하는 값으로 덮어쓰지 않는다. 저장된 초기 자세를 설정한 이후의 위치 변화는 구동기와 물리 계산으로 만들어진다. 뷰어의 대기 시간은 화면 재생 속도를 맞추기 위한 것이며, `--headless`에서도 물리 시간 간격과 계산 횟수는 같다.

이번 장면에서는 로봇이 움직이는 동안 다른 물체에 닿을 이유가 없으므로 접촉이 생기면 중단한다. 이 규칙은 이 빈 장면에만 적용한다. 나중의 집기·삽입에서는 필요한 접촉과 금지된 충돌을 따로 구분해야 한다. 현재 모델의 충돌 형상으로 각 물리 스텝을 검사한 것이며, 연속 충돌 검사나 범용 경로 계획기를 구현한 것은 아니다.

## 도착했다고 판단하는 기준

`assess_motion()`은 명령한 `ctrl`이 아니라 실제 `qpos`와 `qvel`에서 기록한 값을 검사한다.

- 총 7초의 시뮬레이션이 끝났을 것.
- 마지막 0.5초의 모든 측정에서 목표와 실제 각도의 오차가 0.5도 이하일 것.
- 같은 구간에서 회전 속도의 절댓값이 0.5도/초 미만일 것.
- 이동 전체의 최대 실제 속도가 15도/초 이하일 것.
- 나머지 관절의 초기 각도 대비 변화가 전체 구간에서 2도 이하일 것.

각도만 확인하면 목표를 빠르게 지나치는 순간도 성공으로 오해할 수 있다. 속도와 일정 시간 동안의 유지 여부를 함께 확인하면 목표 근처에서 안정됐는지 구분할 수 있다. 위 허용값은 이 입문 실험의 기준이며 실제 로봇의 정밀도 규격이나 조립 허용 오차가 아니다.

## 이번에 확인한 결과

2026-10-26, Python 3.11.15 / MuJoCo 3.17.0, 기존 커뮤니티 UR3e 모델과 중력 -9.81m/s²에서 확인했다.

| 측정 | 결과 |
|---|---:|
| 목표 각도 | -60도 |
| 최종 실제 각도 | -60.000016도 |
| 마지막 0.5초의 최대 각도 오차 | 0.000198도 |
| 마지막 0.5초의 최대 속도 | 0.001012도/초 |
| 이동 전체의 최대 속도 | 11.140780도/초 |
| 나머지 관절의 최대 각도 변화 | 0.725444도 |
| 충돌·관절 한계 초과·엔진 경고 | 없음 |

창 없는 실행과 뷰어 실행 모두 동일한 결과로 통과했고, 뷰어는 한 번의 실험 후 정상 종료했다. 이동 전후 상태를 실제 MuJoCo 렌더러로 확인했다.

성공 판정이 실제 도착을 구분하는지도 별도 대조 실험으로 확인했다. 첫 관절 모터의 출력 힘을 0으로 제한했을 때는 명령이 -60도여도 실제 각도는 약 -89.893도에 남아 도착 판정이 실패했다. 바닥을 로봇 링크와 겹치게 올린 별도 실험에서는 접촉 검사로 중단했다. 이 대조 실험은 임시 검증 스크립트에서 모델을 바꾼 것이며 저장된 원본 모델과 기본 실행 설정에는 반영하지 않았다.

## 지금 이해하면 되는 범위

이번 단계에서 확보한 것은 `목표 관절 각도 → 구동기 → 물리적 이동 → 실제 상태 기반 도착 확인`이라는 가장 작은 제어 흐름이다.

IK(역기구학)는 손끝을 특정 좌표로 보내기 위해 각 관절의 각도를 계산하는 과정이다. 지금은 움직일 관절과 목표 각도를 직접 지정했으므로 IK를 풀 필요가 없다. 장애물을 피하는 경로 선택, 여러 관절의 협조 이동, 그리퍼 조작은 다음 구현 단위다.

매우 작은 도착 오차는 이 이상적인 시뮬레이션의 무부하·한 자세 전환에서 얻은 수치다. 실제 로봇의 정확도, 모든 자세에서의 안정성, 그리퍼 부착 후 동작, 조립 성능을 입증하지 않는다. 원본 모델의 충돌 형상과 구동기 설정은 필요한 동작 범위가 늘어날 때 계속 검증한다.
